## 1. Mordant Coherence: relocate by bit pattern, prove it agrees with the sort-based relocation

**Words that drove it:**
- *mordancy*: a mordant decides which fibres take the dye, as the header tag and the tag bit decide which words the GC rewrites.
- *translatory*: relocation is a rigid translation of each block.
- *unantiquated*: the young generation.
- *edeoscopy*: classifying by inspecting the surface, that is, by bit pattern.
- *picrotoxin*: removing an inhibition, here re-running the law check without the inhibition on raw words.

**Target.** It objects to every round-1 C3 candidate:
- R1-1 #2 Relocation Equivariance
- R1-2 #2 layout DSL and R1-2 #5 render naturality
- R1-3 #2 equivariant predicates
- R1-4 #2 placement parametricity
- R1-5 #2 Pseudomorph and R1-5 #5 Placement Quotient
- R1-6 #2 Aureola and R1-6 #5 Keratectomy

All of them prove invariance under `ρ♯`, an action that rewrites a word when its VM sort is `ptr`. R1-2 flagged the risk. The facts learnt during round 1 confirm it: the machine GC rewrites a word when its bit pattern is even and inside the young range, and `Val.raw` holds words the VM never treats as pointers. So every round-1 fundamental lemma is about an action the collector does not perform. None of them is wrong, but all of them are disconnected from the GC.

L3's check on 20,000 heaps most likely used the sort-based action, because it says "rewriting pointer words through the relocation". So the check may never have tested what the collector does.

**The idea.** Keep whichever round-1 equivariance machinery wins; it proves invariance under the sort action `relocSort`. Add one bridge layer:
- Define the collector's actual action `relocPat ρ m`. On the scanned set (roots, the stack, and fields of blocks with a scan tag), it rewrites a word iff `isYoungPat w`, meaning even and inside `[youngStart, youngEnd)`. It copies everything else, and copies no-scan blocks verbatim.
- Prove once that the two actions agree on every memory satisfying a named-field coherence structure.

C3 then splits three ways:
- equivariance (round 1, sort action);
- coherence ⇒ agreement (this idea, once);
- coherence is maintained by the mutator between collections (Layer A, per arm that writes a word).

**Core rules.**
- **MC1, the coherence structure** (named fields, per CLAUDE.md law 6):
  ```lean
  structure ScanCoherent (L : Layout) (π : Placement) (s : St) (m : Mem) : Prop where
    young_inside : ∀ ℓ, s.young ℓ → blockRange (π ℓ) (size ℓ) ⊆ L.young
    old_outside  : ∀ ℓ, ¬ s.young ℓ → Disjoint (blockRange (π ℓ) (size ℓ)) L.young
    code_outside : ∀ pc, L.codeAddr pc ∉ L.young
    atom_outside : ∀ t,  L.atomAddr t ∉ L.young   -- atoms are static in 4.14 [check]
    raw_safe     : ∀ a ∈ scanned π s, ∀ w, slotVal π s a = .raw w → ¬ isYoungPat L w
    noscan_tag   : ∀ ℓ, s.kind ℓ ∈ NoScan → ∀ a ∈ fieldsRange (π ℓ), a ∉ scanned π s
  ```
- **MC2 (L3, restated as a proved rule about the real collector):** `ScanCoherent L π s m → Admissible ρ π → relocPat L ρ m = relocSort ρ π s m`. The proof is pointwise on addresses and uses one per-value lemma, MC3. L3 then holds for `relocPat` by composing MC2 with round 1's fundamental lemma.
- **MC3 (the value-word lemma, the only arithmetic):** `ScanCoherent … → (isYoungPat L (enc π v) ↔ v.isYoungPtr π s)`, by `cases v`:
  - `int`: `2n+1` is odd.
  - `ptr ℓ k`: `young_inside` or `old_outside`, with `k` inside the block (infix pointers included).
  - `code` and `atom`: `code_outside`, `atom_outside`.
  - `raw`: the `raw_safe` premise.
- **MC4 (post-collection reset):** after a minor collection the young generation is empty, so `young_inside` and `raw_safe` hold vacuously for the new `ρ ∘ π`. Coherence therefore needs maintenance only across allocation and writes between collections. That maintenance is a Layer A obligation, attached to the arms that write words (stack pushes, `SETFIELD`, allocation).
- **MC5 (necessity, a documentation lemma):** a two-word memory with a `raw` stack slot whose value is even and lies in the young range, on which `relocPat ≠ relocSort`. It is proved by `decide` on concrete `UInt64`s, so the premise cannot be "simplified away".

**What it makes free, and what it costs.**
- *Free:* every round-1 C3 candidate becomes a statement about the actual collector. The GC-facing proof obligation (R1-5 #2's "R-GC-is-ρ", R1-2 #5's "R-GC-spec") is restated against `relocPat`, which is what the collector's code actually computes. That makes the GC refinement proof shorter.
- *Cost:* the `raw_safe` premise is a real modelling question. Which raw words can sit in scanned positions? In OCaml 4.14 bytecode, candidates include:
  - return addresses (code pointers, outside the heap);
  - trap links and extra-args counts (`Val_long` in 4.14? [check]);
  - raw addresses into the stack region.
  All lie outside the minor heap by ELF layout, which `OCaml/Vm/Layout.lean` supplies. If one of them could be even and in range, MC5 is a live bug report, not a proof gap.
- *Cost:* Layer A picks up one side condition, "the word written is `enc π v` for the stored `v`", at each word-writing arm.

**Law check to rerun** (tools only check laws):
- Rerun L3's counterexample search with `relocPat`, placing adversarial raw words (even, in the young range) in scanned slots.
- Expected result: counterexamples with `raw_safe` dropped, and none with it kept. This confirms the premise is necessary, in the same way the 12,358 overlap counterexamples did for disjointness.

**Distant theories:**
- Type-erasure correctness in compilers (typed and untyped semantics agree on erased programs, as in the correctness of Coq extraction [check]).
- Precise versus conservative GC (Boehm–Weiser 1988 [check]): `relocPat` is what a precise collector does given a word-level typing invariant.
- Information-flow taint tracking (pointer-ness as a label that must agree with an observable property of the bits).
- Textile chemistry: a mordant's selectivity.

**Clusters:** C3. It also creates a small Layer A maintenance obligation, the entry point to C4 at machine level.

**Pilot.**
- **H5:**
  ```lean
  theorem valWord_reloc_pat (hc : ScanCoherent L π s m) (hρ : Admissible ρ π) (v : Val) :
      relocWordPat L ρ (enc π v) = enc (ρ ∘ π) v
  ```
  Proof: MC3 by `cases v`, then round 1's atom lemma. About 12 lines; the `raw` case is one premise application.
- **H6:**
  - Scan-tag kinds: fields map by H5, and the header is odd-free? No: the header is not in the scanned set, so it is copied.
  - No-scan kinds (strings, doubles, channels): both actions copy verbatim, via `noscan_tag`.
  - About 6 lines on top of the chosen round-1 H6.
- **H7:** the stack lies outside `L.young` by Layout, so each slot goes through H5. About 4 lines.
- **H1–H4, H8, H9:** not applicable.
- **The three refactors:** not applicable. This is stated honestly, since all three are C1.

## 2. Junction Semantics: define the step once as an effect program, so L4 is one generic theorem with no per-opcode arms

**Words that drove it:**
- *neuromuscular*: only what crosses the junction (the transmitter) affects the muscle.
- *multivalve*: state reaches an instruction only through a fixed set of valves (effect operations).
- *aminolysis*: cleaving the step into a program and an interpreter.
- *commonsensibly*.

**Target.** It objects to the whole round-1 footprint family:
- R1-1 #3 Footprint Lenses: "one lemma per opcode (about 150)".
- R1-2 #3: "one locality theorem … a single `cases` on the instruction".
- R1-3 #3 Step patches: "one large opcode-by-opcode proof of P2".
- R1-4 #3: "should fall to `cases op <;> rfl` if `patchOf` mirrors `step` closely [risk]".
- R1-5 #3 Stencil: "R-Stencil sweep over the whole ISA".
- R1-1 #5 Natural Symbolic Stepping: "proved once by structural induction … reusing the step function's own code".

Two concrete obstacles:
- **Lean 4 has no internal parametricity.** Writing `step` generically over a `ValueDomain` class does not yield naturality for free (R1-1 #5, R1-6 #3). The free theorem is a meta-theorem that must still be proved opcode by opcode.
- **The 150-arm sweep is exactly the per-arm, mechanical work that CLAUDE.md law 3 calls an abstraction smell.** It is also brittle: every new opcode or primitive added under "Growing `BcSem`" re-opens it.

**The idea.** Make locality true by construction.
- Present each instruction's step as a term of a small free monad over state operations: the valves.
- `BcSem.step p s := interp (instr p s.pc) s`.
- L4 becomes a theorem about `interp`, proved by one induction on the free-monad term. That single induction is independent of how many opcodes exist.
- The footprint is not declared. It is the log of operations the interpreter actually performs. This is the optimistic-concurrency view: a transaction's result is valid on any state that agrees on its read set.

```lean
inductive Op where
  | peek (k : Nat) | pop | push (v : Val) | getReg (r : Reg) | setReg (r : Reg) (v : Val)
  | getField (ℓ : Loc) (i : Nat) | setField (ℓ : Loc) (i : Nat) (v : Val)
  | alloc (o : Obj) | heapLen | world (q : WorldQ)
inductive Eff (α : Type) where
  | ret  : α → Eff α
  | op   : (o : Op) → (Resp o → Eff α) → Eff α   -- Resp o : Type is the operation's answer type
  | fail : Fault → Eff α                          -- Unsupported / Wrong
def interp : Eff α → St → Except Fault (α × St × List Event)   -- Event = (op, response)
```

**Core rules** (each proved once, by induction on `Eff`):
- **J1 (L4 as a theorem, read-set validation):**
  ```lean
  theorem interp_agree : interp t s = .ok (a, s₁, log) → AgreeOn (reads log) s s' →
      interp t s' = .ok (a, replay log s', log)
  ```
- **J2 (frame, writes only):** `interp t s = .ok (a, s₁, log) → ∀ c ∉ writes log, c.get s₁ = c.get s`. Here `c` ranges over cells: registers, relative stack slots below the pops, fields, `heapLen`, and `world`.
- **J3 (monad law for logs):** `interp (t >>= k)` concatenates logs. Composing several instructions is ordinary monadic bind, with no patch-normalizer to verify (contrast R1-3 #3's P3 `⊙`).
- **J4 (relative stack cells):** `peek k`, `pop` and `push` address slots relative to the top. The "external reads" of a log exclude cells it wrote first, so a `push` followed by `pop` reads nothing external.
- **J5 (append allocation):** `alloc` writes cell `field (heapLen) _` and bumps `heapLen`. Fields of existing locations are outside `writes`, so old objects are framed by J2 (this is R1-1 #3's F4, obtained for free).

**What it makes free, and what it costs.**
- *Free:* L4 for every opcode, including future ones. An opcode added by transcribing an `interp.c` arm into `Eff` style gets locality with zero proof.
- *Free:* the footprint is computed, not declared, so data-dependent footprints (the "dynamic footprint" and "two-phase stencil" risk in R1-2 #3 and R1-5 #3) are handled without special casing, because the log records whatever was read.
- *Free:* C2 gains too. `bcHalts_of_runTo`'s runner can return logs, and a log is a certificate: the manifest of R1-5 #4, now with read sets.
- *Cost:* `BcSem.step` is re-presented. The cheapest path is to redefine `stepI` in `Eff` style, re-run the `runbc` difftest against host `ocamlrun`, and keep `Fragment.lean`'s ledger unchanged. This avoids any per-opcode equality proof: the difftest checks behaviour and J1 is generic.
- *Cost:* kernel reduction goes through `interp`, which adds overhead to `decide +kernel` validation runs. Measure it on the existing `Validation.lean` chunks before adopting.
- *Honest limit:* for straight-line code whose reads are all to cells it wrote earlier (H8), plain reduction of the current `BcSem.step` on a symbolic state may already work, as R1-6 #3 bets. J1 only earns its keep when an instruction reads opaque data. The cases are an unknown heap cell, an abstract stack top that is pattern-matched, or a guard on the whole stack, such as a stack-overflow length check on `PUSH` [check whether `BcSem` has one; if it does, reduction on an abstract stack gets stuck, and J1 is the only route].

**Distant theories:**
- Algebraic effects and handlers (Plotkin–Power 2002; Plotkin–Pretnar 2009 [check]): the instruction is a computation, and the state is a handler.
- Optimistic concurrency control (Kung–Robinson 1981 [check]) and STM read-set validation: J1 is the OCC validation rule.
- Bernstein's conditions for parallel execution (read and write sets, [check]).
- Physiology: synaptic transmission, where only transmitter crossing the cleft matters.

**Clusters:** C4 (straight-line code and framing), C2 (logs as certificates).

**Pilot.**
- **H8:**
  ```lean
  theorem h8 (s : St) (hpc : s.pc = 0) (hP : prog = h8Prog) :
      run 4 s = .more { s with pc := 4, accu := .int 42 }
  ```
  - `instr` for the four pcs is concrete, so the composite `Eff` term reduces by `simp [instr, bind]`.
  - Its external read set is `∅`: `CONSTINT` and `CONST2` write the accumulator, `PUSH` writes slot 0, and `ADDINT` pops the slot `PUSH` wrote and reads the accumulator `CONST2` wrote.
  - J1 applied with `s'` arbitrary against a reference state gives the equation; J2 gives stack equality.
  - About 6 lines, with no case split on `s.stack`.
- **H9:**
  - The body `Eff` term (compare, branch, `OFFSETINT 1`, store, branch back) has external read set `{slot 0}`.
  - Evaluate it once with `slot 0 = int i` symbolic. The arithmetic side goals use `omega` after `BitVec.toNat` normalisation; `bv_decide` is forbidden, and `bv_omega`-style simp plus `omega` is fine.
  - J1 then transports that one evaluation to every state. Iterate with R1-2 #4's Circ-rank or R1-6 #4's ledger.
  - About 15 lines plus the chosen loop rule.
- **H1–H7:** not applicable.
- **Refactor, VM run determinism:** unchanged, since `interp` is a function.
- **Other two refactors:** not applicable.

## 3. Screenplay Grammar: parse the compiler's output against its own emission schemes, with one spec rule per scheme

**Words that drove it:**
- *photoplaywright*: the compiler writes a script from a small set of scene templates.
- *schemingly*: compilation schemes.
- *declaration* and *obtestation*: the parse tree is a declared, witnessed certificate.
- *quippish*: short fused instructions such as `PUSHACC`.
- *Chimakuan*: a language family, so a grammar.

**Target.** It goes where round 1 did not. It combines:
- R1-2 #4, reachability logic with ranked circularity, as the proof rules;
- R1-4 #4, Poincaré sections, which said "α per function has to come from the source";
- R1-5 #4, Manifest, whose certificate is structured here instead of being a trace.

Round 1 treated the 412,087-instruction compiler as arbitrary bytecode needing a CFG lift (R1-1 #4 GKAT) or cut points (R1-4 #4). It is not arbitrary. It was emitted by `bytegen.ml`/`emitcode.ml` [check the 4.14 file names] from about 40 schemes. Each scheme keeps one discipline: compiled code leaves the value in `accu`, restores the stack depth `sz`, and falls through to its continuation.

**The idea.**
- Write the emission schemes as a grammar `G` over instruction sequences, with productions for:
  - constants;
  - `Lprim` with n arguments: the arguments are compiled right to left with `PUSH` between them, then the operator;
  - `Lifthenelse`: `BRANCHIFNOT`, the then-branch, `BRANCH`, the else-branch;
  - `Lwhile` and `Lfor`;
  - `Lsequence`, `Llet` (`PUSH` … `POP`), closures, `APPLY`/`APPTERM`, `SWITCH`, and `PUSHTRAP` … `POPTRAP`;
  - the fused forms from the emitter's peephole table (`PUSHACC n`, `PUSHCONSTINT`, …).
- An executable parser `parse : Code → Pc → Option (Tree × Pc)` is the only checker.
- Each production carries one reachability-logic rule over the universal contract below, proved once. Program specs are folds over the parse tree, and parser soundness is one lemma per production (C2).
  ```lean
  structure ExprCode (P : Prog) (pc pc' : Nat) (val : St → Val) : Prop where
    reaches  : ∀ s, s.pc = pc → s.code = P → (pcAt pc) ⇒ (pcAt pc')        -- R1-2 #4's ⇒
    accu_eq  : … post.accu = val s
    stack_eq : … post.stack = s.stack
    env_eq   : … post.env = s.env
    heap_ext : … s.heap <+: post.heap                                   -- append-only
  ```

**Core rules.**
- **S1 (one per production), for example `prim2`:**
  ```lean
  ExprCode P pc₀ pc₁ v₂ → PushAt P pc₁ → ExprCode P (pc₁+1) pc₂ v₁ → OpAt P pc₂ .addint →
    ExprCode P pc₀ (pc₂+1) (fun s => addInt (v₁ s) (v₂ s))
  ```
  Framing for `v₁` is where L4 enters: `v₁` is evaluated one slot deeper, so `ExprCode`'s `stack_eq` gives `v₁` evaluated on a state whose stack is `v₂ :: s.stack`. The discipline requires `v₁` to be insensitive to that, which is exactly the compiler's `sz` invariant made into a contract.
- **S2 (loop productions):** `Lwhile` and `Lfor` rules are R1-2 #4's Circ-rank, instantiated once with the scheme's fixed shape. The user supplies only the invariant and rank over the *source-level* loop variable.
- **S3 (parser soundness, C2):** `parse P pc = some (t, pc') → ExprCode P pc pc' ⟦t⟧`, by induction on the parse, citing S1 or S2 per node.
- **S4 (functional reading):** `⟦t⟧` is a Lambda-level evaluator over the reconstructed tree. So the bytecode of a compiled function denotes a decompiled Lambda term, which is exactly what Layer C (source-level correctness, the bootstrap fixpoint) wants to reason about.
- **Laws:** L1 enters through the `⇒` semantics (R1-2 #4 over any fuel iterate), and L4 enters through `stack_eq` and `env_eq` in every rule.

**What it makes free, and what it costs.**
- *Free:* specs for every well-parsed region of the 412k image cost nothing per site. Straight-line code, branches and loops of compiler shape all reduce to S1, S2 or S3 and a parse.
- *Free:* failure to parse localises exactly where hand reasoning is needed: hand-written runtime stubs and odd peephole outputs.
- *Free:* combined with R1-4 #4, the `α` "from the source" is the parse tree, so it is computed rather than chosen.
- *Cost:* the grammar must cover the emitter's peephole fusion. That is a finite rewrite table [check `emitcode.ml`'s `Kpush`/`Kacc` merging], but every fused opcode doubles a production.
- *Cost:* label resolution; the parser must follow branch offsets.
- *Cost:* `APPLY` needs function-level contracts (the callee's `ExprCode`), so recursion needs ranked circularity at function granularity. This is the real work, and the grammar does not remove it.
- *Risk:* `ExprCode` is a total-correctness contract, but compiler code can raise or diverge. Productions need an "or raised to the current trap" disjunct.

**Distant theories:**
- Attribute grammars (Knuth 1968 [check]): specs are synthesized attributes.
- Decompilation into logic (Myreen, Gordon and Slind, FMCAD 2008 [check]) and structural control-flow recovery (Cifuentes [check]).
- Translation validation (Pnueli, Siegel and Singerman 1998 [check]).
- Film theory's shot, scene and sequence grammar: a screenplay parsed back into its slug-line structure.

**Clusters:** C4 at compiler scale, and C2 (the parser as a checker).

**Pilot.**
- **H8:** `parse h8Prog 0 = some (.prim2 .addint (.const 2) (.const 40), 4)` by `decide`. S3 gives `ExprCode h8Prog 0 4 (fun _ => .int 42)`, whose fields are the H8 statement. Note: under the right-to-left argument order, the program is the source `2 + 40` [check]. About 3 lines once S1 exists.
- **H9, honest limit:**
  - If H9's loop is `Lfor`-shaped, it parses, and S2 closes it with invariant `i ≤ 10` and rank `10 − i`, in about 5 lines. The emitted `for` loop keeps the index on the stack top.
  - A compiled `for` returns unit (`accu = Val_unit`), not 10. So H9's "accumulator 10 at STOP" indicates hand-written bytecode, which fails to parse. It then falls back to plain R1-2 #4.
  - The pilot measures exactly this: the fraction of a real `ocamlc` output that parses.
  - A second, extra pilot (it goes beyond the held-out suite): parse the bytecode of `runbc`'s smallest test programs and report coverage.
- **H1–H7:** not applicable.
- **The three refactors:** not applicable.

## 4. Lagrangian Placement: keep the placement uncollapsed but scoped inside one invariant; the GC is the only thing that sees it

**Words that drove it:**
- *uncollapsed*: do not quotient.
- *varicella*: a latent virus hides in one ganglion and reactivates at intervals, as the placement hides in one invariant and wakes at each collection.
- *translatory*: material versus spatial coordinates.
- *unfurred*: clients see the bare VM heap.

**Target.** It objects to R1-3 #5 (Gauge-fixed simulation) and R1-5 #5 (Placement Quotient), and extends R1-6 #5 (Keratectomy).

Concrete Lean-without-Mathlib obstacles to quotients:
- `Quotient.lift` over memories blocks `decide +kernel`, which the project uses for `BcSem` validation (`bcHalts_of_runTo`) and for layout facts.
- `Quotient.out` is noncomputable, so any C2 checker over `MemMod` is lost; R1-5 #5 admits this.
- R1-3 #5's setoid version forces every downstream lemma to carry `respects ≈`, which is a new per-lemma obligation: the duplication CLAUDE.md law 3 warns against.
- The quotient buys less than it seems. The 15-field loop-head relation already quantifies the placement existentially, so the only issue is where the `∃` is opened.

**The idea.** Use the continuum-mechanics split between Lagrangian (material) and Eulerian (spatial) coordinates.
- Clients (C4 specs, Layer B′, arm simulations that do not allocate or collect) state everything in material coordinates: VM locations and VM objects, held as resources or named facts `ℓ ↦ᵥ obj`.
- The spatial placement `π` appears in exactly one place, a named invariant:
  ```lean
  structure HeapInv (L : Layout) (h : VmHeap) (m : Mem) : Prop where
    π        : Placement                -- existential kept, but only here
    disj     : Disjoint₂ L π h
    coherent : ScanCoherent L π h m     -- idea 1
    blocks   : ∀ ℓ o, h.get? ℓ = some o → BlockAt L m (π ℓ) (encObj π o)
  ```
- The GC's machine-level spec is `HeapInv L h m → run gc m = m' → HeapInv L h m'`, proved once. Inside it, L3 is used once, to rebuild `blocks` at `ρ ∘ π`.
- Every other spec frames `HeapInv` through the GC without mentioning it. With `∀ (Wp : MachWP M)`, the GC is a `wp_localRunW` whose pre- and postcondition is `HeapInv`.
- If iris-lean's resource algebra library has an authoritative map [check], `h` becomes `●h` and clients own `◯{ℓ ↦ o}` fragments: the standard "logical heap over physical heap" Iris pattern. If it does not, `HeapInv` stays a named-field `Prop` threaded through `MachWP` posts, which is lighter and loses nothing for a single-threaded VM.

**Core rules.**
- **LP1, GC transparency:** `{HeapInv L h} gc {HeapInv L h}`. This is L3 as a proved rule, used once: `blocks` is rebuilt from round 1's fundamental lemma composed with idea 1's MC2. `π` is re-chosen as `ρ ∘ π`, and no user-visible term changes.
- **LP2, allocation:** `{HeapInv L h ∗ free young room n} alloc o {ℓ. HeapInv L (h.push o) ∧ ℓ = h.length}`. It extends `π` at the new location, and `disj` uses the bump-pointer fact.
- **LP3, material framing:** any assertion not mentioning `π` commutes with LP1 and LP2. This holds by construction, because `π` is not in scope outside `HeapInv`.
- **LP4, flow composition:** `HeapInv` after `k` collections carries `ρ_k ∘ … ∘ ρ_1 ∘ π`, but nobody ever writes this composite. The Lagrangian label `ℓ` is the only name used. Compaction in the major collector, if enabled [check 4.14], is another LP1 instance with `ρ` on all blocks.

**What it makes free, and what it costs.**
- *Free:* no C4, Layer B′ or Layer A arm proof ever mentions the collector or the placement. The stuttering of R1-3 #5 is absorbed by WP, which counts machine steps, not VM steps, so no stutter-bisimulation theory is needed.
- *Free:* no quotient, so every concrete check stays `decide`-able.
- *Cost:* the existing 15-field loop-head relation must be split into material fields (the VM state as resources or facts) and the one spatial `HeapInv`. This is a real restructuring of the relation.
- *Cost:* if `MachWP` has no invariant mechanism, `HeapInv` has to be threaded explicitly through every `wp_callW` post [check].
- *Honest:* this does not prove L3. It limits the use of L3 to one site. H5–H7 are exactly the three sub-lemmas LP1 needs.

**Distant theories:**
- Continuum mechanics: Lagrangian and Eulerian descriptions, the flow map, and material frame-indifference (Noll's objectivity principle [check]).
- Database indirection: the Bw-tree mapping table, logical page id to physical address, updated atomically on relocation (Levandoski, Lomet and Sengupta, ICDE 2013 [check]).
- Iris's authoritative/fragment ghost state over a physical heap (Jung et al., JFP 2018 [check]).
- Epidemiology of latent infection (the placement lies dormant and reactivates at collection).

**Clusters:** C3 (the use side), and C4 or Layer A (keeping specs placement-free).

**Pilot.**
- **H5–H7:** stated as the three lemmas LP1 consumes, `blocks`-field rebuild for a value word, an object and the stack region. They are proved by the winning round-1 C3 candidate plus idea 1. LP1 itself is about 25 lines of assembly around them.

## 5. Narcoleptic Clocks: lax, time-changed morphisms of deterministic systems (fixing round 1's lockstep transport and H3)

**Words that drove it:**
- *narcoleptic*: the image system "sleeps" through many steps per source step.
- *preordination*: determinism, so each outcome is fixed in advance.
- *quartetto*: four outcomes, namely Halt, Unsupported, Wrong and divergence.
- *energeticalness*: the clock must be positive, spending at least one unit per step.
- *undecoic*: eleven, the number of H9 starts; a reminder that finite enumeration is not a proof method at 412k.

**Target.** It objects to round 1's C1 transport rules and extends the C1 kernel:
- R1-1 #1 `iterate_map`
- R1-4 #1 R6
- R1-5 #1 R-Transport
- R1-6 #1 R-transport ("`e := id` … `funext; rfl`")

Four objections:

**(a) No Mathlib.** R1-2 #1 and R1-4 #1 build on Mathlib's `Computation`, R1-4 #5 on `KleeneAlgebra` and `OrderHom.gfp`, and several rely on `Relation.ReflTransGen`. None is available.
- The minimal kernel is about 80 lines over `Nat`-fuel `run` with an absorbing `done`.
- It is structurally recursive, so kernel-reducible, and the existing `runTo` should *be* this `run`. That turns the C2 member `bcHalts_of_runTo` into a C1 corollary.

**(b) The squares are strict lockstep squares** (`step ∘ e = map e ∘ step`). That covers only the trivial VM ↔ `BcModel` wrapper. The project's central simulation (Layer A: one VM step equals many machine steps) and any machine ↔ OS-spec seam are one-to-many, and nothing in round 1 transports along them.

**(c) The outcome types differ, so `e := id` is not `rfl`.** `BcModel`'s `StepResult` is `next | halt code out | stuck`, while `BcSem` has `Halt code world | Unsupported | Wrong`. The outcome map `g` collapses `Unsupported` and `Wrong` into `stuck` and projects `world` to `out`. `g` is not injective, so only some facts reflect back.

**(d) H3 is false as literally stated.** Take a program whose first instruction hits an unsupported primitive. It never goes wrong, never halts, and does not diverge. The hypothesis must be "never Wrong and never Unsupported"; equivalently, never `stuck` after `g`. R1-2 and R1-3 noticed this; the others' H3 pilots silently assume it.

**The idea.** Put one structure between any two deterministic systems, a time-changed, lax morphism, and derive both forward and backward transport from it using determinism.

```lean
structure TimeChange (A : DetSys σ O) (B : DetSys τ P) where
  e        : σ → τ
  g        : O → P                   -- lax: may collapse outcomes
  clock    : σ → Nat
  clock_pos : ∀ s, 0 < clock s       -- no Zeno: each source step costs ≥ 1 target step
  more_sq  : ∀ s s', A.step s = .more s' → B.run (clock s) (e s) = .more (e s')
  done_sq  : ∀ s o,  A.step s = .done o  → ∃ k, B.run k (e s) = .done (g o)
```

**Core rules** (all generic, proved once):
- **K0 (L1 as the definition):** `A.rel n s t :≡ A.run n s = .more t`, plus `run_add` (the action law), `run_done_mono` (absorption) and `done_unique`. This is round 1's C1 kernel restated without Mathlib. Rebuild `Star`, or check whether core or Batteries already has `Relation.ReflTransGen` [check].
- **K1 (forward):** `A.halts s o → B.halts (e s) (g o)`, and `A.diverges s → B.diverges (e s)`. The divergence half uses `clock_pos`; without it, a clock of zero would let divergence map to a stuck image.
- **K2 (backward for free):** `B.halts (e s) p → ∃ o, A.halts s o ∧ g o = p`. By A's trichotomy: if A diverges, K1 makes B diverge, contradicting halting; if A stops with `o`, K1 gives `g o`, and B's `done_unique` gives `p = g o`. This is the CompCert pattern of a forward simulation plus a deterministic target giving a backward simulation (Leroy [check]), stated once for all four systems.
- **K3 (reflecting "never stuck"):** if `g⁻¹(stuck) = {Unsupported, Wrong}`, then "B never stuck from `e s`" ↔ "A never Unsupported and never Wrong from `s`". This is the corrected H3 hypothesis, obtained by transport.
- **K4 (lockstep as a special case):** `clock ≡ 1` and `g` equal to the constructor map. This is round 1's R-transport, and the `BcModel` wrapper instance is proved by `cases BcSem.step p s <;> rfl`, about 4 lines. It is not `rfl` outright, because of (c).

**What it makes free, and what it costs.**
- *Free:* all C1 members, as in round 1.
- *Free:* the outcome half of every cross-system result. Layer A's final theorem ("the ELF halts with the VM's code and output") becomes one `TimeChange` instance (`clock s` = the machine steps of the arm at `s.pc`) plus K1 and K2.
- *Free:* the arm obligations (`ArmSim`) become exactly the `more_sq` and `done_sq` fields.
- *Cost:* `more_sq` asks for an exact state `e s'`. Layer A has only a relation (the loop-head representation with `∃` placement), so the real structure is a relational variant, `TimeChangeRel` with `R : σ → τ → Prop` in place of `e`. K1 and K2 still go through, because only the target's determinism is used. The pilot should build `TimeChangeRel` from the start.
- *Cost:* the OS spec, if nondeterministic [check], is not a `DetSys`. Extension: determinize by an oracle `ω : Nat → Answer` (the probabilist's sample point). All rules then hold per `ω`, and nondeterministic reachability is `∃ ω`.

**Distant theories:**
- Time changes of stochastic processes and random time-changes (Dambis–Dubins–Schwarz style reparametrisation [check]): the same path run on a different clock.
- CompCert's forward-to-backward simulation via determinism (Leroy, CACM 2009 [check]).
- Stuttering bisimulation (Browne, Clarke and Grumberg 1988 [check]), here replaced by a positive clock with no quotient.
- Probability's sample-space determinization, for the oracle extension.

**Clusters:** C1 (including cross-system transport, which round 1 left out), and C2 (`runTo` becomes `run`).

**Pilot.**
- **H1:**
