## 1. Halochromic words: a word's pointer-colour is set by its surroundings, not by its VM sort

**Words that drove it:**
- *halochromy*: a substance's colour changes with the salt or acid around it.
- *anilinophile*: something that takes up a dye.
- *splendescent*: something that becomes visible.

A machine word "is a pointer" only relative to its environment: the young range, and whether the block holding it is scanned. That is not an intrinsic property of the word.

**Target round-1 ideas:**
- **It objects to** R1-2 #2 (sorted `vword`), R1-3 #2 E1 (typed encoding, "no raw word is ever mis-rewritten"), R1-6 #2 (`Word'` typing) and R1-5 #2 (R-Pseudomorph). Each defines the relocation action by the word's **VM sort**. The disclosed fact is that the machine GC rewrites by **bit pattern**: even and in the young range. So their master theorems prove invariance under an action that the collector does not perform.
  - Concrete counterexample: a scanned slot holds `Val.raw w` with `w` even and inside the young range. The real collector rewrites it, but `ρ·m` defined by sort copies it. The representation of `raw w` breaks, and no round-1 fundamental lemma notices.
- **It extends** R1-6 #5 (Keratectomy). That idea already decodes "by tag", but it treated ambiguous raw words as "a real modelling obligation" and left it open. This idea is that obligation, stated and discharged.

**The idea.** Keep any round-1 sort-level equivariance theorem, which is clean. Add **one bridge** from the sort action to the bit action, valid on memories satisfying a named colour-consistency invariant `Chromatic`. The bridge is the only lemma where bit patterns meet VM sorts.

```lean
def looksYoung (Y : YoungRange) (w : UInt64) : Bool :=
  w % 2 == 0 && Y.lo ≤ w && w < Y.hi          -- Is_block && Is_young, as the GC tests it
def relocBits (Y) (ρ : UInt64 → UInt64) (w : UInt64) : UInt64 :=
  if looksYoung Y w then ρ w else w            -- what the collector does to a SCANNED word

structure Chromatic (Y : YoungRange) (pl : Loc → UInt64) (s : St) (m : Mem) : Prop where
  youngExact   : ∀ ℓ, s.isYoung ℓ ↔ (Y.lo ≤ pl ℓ ∧ pl ℓ < Y.hi)   -- placement agrees with Y
  oldOutside   : ∀ ℓ, ¬ s.isYoung ℓ → blockRange pl ℓ ∩ Y = ∅
  codePale     : codeSegment ∩ Y = ∅                               -- one `decide` on the layout
  atomPale     : atomTable ∩ Y = ∅
  stackPale    : stackRange ∩ Y = ∅                                -- trap links are stack addresses
  rawPale      : ∀ slot ∈ scannedSlots s, slot.val = .raw w → ¬ looksYoung Y w
  noScanOpaque : ∀ ℓ, s.kind ℓ ∈ {bytes, double, …} → ¬ scanned ℓ  -- the GC copies these as bytes
```

**Core rules:**
- **HC-Bridge (makes L3 true of the real GC):**
  - Statement: `Chromatic Y pl s m → slot ∈ scannedSlots s → relocBits Y ρ (enc pl v) = enc (ρ ∘ pl) v`.
  - Proof: cases on `Val`.
  - `int`: the word is odd, hence pale. This is free.
  - `code` and `atom`: `codePale` and `atomPale`.
  - `raw`: `rawPale`.
  - `ptr ℓ k`: `youngExact`, plus within-block translation for young blocks and `ρ = id` for old ones.
  - This is the only bit-level lemma in C3.
- **HC-Lift:** for any round-1 sort-equivariance theorem `Equiv P`, `Chromatic → P pl m → P (ρ∘pl) (gcBits ρ m)`, by HC-Bridge applied pointwise over scanned slots. Unscanned (no-scan) blocks are byte copies, so they need no bridge.
- **HC-Step (Chromatic is a step invariant):**
  - `step p s = next s' → Chromatic Y pl s m → (new rendering) → Chromatic Y pl' s' m'`.
  - By L4, only the footprint's slots change. So the obligation is a *provenance table*: which opcodes and primitives can *create* a `raw` value, and what they create it from.
  - This is proved once per value-creating op (see idea 4, where it becomes one clause per effect op rather than per opcode).
- **HC-Necessity:** `¬ Chromatic`-style counterexample as a proved lemma, by `decide` on a three-word memory: an even, young-looking `raw` word that the bit action rewrites and the sort action does not. This documents why `rawPale` cannot be dropped, as R1-5 #2 R-Necessity did for disjointness.

**New law to check before adopting (L3c):**
- Statement: *no scanned `raw` word is even and young*.
- Check it by instrumenting the host difftest runs to dump every raw value at every GC point, on the same corpus as L4's 78,855 perturbed steps.
- If it fails, the failing site shows exactly which primitive leaks addresses (for example an `Obj`-level primitive, or naked pointers). That becomes an explicit exception list.

**Free / cost:**
- Free: every round-1 C3 proof becomes a statement about the *actual* collector. The raw-word risk flagged by R1-2 #2 and R1-2 #5 becomes one named field instead of a latent unsoundness.
- Cost: a new component of the loop-head relation (`Chromatic`, a named-field structure per Law 6), and a provenance proof for raw-creating ops.

**Distant theories:**
- Halochromic indicators in acid–base chemistry: colour is a function of the medium, not the molecule.
- Conservative vs precise collection: Boehm–Weiser ambiguous roots (SP&E 1988 [check]). `Chromatic` is exactly the condition under which a precise collector's bit test agrees with the type.
- Denning's lattice model of information flow (CACM 1976 [check]): paleness is a taint label preserved by the step.
- Type-preserving GC (Wang and Appel, POPL 2001 [check]): the mutator must never manufacture values the collector misclassifies.

**Clusters:** C3 (primary), and C2 via a decidable `Chromatic` checker on concrete snapshots.

**Pilot:**
- **H5:**
  - Split into the sort lemma (4 cases, from any round-1 C3 candidate) plus HC-Bridge (5 cases).
  - Stated: `Chromatic Y pl s m → slot ∈ scannedSlots s → relocBits Y ρ (enc pl v) = enc (ρ∘pl) v`.
  - About 12 lines, 3 of them for the `raw` case.
- **H6:**
  - Scan kinds: HC-Lift over fields.
  - No-scan kinds (string, double): `noScanOpaque`, then the block is copied byte for byte. No word-level reasoning.
  - Split this way, the 8 object kinds need 2 proofs, not 8.
- **H7:** `stackPale` gives that the addresses are fixed. Each slot goes through HC-Bridge. Raw trap links fall under `stackPale` again, since their *values* are stack addresses. About 5 lines.
- **HC-Necessity** as an added held-out negative test, by `decide`.
- H1–H4, H8, H9 and the three refactors: not targeted.

## 2. Fadable placement: garbage is affine weakening, and death is stable

**Words that drove it:**
- *fadable* and *flyblown*: dead objects rot, and their space is reclaimed.
- *panspermism*: new life seeded into the same ground.
- *plurimammate*: a finite source (the minor heap) feeding unboundedly many young.

**Target round-1 ideas:**
- **It objects to** R1-6 #2 (`ρ : Loc → Addr` injective with pairwise-disjoint ranges over *every* `Loc` in the layout), R1-2 #2 (a relocation injective on the footprints of all block ids), R1-5 #2 (`base : BlockVar → Addr` total) and R1-6 #3 R-heap-append ("every pre-existing `ptr ℓ k` stays valid (monotone world)"). Machine-checkable obstruction:
  - The VM heap only grows; the brief says nothing is freed.
  - The minor heap has fixed size `N` words. A program allocating `k·N` words of young blocks in a loop creates more than `N` VM locations that were all young at some point.
  - After the first minor collection, the next allocation is placed at a *previously used* young address, so `pl ℓ_new = pl_old ℓ_dead`.
  - Any total, disjoint placement over all VM locations is therefore unsatisfiable after one GC cycle. The representation becomes false on a correct execution.
  - The monotone-world rule is true of `BcSem` and false of the machine.
- **It objects to** R1-3 #5's quotient (`c ≈ c'` iff they "differ by some ρ on the live heap and agree elsewhere"). "Agree elsewhere" fails because the dead young area is overwritten.
- **It extends** R1-1 #2's `bigStar live P` by making "live" a *shrinkable domain* with a proved weakening rule, instead of an unexplained parameter.

**The idea.** The placement is partial: `pl : Loc → Option UInt64`, with a domain `D` that must satisfy `reach s ⊆ D`. The representation is a big separating conjunction over `D`, written in the iris-lean BI that the project already has. Iris is affine, so **dropping garbage is weakening**. The GC is "fade to `reach s`, then relocate". Allocation needs disjointness only against the current `D`, never against history.

**Core rules:**
- **F-Fade:** `Repr D s m ⊢ Repr D' s m` whenever `reach s ⊆ D' ⊆ D`. In iris-lean terms this is big-sep weakening over a submap (the `big_sepM` subset lemma [check the iris-lean name]). It costs one line, because affinity is built into the logic.
- **F-Stable (new law L5, check by fuzz):** `ℓ ∉ reach s → step p s = next s' → ℓ ∉ reach s'`. The VM cannot forge pointers: `raw` is never a pointer (disclosed fact) and allocation creates only fresh locations. So once dead, always dead.
  - Check it on the L4 corpus: 0 violations is required.
  - The likely failure points are primitives that resurrect from global tables, such as the weak or ephemeron tables and finalisers. They become an exception list.
- **F-Irrelevance (the λgc lemma):** `step p s` is unchanged if heap objects outside `reach s` are replaced arbitrarily. This is L4 read at the heap level, because the footprint reads only reachable objects. It justifies stating everything over `D`.
- **F-Alloc:** `Repr D s m ∗ freshWords a n ⊢ Repr (D ∪ {ℓ_new}) s' m'`. Freshness is relative to `D`'s ranges, which the separating conjunction provides.
- **F-GC:** `Repr D s m → Repr (reach s) s (gc m)`, with placement `ρ ∘ pl|reach`. This is F-Fade followed by the relocation law (any round-1 C3 candidate, corrected by idea 1).
- **Decidable `reach`:** without Mathlib, `reach s` is a fuel-bounded breadth-first search over the finite heap list (fuel = `heap.length`), with one soundness and completeness lemma. That lemma is itself the C2 shape, proved once.

**Free / cost:**
- Free: representation survives unbounded allocation and reuse of the minor heap. The GC statement loses its "and agree elsewhere" clause.
- Cost:
  - L5 must be checked, and it may surface weak-pointer exceptions.
  - Every C3 statement takes the domain `D` as a parameter.
  - The roots of `reach` (accu, env, the stack, extra args, trap frames, globals, channel blocks in `world`) must be enumerated once. Getting that list wrong is a soundness bug, so the enumeration must be checked against the collector's root scan. That is idea 3's T-Roots.

**Distant theories:**
- Morrisett, Felleisen and Harper, "Abstract models of memory management" (FPCA 1995 [check]). Their λgc GC rule deletes unreachable heap bindings, and its soundness is F-Stable plus F-Irrelevance.
- Affine and linear logic (Girard). Weakening is exactly the structural rule that permits disposal, and Iris's affine BI makes it primitive.
- Ecology of decomposition, the *flyblown* image: dead matter is reclaimed, and its place is recolonised (*panspermism*) with no memory of the previous tenant.
- Datalog: reachability is a monotone transitive-closure query. F-Stable is a "no negation, no invention" property of the step, the reason Datalog-style reachability is stable under insertion-only updates.

**Clusters:** C3; C2 (the `reach` checker).

**Pilot:**
- H5–H7 are unchanged in shape: each is stated with domain `D` and proved as in idea 1.
- New held-out test **H10**, stated as `Repr D s m → … → Repr D'' s'' m''`: allocate a young block, collect so that it is dead, allocate again at the same address, and show the representation still holds. This is F-Fade, then F-GC, then F-Alloc. About 8 lines. Under R1-6 #2's total placement the same statement is *refutable*, and I expect the refutation to be a short `decide` on a 2-block toy memory.
- H1–H4, H8, H9 and the refactors: not targeted.

## 3. The forwarding log *is* ρ: tricolour oldify, the remembered set as a materialised view, and the Forward_tag leak

**Words that drove it:**
- *scutiger* (shield-bearer): the forwarding header that stands in front of a moved block.
- *lineaged*: the forwarding pointer records where each block went.
- *battening*: the write barrier fastens old-to-young edges down.
- *lithify*, *hippurite* (a fossil reef-builder): promoted blocks become stone, and minor GC never moves them again.
- *cadelle*: the pest in the store, here the short-circuiting of Forward blocks.

**Target round-1 ideas:**
- **It goes where no round-1 idea went.** Every C3 candidate names the collector's correctness as a single irreducible obligation and leaves it unproved: R1-1 #2 E4, R1-2 #5 R-GC-spec, R1-4 #2 Cost 3, R1-5 #2 R-GC-is-ρ, R1-5 #5 R-GC, R1-6 #2 cost, R1-3 #5 G3.
- **It objects to L3 as those candidates use it.** They read L3 as "rewrites *every* pointer word". The 20,000-heap check tested a model relocation that rewrites globally, not the collector. Two concrete divergences from OCaml 4.14's minor collector ([check] all of `minor_gc.c`):
  1. **The remembered set.** The minor collector rewrites only its roots, the fields of promoted blocks, and the addresses recorded in `caml_ref_table` (plus the ephemeron and custom tables). An old-to-young pointer that is *not* recorded is left dangling. So "the GC effect is ρ♯" holds only under `RemSetComplete`: every old word that looks young is at an address in `ref_table`. This is a C3 component *missing from all round-1 lists*, and a Layer A obligation for every writing arm, maintained by the write barrier (`caml_modify` / `caml_initialize`).
  2. **Forward_tag short-circuiting.** `caml_oldify_one` can replace a pointer to a `Forward_tag` block (a forced lazy value) with the forwarded value itself, under conditions such as the target not being a young `Forward`, `Lazy` or `Double` [check]. That is not "moving a block as a whole": the word `pl ℓ` becomes `pl ℓ'` for a *different* VM location. If `BcSem` exposes Forward blocks (through `Obj.set_tag` and CamlinternalLazy, which the compiler uses [check]), L3 as stated is **false** for them. The representation needs a lax clause: "a pointer to a Forward block may be represented by its target's word". Check this by fuzzing with lazy-heavy programs before any C3 proof.

**The idea.** Do not state the collector's result existentially. Read ρ off memory: `ρ_m ℓ := if header(pl ℓ) = 0 then field0(pl ℓ) else pl ℓ` (forwarded blocks carry header 0 and their new address in field 0). Prove the oldify loop with a **tricolour invariant** whose partial relocation `ρ_k` *is* the current forwarding table:
- white: young and not yet forwarded;
- grey: promoted and on the todo list, with fields not yet fixed;
- black: promoted, with fields fixed through `relocBits`.

The invariant is a named-field structure `OldifyInv`, run through the existing Iris-machine WP loop rules.

**Core rules:**
- **T-Grow:** forwarding a white block allocates its target through the major allocator (`caml_alloc_shr`), copies the block, writes header 0 and the forward pointer, and extends `ρ_k`. **Disjointness of targets is discharged by the allocator's freshness spec, not assumed.** L3's necessary hypothesis (12,358 counterexamples) is an allocator post-condition, not a lemma about heaps.
- **T-Blacken:** fixing one grey field applies `relocBits` (idea 1). It is monotone in `ρ_k`, and the grey set shrinks.
- **T-Roots:** the root scan covers exactly the root set of idea 2's `reach`. This ties the collector to the representation's notion of liveness.
- **T-Done:** `todo = [] ∧ roots fixed ∧ ref_table fixed ∧ RemSetComplete → m_final|reach = ρ_final♯ (m_init|reach)`. This is L3's hypothesis-side, delivered.
- **T-Lithify:** promoted targets lie outside the young range, so every later minor collection has `ρ = id` on them. Old-generation words stay fixed unless they are recorded in the remembered set.
- **T-Barrier (Layer A, per writing arm):**
  - Statement: `RemSetComplete m → store via caml_modify → RemSetComplete m'`.
  - Proved once for the barrier routine as a function summary (a call splice), not per arm.
  - Each writing arm cites the summary.
- **T-Reset:** after a collection, `ref_table = []` and no young words exist, so `RemSetComplete` holds trivially. Hence it is cheap to re-establish per cycle.

**Free / cost:**
- Free:
  - The existential "∃ ρ with Disj" becomes an explicit term, `ρ_final`, read from memory.
  - The disjointness hypothesis is supplied by an existing abstraction (allocator runs).
  - `RemSetComplete` and the Forward clause surface *before* the 40 C3 proofs are written against a law that is false for the collector.
- Cost:
  - The tricolour invariant proof over the real `caml_oldify_*` loop, which is real work.
  - `RemSetComplete` becomes a loop-head field.
  - The Forward clause complicates value encoding (idea 1's `enc` becomes a relation for Forward targets).

**Distant theories:**
- Dijkstra, Lamport et al., tricolour on-the-fly marking (CACM 1978 [check]) and Cheney's scan (CACM 1970 [check]).
- Databases:
  - The remembered set is a **materialised view** of old-to-young edges. The write barrier is its **incremental view-maintenance trigger**, and `RemSetComplete` is view completeness.
  - Forwarding pointers are a **redo log**: replaying the log reconstructs ρ, as in ARIES (Mohan et al., TODS 1992 [check]).
- Generational collection and remembered sets (Ungar 1984 [check]).
- Geology: lithification. The promoted generation is the stone record, never re-sedimented by minor GC.

**Clusters:** C3 (the collector side); Layer A writing arms (`T-Barrier`).

**Pilot:**
- H5–H7 are the invariance side and are unaffected; ideas 1 and 2 cover them.
- Two added held-out tests:
  - **HGC-0:** a Lean model of `oldify` on a 3-block heap with one old-to-young pointer. Recorded: the result equals `ρ♯` (T-Done). Unrecorded: a counterexample by `decide`. About 30 lines for the model and 10 for each direction.
  - **HGC-F:** a Forward block short-circuited by the model. It shows `enc (ρ∘pl) (ptr ℓ_fwd 0) ≠ relocBits …`, by `decide`, as the documentation lemma forcing the lax clause.
- Refactors: none.

## 4. Vesseled semantics: one effect-tree semantics, where lenses, symbolic stepping, footprints and checkers are *handlers*

**Words that drove it:**
- *vesseled*: effects contained in a vessel and interpreted by a handler.
- *hydrazino*: a small reactive functional group, here about a dozen primitive ops that do all the chemistry.
- *biochemy*: enzymes (handlers) act on the same substrate in different ways.
- *creese*: the same blade cuts concrete and symbolic.

**Target round-1 ideas:**
- **It objects to** R1-2 #3 R-Local, R1-3 #3 P2, R1-4 #3 (`step = interp ∘ patchOf`, "falls to `cases op <;> rfl` … [risk]") and R1-5 #3 R-Stencil. Each needs a **second, ~150-arm description** of the semantics (`patchOf`, `δ_i`, stencils), proved equal to `BcSem.step` by an opcode sweep.
  - `BcSem` is grown by transcribing `interp.c` arms and primitives.
  - Every new opcode or primitive then costs two transcriptions plus a sweep arm.
  - The sweep is exactly the duplicated, mechanical work that Law 3 forbids.
- **It objects to** R1-1 #5 (a step polymorphic over a `ValueDomain`). Polymorphism in *values* does not expose *which cells were read*, so it gives naturality but not footprints or heap framing.
- **It objects to** R1-6 #1 R-checker ("each C2 obligation reduces to a single `csimp` equation", via `@[implemented_by]`/`csimp`).
  - `decide +kernel` ignores `implemented_by` and evaluates the reference definition.
  - `@[csimp]` affects only compiled code and requires the equation *as a proved theorem*, which is the 4–20 lines of C2 again.
  - So it is no saving for kernel-checked facts.
- **It combines** R1-1 #5's naturality square with R1-4 #3's patch normal form, as two handlers of one object.

**The idea.** Write each instruction once as a tree of primitive VM effects, in a first-order free monad that lives in `Type`. Results are a small sum type `Res`, not an indexed `VmOp β`. That keeps `Eff` in `Type 0` for kernel reduction and avoids a universe bump. Define `BcSem.step p s := runConc (stepE (code p s.pc)) s`, *definitionally*.

Every other view is a handler of `Eff`, proved correct **by induction on `Eff`, once**. The proof obligations scale with the number of ops (about 12), not the number of opcodes (about 150).

```lean
inductive Op | pc | setPc (n : Nat) | accu | setAccu (v : Val) | peek (i : Nat) | push (v : Val)
             | pop (n : Nat) | env | setEnv (v : Val) | field (ℓ : Loc) (i : Nat)
             | setField (ℓ : Loc) (i : Nat) (v : Val) | alloc (tag : Nat) (fs : List Val)
             | halt (c : Int) | unsupported | wrong      -- world/extra/trap ops elided
inductive Res | unit | val (v : Val) | nat (n : Nat) | loc (ℓ : Loc)
inductive Eff | ret | op (o : Op) (k : Res → Eff)      -- first-order, Type 0
```

**Core rules (proved once, by induction on `Eff`):**
- **V-Def:** `BcSem.step = runConc ∘ stepE`, by `rfl`. There is no second semantics. A new opcode is one new `stepE` arm, and every handler theorem already covers it.
- **V-Local (L4 as a proved rule):**
  - `readsOf e s` (the footprint handler, which returns the list of cells touched) satisfies `agreeOn (readsOf e s) s s' → runConc e s ≈[writesOf e s] runConc e s'`.
  - Each op's clause is a one-line cell lemma. The induction is generic.
  - Data-dependent footprints (`APPTERM n`, a field index read from the stack) are free: the continuation has already seen the read value.
- **V-Nat (R1-1 #5 N1 without rewriting values):** the template handler `runSym` over states with a symbolic stack tail `?rest` and symbolic `?env`, `?heap` and so on satisfies `runSym e t = some t' → ∀σ, runConc e ⟦t⟧σ = ⟦t'⟧σ`. There is one naturality lemma per op.
- **V-Patch:** a branch-free `Eff` normalises to a patch (R1-3 #3's ⊙ and R1-4 #3's `Patch.comp`). Patches are a *derived normal form*, never a hand-maintained table.
- **V-Handler-morphism (C2):**
  - A checker is `runH` for some handler `H`, with a handler morphism `h : H → Conc` (the `op` clauses commute).
  - `runConc = h ∘ runH` then follows by one induction.
  - Seven C2 members become seven morphism instances of about 12 clauses each, generic in the program.
- **V-Provenance:** idea 1's `HC-Step` and idea 2's F-Stable become per-*op* facts. Only `alloc` creates a location, and the ops that create `raw` values are listed. The per-opcode provenance proof disappears.

**Free / cost:**
- Free:
  - L4, naturality, patches, footprints and checker soundness become one proof each by induction on `Eff`.
  - BcSem growth costs one arm.
  - H8-style "from any state" facts come from `runSym` by `rfl`.
- Cost:
  - Re-expressing the existing `BcSem.step` arms as `Eff` terms, once. This is mechanical from the existing Lean arms via `do` notation over `Eff`, and the difftest is unchanged because `step` is the same function extensionally.
  - Kernel reduction of long runs pays an interpretive overhead, estimated at 1.5–3×. Measure it against `runTo`'s chunked `decide +kernel` baseline before adopting.
  - Primitives (`primF1Impl`) with deep internal computation can be a single opaque op whose footprint is declared. That leaves one small ledger, but not a second semantics.

**Distant theories:**
- Algebraic effects and handlers (Plotkin and Power 2002; Plotkin and Pretnar, ESOP 2009 [check]).
- Interaction trees (Xia et al., POPL 2020 [check]), and Swierstra, "Data types à la carte" (JFP 2008 [check]).
- Microprogramming (Wilkes 1951 [check]). An ISA instruction is a microprogram over a dozen micro-ops, and locality is a property of the micro-ops.
- Biochemistry: substrate and enzyme. One substrate (the effect tree) is transformed by different enzymes (handlers), and each enzyme's specificity is a property of the functional groups (ops) it acts on.

**Clusters:** C4 (straight-line code and framing), C2 (the checkers), and it feeds C3's provenance obligations.

**Pilot:**
- **H8:**
  - `stepE` gives `CONSTINT 40 ↦ op (setAccu 40) (λ_ => op (setPc 1) ret)` and so on.
  - `runSym` from template `⟨pc=0, stack=?rest, accu=?a, …⟩`, four times, computes `⟨pc=4, stack=?rest, accu=int 42⟩` by `rfl`.
  - V-Nat then gives the result for all states.
  - About 4 lines, and the 63-bit add reduces by `decide`.
- **H9:** the body is one `runSym` pass with the branch as a template case split. The loop is idea 5.
- **H1–H4:** not targeted, but see the C1 note at the end.
- **Refactor, VM run-determinism:** unaffected, since `step` is still a function.
- **Refactor, conversion between `BcModel` reachability and the VM n-step relation:** unchanged, because `BcModel`'s step is V-Def's `step` by `rfl`.
- **C2 refactor bonus:** the runner or checker with the largest C2 cost becomes a handler, and the pilot measures its morphism proof.

## 5. Lithified loops: decompile bytecode into Lean functions with a proved `tailrec`, instead of hand-writing Poincaré maps

**Words that drove it:**
- *lithify*: loose sediment (bytecode) compacted into rock (Lean terms).
- *rebehold* and *amphoriloquy*: the program seen again as an echo in another vessel.
- *bargainee*: a call site receives the callee's contract.
- *globulous*: functions as self-contained globules.

**Target round-1 ideas:**
- **It extends** R1-4 #4 (Poincaré sections, the semi-conjugacy `α ∘ R = f ∘ α`) and objects to its scaling claim that "each OCaml source function already is the `f` … α per function has to come from the source".
  - At Layer B′ there is no Lean semantics of OCaml source; that is Layer C.
  - Source functions use closures, exceptions (`trap`), mutation and I/O (`world`), so a pure `f : A → A ⊕ B` over the source does not exist for most of the 412k instructions.
  - Hand-writing `f` and `α` for thousands of functions is per-site work.
- **It merges** R1-6 #4's ledger and R1-2 #4's Circ-rank as the termination premise of a single combinator, so they stop being rival loop logics.

**The idea.**
- A generator reads `dumpobj` output and emits, per bytecode function or loop, a Lean function in *view variables*. Arithmetic is emitted over `Int` with an explicit overflow side condition, not BitVec 63, because `bv_decide` is banned.
- Alongside it, the generator emits a *certificate theorem* proved by one fixed tactic, idea 4's `runSym` plus V-Nat: "from any VM state whose view is `a` and whose pc is the entry, the VM reaches the exit view `f a`".
- Loops are emitted through one combinator, `tailrec`. Calls become Lean calls to the callee's decompiled function.
- Human work is reasoning about the pure Lean `f`: `omega`, `decide`, induction, or a proof that `f` refines a Layer-C source model once one exists.

**Core rules:**
- **LT-Tailrec:**
  - `tailrec (body : A → A ⊕ B) (fuel : Nat) : A → Option B`.
  - With `TailrecOK pre rank body := ∀ a, pre a → ∀ a', body a = .inl a' → pre a' ∧ rank a' < rank a`, we get `pre a → ∃ b, ∀ n ≥ rank a + 1, tailrec body n a = some b`.
  - Fuel-indexed, so no `partial` and no Mathlib. Proved once by well-founded induction on `rank`.
  - This is R1-2 #4 Circ-rank and R1-6 #4 R-ledger, specialised to a function.
- **LT-Semiconj:** if the generated block certificate `∀ s, view s = a → pc s = head → runBlock s = (the view of body a)` holds, then the VM from `head` reaches the exit with view `tailrec body _ a`. This is R1-4 #4's transport rule, proved once, generic in `body`.
- **LT-Pre (side-condition functions):** `Wrong`, `Unsupported` and 63-bit overflow become a generated `f_pre : A → Prop` that the human discharges. This is the Myreen-style precondition, which keeps `f` total and honest.
- **LT-Call (bargainee):** a callee's certificate is cited at the call site as a lemma about a Lean function call, and nested sections compose (R1-4 #4 functoriality). The caller's proof never re-enters the callee's code.
- **LT-Frame:** from idea 4's V-Local, certificates quantify over the rest of the state for free.
- **LT-Heap:** for heap-touching code, `A` includes a *heap view* whose shape comes from the footprint handler. Allocation appears as `alloc` in `f`'s state-passing. This is where purity gives way, and it is honest about it: `f` is state-passing over the abstract VM heap, never over placements.

**Free / cost:**
- Free:
  - Loop and function specifications at the size of the program, generated.
  - Per-loop human work is reduced to a rank and a precondition.
  - The Poincaré square is proved by the generator's fixed tactic, not by hand.
  - C2 soundness is not needed per run: this is translation validation per function.
- Cost:
  - The generator plus certificate tactic, which must stay inside the elaboration budget. Large functions need chunking at cut points; back-edges give the cut points.
  - Indirect calls through closures (`APPLY` on an unknown closure) need a *closure-contract table*: a spec per code pointer.
  - Exceptions become an `Except` in `f`'s result.

**Distant theories:**
- Decompilation into logic: Myreen, Slind and Gordon (FMCAD 2008 [check]); Myreen and Gordon on function extraction [check].
- CakeML's proof-producing translator (Myreen and Owens, ICFP 2012 [check]), run in reverse.
- McCarthy's translation of flowcharts into recursive function definitions (1962–63 [check]).
- Poincaré return maps (R1-4 #4).
- Geology: lithification. Structure is preserved while the medium changes from sediment to stone.

**Clusters:** C4 at scale (primary); C2 (translation validation replaces checker soundness).

### Cross-note on the C1 cluster, given the post-round-1 facts

This note makes no separate claim; it records obstructions to named round-1 ideas.
- **R1-2 #1 and R1-4 #1** build on Mathlib's `Computation`. **R1-4 #5** builds on Mathlib's `KleeneAlgebra` and `OrderHom.gfp`. **R1-5 #1 R-Closure** and **R1-6 #1** cite `Relation.ReflTransGen`. None of these exist here: Lean core, Batteries and iris-lean only. Each would have to be rebuilt first, including `mem_unique` and the absorbing-stream structure. The fuel-iterate variants (R1-3 #1, R1-6 #1) have no such dependency.
- `VsaIris.MachineModel`'s `StepResult` is already `next | halt | stuck`. So the orbit algebra should be proved directly on `MachineModel`, with the machine and `BcSem` as its existing instances, rather than on a new `DetSys` class. That removes the bridge each round-1 C1 idea pays.
- Caveat for **H3**: `BcModel` collapses `Unsupported` and `Wrong` into `stuck`. At the `BcSem` level, "never-Wrong" alone does **not** give "diverges ↔ ¬halts", because a run can stop at `Unsupported`. The held-out statement must say "never stuck" at the model level, or the transport must carry an outcome map that reflects `Unsupported`.
