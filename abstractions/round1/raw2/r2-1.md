## A. Time-change morphisms: Kakutani induced maps as the one transport rule

**Seed driver:** the palindrome `zcYYcz` (a square that commutes) and the stutter insertion `KupJ → KukpJ`.

**Relation to round 1: an objection, then an extension and a combination.**

*The objection.* Every C1 candidate carries its conversions with a strict commuting square:
- R1-4 #1 R6: `step' ∘ h = map h ∘ step`;
- R1-6 #1 R-transport;
- R1-5 #1 R-Transport;
- R1-1 #1: "`iterate_map` strict square".

Two concrete reasons this is too weak:
1. **Refactor 3 is not `h = id`, `rfl`.** R1-4 #1 and R1-6 #1 both claim it is. `BcModel`'s step lands in `StepResult` (three outcomes) while `BcSem.step` has four. So the square carries a *lossy* outcome map `g : Halt c w ↦ halt c (out w); Unsupported, Wrong ↦ stuck`. Because `g` is not injective, a strict "transport of behaviour" theorem gives only the forward direction. For example, "the VM never goes Wrong" cannot be recovered from generic-model facts, because Wrong and Unsupported are merged.
2. **Layer A has no strict square.** One VM step corresponds to k(s) machine steps, and GC inserts more machine steps. R1-3 #5 noticed the GC stutter but kept a quotient. R1-4 #4's Poincaré return map is also a variable-time map. Neither is expressible as a strict morphism.

*The extension.* Replace strict morphisms with **time changes**, and observe that R1-4 #4's return map is exactly Kakutani's *induced transformation*. Round 1 used the Poincaré picture only for loops. The same one structure then covers:
- the model conversion (k ≡ 1, lossy g);
- Layer-A arm simulation (k = the machine steps per arm);
- GC stutter (k grows by the collector's run);
- loop sections (the induced system on Σ).

**The idea.** Define one named structure (CLAUDE.md law 6: named fields, not an ∃/∧ tower), over a Mathlib-free run algebra (`run` by `Nat.rec`, uniqueness by `Nat.le_total`, trichotomy by `Classical.em`; no `Nat.find` needed):

```lean
structure TimeChange (A : DetSys C O) (B : DetSys D P) where
  h      : C → D
  g      : O → P
  k      : C → Nat
  k_pos  : ∀ c, 0 < k c                          -- no infinite stutter
  sqNext : A.step c = .next c' → B.run (k c) (h c) = .next (h c')
  sqStop : A.step c = .stop o  → ∃ j, j ≤ k c ∧ B.run j (h c) = .stop (g o)
```

For Layer A, `h` becomes a relation, because placement is existential: `TimeChangeRel` with `sqNext : R c d → A.step c = .next c' → ∃ j, 0<j ∧ ∃ d', B.run j d = .next d' ∧ R c' d'`.

**Core rules (each proved once).** L1 is used as the definition `rel n c c' :≡ run n c = .next c'`.
- **T1, run transport (L1 + R-act):** `A.run n c = .next c' → B.run (Σ_{i<n} k(cᵢ)) (h c) = .next (h c')`. With `k ≡ 1` the time is exactly `n`; this is the specialization used for refactor 3.
- **T2, halting transport:** A halts with `o` → B halts with `g o`. The converse holds when `g` *reflects* halting (`g o = halt _ → o = Halt _`). This is the named premise that the lossy map is still safe for halting.
- **T3, divergence transport:** A diverges → B diverges. This needs `k_pos`. Without it, a `k = 0` counterexample exists (A spins, B halts). This is the well-foundedness condition in CompCert's "simulation with measure" [check: Leroy, JAR 2009], proved rather than assumed.
- **T4, category:** time changes compose (`k'' c = Σ` of `k'` along the `k c` steps), with identity `k ≡ 1`.
- **T5, induced system (Kakutani):** for a section `Σ ⊆ C` with a return-time premise `ret : ∀ c ∈ Σ, ∃ j>0, A.run j c ∈ Σ ∪ stop`, the induced `A|Σ` is a `DetSys` and the inclusion is a `TimeChange (A|Σ) A`. A loop then becomes an induced system. R1-4 #4's semi-conjugacy `α ∘ R = f ∘ α` is a strict (`k ≡ 1`) morphism from `A|Σ` to the Lean function `f` presented as a `DetSys`, so T4 composes it with the inclusion.
- **T6, lossy reflection:** for a lossy `g`, the facts that transport backwards are exactly those stated on `g`-saturated outcome sets. This is where the "never wrong ⇏ from generic model" limitation becomes a proved rule and not a surprise.

**Free, and cost.**
- *Free:* all C1 conversions; the machine↔VM↔model triangle; loops as induced systems; GC stutter without quotients. H3 and H4 become one lemma over `DetSys` with a "bad-outcome set" parameter.
- *Cost:* for `TimeChangeRel`, the `Σ k` bookkeeping is existential, so T1 in relational form gives `∃ m ≥ n`. Computing `k` for Layer-A arms comes from the arm segment family, one per arm. It is not free, but it is already planned.

**Distant theories:**
- Ergodic theory: Kakutani's induced transformations, time changes of flows, Kakutani equivalence [check: Kakutani 1943].
- Relativity: proper time vs coordinate time, where the same worldline is reparametrised.
- Stuttering bisimulation (Browne–Clarke–Grumberg, TCS 1988 [check]) and Lamport's stuttering-invariant TLA.
- CompCert's star/plus simulation with a measure [check].

**Clusters:** C1 (conversions, H1–H4), C4 (loops via T5), and the Layer-A use of C3 (GC as stutter).

**Pilot:**
- **H1:** `DetSys.halt_unique` for `MachineModel` viewed as a `DetSys`: absorption plus `Nat.le_total`, about 4 lines generic, 0 per instance.
- **H2:** `reach ↔ ∃ n, run n = next`. Our own `RTC` inductive is proved once, about 15 lines, because `ReflTransGen` is not in core [check whether Batteries has it].
- **H3 and H4:** one generic lemma `neverBad (Bad : O → Prop) → (diverges ↔ ¬ halts)`, instantiated with `Bad := Wrong ∨ Unsupported` and with `Bad := stuck`. I flag the brief's ambiguity (whether H3 excludes Unsupported) as resolved by *parameterising* over `Bad`.
- **H5–H7:** not targeted.
- **H8:** not targeted. It is a `k ≡ 1` strict run.
- **H9:** Σ = {loop head}. The induced map is strict-conjugate to `f i = if i<10 then .next (i+1) else .stop 10`, and T4 plus T2 give halting with accu 10. The body's return time `j` is one straight-line evaluation (idea C).
- **Refactor, VM run determinism:** becomes `DetSys` instance projections.
- **Refactor, machine run composition:** R-act.
- **Refactor, generic reach ↔ VM n-step:** `bcTimeChange : TimeChange BcSem BcModel` with `k ≡ 1`, `h = id` and the lossy `g`; then T1 with `k ≡ 1`. It is about 6 lines, and it states honestly which direction is lossy.

## B. Classifier coherence: the C3 families prove the wrong L3, and here is the repair

**Seed driver:** `UFU`, one middle letter that two readers classify differently (the VM calls a word raw; the GC calls it a pointer).

**Relation to round 1: a concrete objection to every C3 candidate, then a combination with R1-6 #5.**

*The objection.* R1-1 #2, R1-2 #2/#5, R1-3 #2, R1-4 #2, R1-5 #2/#5 and R1-6 #2 all define `ρ♯` by *VM sort*: "the VM value's constructor, not the bit pattern, decides" (R1-2 #2), and "no raw word is ever mis-rewritten" (R1-3 #2). They then each posit a single GC-facing obligation: R-GC-is-ρ (R1-5 #2 rule 5), R-GC-spec (R1-2 #5), and "GC must compute reloc r" (R1-6 #2).

With the addendum's fact that the machine GC classifies by bit pattern and young range, **that obligation is false as stated**. Take any scanned slot holding a VM `raw w` (or a `code pc` word) with `w` even and inside `[young_start, young_end)`:
- the GC rewrites it;
- `ρ♯` copies it;
- so `gc m ≠ ρ♯ m`.

The equivariance theorems then prove invariance under a map the collector does not perform. R1-2 #2 flagged this as a risk; nobody fixed it.

A second, subtler leak: young *range* is not the same as young *live blocks*. A raw word equal to a *dead* young address is also rewritten, or corrupts the collector's forwarding test. So an invariant stated per live block is insufficient.

**The idea.** Split L3 into two proved rules joined by a named invariant.
1. Keep any round-1 equivariance engine (DSL, pullback or pushforward) for the *sorted* action `ρ♯ₛ`.
2. Add one **coherence theorem**: on memories satisfying `NoYoungAlias`, the GC's classifier action `ρ♯_gc` equals `ρ♯ₛ`.

`NoYoungAlias` is a named-field structure:

```lean
structure NoYoungAlias (L : Layout) (π) (m : Mem) : Prop where
  scannedNonPtr : ∀ a ∈ scannedAddrs π m, ¬ isPtrVal (valAt a) → ¬ youngBits (m a)
  codeOutside   : codeSegment ∩ youngRange = ∅          -- one `decide` on Layout constants
  noScanOpaque  : ∀ blk, tag blk ≥ NoScanTag → fields blk ∉ scannedAddrs π m
```

Here `youngBits w := w % 2 = 0 ∧ w ∈ [young_start, young_end)`, read from `Layout.lean`, never hand-written.

**Core rules:**
- **K-coh (the repaired L3):** `NoYoungAlias L π m → ρ♯_gc r m = ρ♯ₛ r m` on scanned addresses. The only arithmetic is `enc (int n) = 2n+1` (odd, so never young) and `enc (code pc) ∈ codeSegment`.
- **K-pres:** `NoYoungAlias` is itself relocation-invariant when the targets lie outside the young range (promotion). The allocation-invariance half is idea E's K1.
- **K-obstruction (CLAUDE.md law 4, a machine-checked obstruction):** a concrete `decide`d counterexample `m₀` with one stack slot `raw (young_start + 8)` where `ρ♯_gc r m₀ ≠ ρ♯ₛ r m₀`. This lemma is kept permanently, like R1-5 #2's R-Necessity, so the premise cannot be "simplified away".
- **K-peel (combination with R1-6 #5):** define `peel` to decode words with the *GC's* classifier (`youngBits` first, then the placement lookup). R-peel is then coherent by construction. `NoYoungAlias` becomes exactly R1-6 #5's `Wf` clause, and K-coh becomes a corollary. This gives the pullback-vs-pushforward bake-off a discriminator round 1 lacked: **pullback states the invariant in the GC's own sort; pushforward needs K-coh as an extra theorem.**

**Free, and cost.**
- *Free:* the GC-facing obligation becomes *true*. It is also now stated at the level the collector's code actually implements (`Is_block && Is_young` [check against `minor_gc.c`]).
- *Cost:* the laws stage must re-run the L3 checker with bit-pattern classification and with raw words sampled into scanned positions. I predict counterexamples appear exactly when raw words sit in scanned slots.
- *Cost, a modelling question pushed back:* where can BcSem's `raw` appear in a *scanned* position? If only inside no-scan blocks (doubles, strings, custom), `scannedNonPtr` is vacuous for raw words. If `raw` ever reaches the VM stack or accu, it is a real obligation per primitive.

**Distant theories:**
- Conservative vs precise garbage collection (Boehm–Weiser 1988 [check]): ambiguous roots are exactly this failure mode.
- Typed assembly language and GC-safety as typing (Morrisett et al., TOPLAS 1999 [check]).
- Databases, schema-on-write vs schema-on-read: the VM constructor is the write-time schema, the GC bit test is the read-time schema, and coherence says they agree on all stored rows.
- Information-flow labels / taint: a word may only be declassified to "pointer" by the encoder.

**Clusters:** C3.

**Pilot:**
- **H5:** stated with `NoYoungAlias`. By `cases v`: `int` is odd, so both actions fix it; `ptr` is the round-1 atom law; `code` is fixed via `codeOutside` (by `decide`); `raw` is fixed via `scannedNonPtr`. About 10 lines. *Without the premise, H5 is false, and K-obstruction is the witness.*
- **H6:** the header word is odd-tagged per OCaml's header format [check], so it is not young; fields go through H5; no-scan kinds go through `noScanOpaque`. About 6 lines.
- **H7:** the stack is scanned. Every slot goes through H5, and the base is fixed. About 4 lines.
- **H1–H4, H8, H9, and the three refactors:** not applicable.

## C. Code as footprint: slice locality and pc-translation equivariance

**Seed driver:** `kyk`, with `Uk` / `LUk` / `Kuk` recurring at different offsets: the same fragment at different addresses.

**Relation to round 1: goes where none of round 1 went.** Every C4 candidate fixes the whole program in the precondition:
- `code = P` in R1-2 #4 H9;
- "R may depend on the pc and the decoded instruction" in R1-5 #3;
- "the code list is concrete, so decode reduces definitionally" in R1-6 #3.

L4 was applied to the *state* only. Two objections:
1. **Reduction cost at scale.** R1-6 #3 and R1-1 #5 close H8-style goals by `rfl` / kernel reduction. On a 412,087-instruction `Prog`, `P.code[pc]` for a literal array reduces through `List.get` in O(pc) kernel steps per fetch [check: the kernel has no `Array` acceleration]. That is roughly 10⁵ unfoldings per instruction, and it collides with CLAUDE.md law 1 (the elaboration budget).
2. **No reuse across programs.** The same stdlib function's bytecode appears in the compiler, the tests and the bootstrap stages, at different offsets.

**The idea.** Treat the code as part of the footprint (L4 applied to `Prog`), and treat pc-translation as a symmetry (the Erlangen idea of the C3 candidates, used positively on code). Specs are proved against a tiny slice `P₀` at base 0 and lifted to any program that contains a translate of `P₀`.

**Core rules:**
- **CL0 (code locality, L4 applied to code):** `P.fetch s.pc = P'.fetch s.pc` together with an operand-window agreement → `step P s = step P' s`. It is proved by one `cases` on the fetched instruction, since `step` reads code only at `pc … pc+arity` [check: `CLOSUREREC` and `SWITCH` read variable-length operand windows; the window is a function of the fetched operands].
- **CL1 (slice lifting):** `P₀ ⊑ P` (P agrees with P₀ on dom P₀), plus the run on P₀ staying `Confined` to dom P₀, gives `run P n s = run P₀ n s`. This follows from CL0 and R-act. `Confined` is a named structure listing the pcs visited, checked by `decide` on the slice.
- **CL2 (translation equivariance):** `step (shift d P) (shift d s) = (step P s).map (shift d)`, where `shift d` acts on `s.pc` and on every `Val.code` in accu, stack, env and heap fields. OCaml bytecode branches and closure offsets are pc-relative [check: `pc += *pc` in `interp.c`], so `shift` is an action of ℤ that commutes with `step`. This is one opcode sweep, with the law first fuzzed against `runbc` as CLAUDE.md requires for growing BcSem.
- **CL3 (spec transport):** any spec whose pre/post mention code pointers only through `shift`-equivariant atoms transports from base 0 to base d.
- **Fallback CL4:** if CL2 fails for some opcode (e.g. an absolute-pc primitive), store code as a radix trie keyed by pc bits, which gives depth ≈19 reduction per fetch. This is an engineering fallback; slices make it unnecessary in the common case.

**Free, and cost.**
- *Free:* kernel reduction only ever sees 5–50-instruction slices, never the 412k array.
- *Free:* one spec per function body, reused at every program and offset where that code occurs.
- *Free:* the compiler's function specs become per-slice artifacts that `runbc --lean` can emit. The `Confined` side condition is one `decide` per slice.
- *Cost:* the CL2 sweep. Any global data holding absolute code pointers (closures in globals at load time) must be shifted too, which the loader has to expose.
- *Cost:* calls out of the slice break `Confined`. Callee specs enter as time-changed summaries (idea A, T4/T5), not by enlarging the slice.

**Distant theories:**
- Linkers and position-independent code; Cardelli, "Program fragments, linking, and modularization", POPL 1997 [check].
- Separation logic with code as a resource and a frame rule over code: Jensen–Benton–Kennedy, "High-level separation logic for low-level code", POPL 2013 [check]; Saabas–Uustalu 2007 [check].
- Crystallography / Bloch's theorem: translation symmetry lets one unit cell's analysis cover the lattice.
- Noether-style reasoning: a continuous symmetry, here discrete translation, yields a conserved, reusable quantity (the spec).

**Clusters:** C4 at the 412k scale; C2 (the `Confined` checker is `decide`, sound by `decide_eq_true`).

**Pilot:**
- **H8:** prove it on `P₀ = [CONSTINT 40; PUSH; CONST2; ADDINT; STOP]` by symbolic reduction, with the stack tail free. Idea D-independent: R1-6 #3's membrane form works here *because* P₀ is 5 instructions. `Confined` is `decide`, and CL1 lifts to any `P ⊒ P₀`. About 6 lines; the "any program containing this block at any base" generalization costs 2 lines more via CL3.
- **H9:** the loop slice (about 8 instructions). The body return map is reduced on the slice and the iteration uses idea A's T5. The spec is then lifted by CL1.
- **H1–H7:** not applicable.
- **The three refactors:** not applicable, except that CL1 is itself a run-level corollary of R-act.

## D. Oracle skew products: one C1 class for the nondeterministic OS spec too

**Seed driver:** the doubles `YY`, `CC`, `XX`, `55`: a state paired with its twin tape.

**Relation to round 1: extends R1-3 #1's admitted gap and goes where none went.** The C1 census lists "the OS spec" among the re-proving relations. R1-3 #1 conceded that "a genuinely nondeterministic OS spec does not fit and needs … a powerset lifting". Every other C1 candidate silently assumed determinism. A powerset lifting destroys the function-based algebra (`run` is no longer a function), so the "L1 as definition" trick dies exactly there.

**The idea.** Present a nondeterministic system `S : C → Next C → Prop`, or a finite-choice `C → List (Next C)`, as a deterministic **skew product over an oracle shift**:
- `det S : DetSys (C × Oracle)`, where `Oracle := Nat → Nat` is a choice stream;
- the step consumes `ω 0`, picks that alternative (defaulting on an out-of-range index), and shifts `ω`.

All C1 rules then hold *per oracle* by the same class. Relational facts are `∃ ω` / `∀ ω` over deterministic ones.

**Core rules:**
- **S1 (L1 lifted):** `RTC S c c' ↔ ∃ ω n, (det S).run n (c, ω) = .next (c', _)`. This is proved once from L1 for `det S` plus a choice-extraction lemma (build ω from a run by `List`-indexing).
- **S2 (per-oracle determinism):** uniqueness, absorption and trichotomy hold for each fixed ω, for free from the `DetSys` instance.
- **S3 (may/must):** `mayHalt := ∃ ω, halts (c, ω)`, `mustHalt := ∀ ω, halts (c, ω)`. Angelic and demonic facts are quantifier placement, not new lemmas.
- **S4 (deterministic embedding):** a deterministic system is `det` with `Oracle` ignored. The embedding is a `k ≡ 1` time change (idea A), so the VM, machine and model lose nothing.
- **S5 (checker soundness, C2):** a trace-acceptance checker (SibylFS-style: "does this observed trace belong to the spec?") is sound iff it outputs an oracle witness ω that `decide` replays. Soundness is then R-act plus `decide_eq_true`, which gives certificate checking in place of per-checker proofs, extending R1-5 #4 (Manifest) to nondeterminism.

**Free, and cost.**
- *Free:* the OS spec's C1 members join the same class, so all four "re-proved for every step relation" instances collapse. C2 trace checkers get a uniform witness format.
- *Cost:* `Oracle = Nat → Nat` is not decidable to quantify over. `∀ ω` facts need an invariant, not `decide`. Oracle extraction (S1 ←) needs choice over finite lists, which is fine in core. If the spec's nondeterminism is infinitely branching (e.g. arbitrary error codes), the oracle ranges over `Nat → α` with a default.

**Distant theories:**
- Random dynamical systems as skew products over a base shift (Arnold, *Random Dynamical Systems*, 1998 [check]).
- Prophecy variables (Abadi–Lamport 1991 [check]): the oracle is a prophecy of all future choices.
- Skolemization in logic: `∀∃` becomes a choice function.
- Game semantics: a run is a play against an opponent strategy, and the oracle is the strategy.

**Clusters:** C1 (the OS-spec members) and C2 (trace checkers).

**Pilot:**
- **H1–H4:** unchanged for deterministic systems (via S4). The new content is their OS-spec analogues, e.g. `halt_unique` per ω in 0 lines, and "must-halt ↔ ¬may-diverge" classically in about 5 lines.
- **H2:** for the OS spec it is S1, about 20 lines once.
- **H5–H9:** not applicable.
- **Refactor, VM determinism:** unaffected (S4).
- **Refactor, run composition:** unaffected.
- **Refactor, the conversion:** unaffected.
- The honest scope is the OS-spec share of C1's 31 members, which should be measured by the census.

## E. Generational Kripke worlds: minor GC is one-shot promotion, gated by a remembered-set invariant

**Seed driver:** `2084` (time only moves forward), with `30k54` / `02` / `13` read as generations 0 and 1.

**Relation to round 1: objects to R1-3 #5 and R1-5 #5, and to the "ρ♯ rewrites every pointer" premise shared by all C3 candidates; combines L3 with R1-6 #3's R-heap-append.**

*Objection 1: the groupoid/quotient framing is wrong.*
- R1-3 #5 G1 ("invertible on its image") and R1-5 #5 R-Equiv ("an identity and an inverse") rely on inverses.
- An admissible minor-GC relocation maps young → free old-gen space. Its inverse moves old → young, which is not admissible, so `~` is not symmetric.
- The quotient must therefore be the *equivalence closure*. That closure contains old→young moves, which break idea B's `NoYoungAlias` (moving a block into the young range can make an existing raw word alias it).
- So R-Follow-WD over the closure is either false or needs a stronger invariant. Lean `Quot` friction is then paid for nothing.

*Objection 2, a new gap.* L3 says the GC "rewrites every pointer to" a moved block. A real generational minor GC finds old→young pointers only through the **remembered set** (`ref_table`, filled by the `caml_modify` write barrier [check: OCaml 4.14 `minor_gc.c`]). An old-block field holding a young pointer that is *not* in `ref_table` is not rewritten. Therefore R-GC-is-ρ needs a representation invariant `RememberedComplete`, which none of round 1 stated. L3 as checked on random heaps would not find this, because the checker's relocation is idealised.

**The idea.** Placement is a Kripke world `W = ⟨πold, πyoung, heapLen, refTable⟩` with a monotone accessibility `W ⊑ W'` generated by two moves only:
- **alloc:** the VM heap is appended (L4's append) and `πyoung` is extended with a fresh young range;
- **promote r:** every `πyoung` loc is moved to disjoint free old space and `πyoung := ∅`. Old-gen placements are never moved [check that compaction is disabled or never triggered in the bare-metal `ocamlrun`; if not, compaction is a third move with its own law].

Representation predicates are Kripke-monotone. Each loc is relocated at most once in its lifetime, so no groupoid, inverse or quotient is needed.

**Core rules:**
- **K1 (alloc monotonicity; L4 heap-append plus freshness):** `Repr W s m → Repr (W.alloc ℓ a) (s.alloc b) (m.write a blk)`, provided `a` is fresh-young. The freshness premise also preserves idea B's `NoYoungAlias`, because the young *range* is fixed and raw words are already outside it.
- **K2 (promotion; L3 specialised):** `Repr W s m → RememberedComplete W m → Disjoint targets → Repr (W.promote r) s (gcAction r W.refTable m)`. `gcAction` rewrites only roots ∪ refTable slots ∪ promoted copies, which is the collector's real traversal. The disjointness hypothesis is L3's, and it is now visible in one rule.
- **K3 (write barrier):** `SETFIELD` / `caml_modify` into an old block storing a young pointer preserves `RememberedComplete` iff the slot is added to `refTable`. This is a per-primitive obligation of the arm proofs, stated once here.
- **K4 (reset):** after promotion `πyoung = ∅` and `refTable = ∅`, so `RememberedComplete` holds trivially. The invariant only has to survive between collections.
- **K5 (composition):** promotions compose trivially, since a promoted loc is old forever. Multiple collections cost nothing, with no groupoid algebra.

**Free, and cost.**
- *Free:* C3 becomes three rules (K1, K2, K3), and each round-1 equivariance engine plugs into K2 unchanged. Placement-existential consumers see only `⊑`-monotone facts: "any fact about old placement persists forever", in the step-indexed-Kripke style.
- *Cost:* `RememberedComplete` must be threaded through every mutating arm (SETFIELD, SETFLOATFIELD, SETVECTITEM, the `caml_modify` primitive). That is the honest price of a generational GC.
- *Cost:* major-heap allocation (large blocks allocated directly old) is a third, K1-like move.

**Distant theories:**
- Kripke semantics with monotone accessibility, and step-indexed Kripke logical relations (Ahmed 2004 [check]; Dreyer et al.).
- Generation scavenging and remembered sets (Ungar 1984 [check]).
- Databases: incremental view maintenance with a delta log (the ref table is the delta; the rewrite is incremental maintenance) (Gupta–Mumick [check]).
- Thermodynamics: an irreversible ratchet. Promotion is entropy-increasing and never undone, which is why no inverse is needed.
