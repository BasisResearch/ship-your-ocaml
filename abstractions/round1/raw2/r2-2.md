## 1. One bridge for every presentation: run relations determined by their constructors (contractive-uniqueness transport)

**Round-1 target: extends the C1 consensus and objects to part of it.** The consensus is R1-1 #1 Orbit Calculus, R1-2 #1 Behaviour extraction, R1-3 #1 Absorbing ℕ-orbits, R1-4 #1 Delay computations, R1-5 #1 Decay Chain and R1-6 #1 Capot.

**Objections:**
- R1-2 #1 and R1-4 #1 are built on Mathlib's `Computation`. R1-2 #1, R1-5 #1 and R1-4 #5 state their closure rule against `ReflTransGen`. Neither exists here, so they would have to be rebuilt.
- R1-3 #1's O4 uses `Nat.find`, which is also Mathlib-side [check]. It is unnecessary: unique halting follows from absorption at `max m n`.
- The bigger objection is migration cost. Every round-1 C1 candidate pays one hand-written bridge per legacy relation: "~10 lines each" (R1-3 #1, R1-5 #1) and "migration bridges" (R1-6 #1). The project has at least four of these relations (machine, VM, the generic model, the OS spec), in cons, snoc and unindexed-closure forms. That is the same duplication rule 3 forbids, moved one level up.

**Idea.** An ℕ-indexed run relation is *uniquely determined by its constructors plus its inversion principle*. The index makes the defining equation contractive, so it has exactly one solution. State that fact once, as a structure, and prove once that anything satisfying it is the graph of the iterate. A legacy relation then enters the theory by supplying its own constructors and a one-line `cases`, with no proof by induction.

```lean
inductive Next (C O : Type) | next (c : C) | done (o : O)

def iter (f : C → Next C O) : Nat → C → Next C O
  | 0,   c => .next c
  | n+1, c => match f c with | .next c' => iter f n c' | .done o => .done o

structure ConsPres (f : C → Next C O) (R : C → Nat → C → Prop) : Prop where
  nil  : ∀ c, R c 0 c
  cons : ∀ {c c' n d}, f c = .next c' → R c' n d → R c (n+1) d
  inv  : ∀ {c n d}, R c n d →
           (n = 0 ∧ c = d) ∨ ∃ n' c', n = n'+1 ∧ f c = .next c' ∧ R c' n' d

structure SnocPres (f) (R) : Prop where
  nil  : ∀ c, R c 0 c
  snoc : ∀ {c n d d'}, R c n d → f d = .next d' → R c (n+1) d'
  inv  : ∀ {c n d}, R c n d →
           (n = 0 ∧ c = d) ∨ ∃ n' e, n = n'+1 ∧ R c n' e ∧ f e = .next d

structure ClosPres (f) (R : C → C → Prop) : Prop where   -- no index: needs the recursor
  refl : ∀ c, R c c
  head : ∀ {c c' d}, f c = .next c' → R c' d → R c d
  ind  : ∀ (M : C → C → Prop), (∀ c, M c c) →
           (∀ {c c' d}, f c = .next c' → R c' d → M c' d → M c d) → ∀ {c d}, R c d → M c d
```

**Core rules (proved once, generic in `f`; about 120 lines, Lean core only):**
- **U1 (L1 as a theorem about every presentation).** `ConsPres f R → (R c n d ↔ iter f n c = .next d)`, by induction on `n` using `inv`. The same holds for `SnocPres`, using the shift law U2.
- **U2 (shift).** `iter f (m+n) c = (iter f m c).bind (iter f n)`, where `bind` absorbs on `done`.
- **U3 (closure).** `ClosPres f R → (R c d ↔ ∃ n, iter f n c = .next d)`. This replaces the missing `ReflTransGen` theorem, and any closure-shaped relation qualifies.
- **U4 (absorb and unique, with no `Nat.find`).** If `iter f m c = .done o` and `iter f n c = .done o'`, then `o = o'`. Proof: rewrite both at `max m n`.
- **U5 (outcome-partitioned trichotomy).** For any `Bad : O → Prop`:
  `(∀ n o, iter f n c = .done o → ¬Bad o) → ((∀ n, ∃ d, iter f n c = .next d) ↔ ¬∃ n o, iter f n c = .done o)`.
  H3 and H4 are the *same* theorem, and "sticks" is a choice of `Bad`.
- **U6 (transport along a square with a lossy outcome map).** Given `e : C → D`, `g : O → O'` and `fD (e c) = (fC c).map e g`, we get `iter fD n (e c) = (iter fC n c).map e g`. `BcModel` collapses `Unsupported` and `Wrong` into `stuck` (non-injective `g`) [check]. So consequences that need the outcome partition must be proved before transport.

**Free, and what it costs.**
- *Free:* all 31 C1 members and every future relation. Each legacy relation now costs about one line: `⟨R.refl, R.step, fun h => by cases h <;> simp_all⟩`, not about 10 lines of induction. Presentations are data, so the discipline gate can require that every new run relation arrive as `ConsPres`, `SnocPres` or `ClosPres` (a TSV rule).
- *Cost:* `inv` must be derivable by `cases`, which is true for ordinary inductive families. A relation with extra indices or side conditions needs its own presentation shape, costing one more uniqueness proof per *shape* (not per relation).

**Distant theories:**
- Banach's fixed-point theorem and guarded recursion: the ℕ index is a "later" modality, the defining operator is contractive, and so its fixed point is unique (Nakano 2000; Birkedal et al., the topos of trees, LMCS 2012 [check]).
- Initial-algebra semantics (Goguen, Thatcher, Wagner and Wright, the ADJ group [check]) and Lambek's lemma: constructors plus inversion characterise the object up to iso.
- Databases: a recursive view with bounded recursion depth has a unique model, independent of how it is written (stratified or bounded Datalog [check]).

**Clusters:** C1 fully. It also covers C2 runners written as `iter`.

**Pilot.**
- **H1:**
  `theorem H1 (M : MachineModel) {s} {n m c c' o o'} (h : iterM M n s = .done (c,o)) (h' : iterM M m s = .done (c',o')) : c = c' ∧ o = o'`
  This is `U4` plus `Prod.ext`. About 2 lines.
- **H2:** `(M.reachesPres).U3` followed by `ConsPres.U1` under `∃ n`. About 2 lines.
- **H3 needs a concrete counterexample.** As phrased, with "never-wrong" excluding only `Wrong`, H3 is *false*: a one-instruction program whose first opcode is an unimplemented primitive reaches `Unsupported`. It never goes wrong, does not diverge, and does not halt.
  - `theorem H3_false : ∃ P s, neverWrong P s ∧ ¬(diverges P s ↔ ¬halts P s) := ⟨unsupProg, s₀, by decide, by decide⟩` (kernel `decide` on a 1-step `iter`).
  - The true H3 is `U5` with `Bad := (· ∈ {Wrong, Unsupported})`. About 3 lines.

- **H5–H9:** not targeted.
- **Refactor, VM run-determinism block:** `BcSem.StepsN` gets `ConsPres` in one line. Determinism is `U1` plus `Next.next.inj`, and the halting variants are `U4`. The block becomes about 5 lines.

## 2. The no-confusion square: sort-driven relocation and bit-driven relocation must be proved to coincide

**Round-1 target: an objection to every C3 candidate, plus a fix.** The candidates are:
- R1-1 #2 Relocation Equivariance;
- R1-2 #2 layout language and R1-2 #5 Rendering naturality;
- R1-3 #2 Equivariant predicates ("the encoding is typed, so no raw word is ever mis-rewritten");
- R1-4 #2 Placement parametricity;
- R1-5 #2 Pseudomorph and R1-5 #5 Placement Quotient;
- R1-6 #2 Aureola (`Word'` typing) and R1-6 #5 Keratectomy ("also covers words the VM did not produce").

R1-2 #2 flagged the risk. I make it the central obligation.

**The objection.** Every one of these proves invariance under `ρ♯_sort`, a relocation that rewrites a word because its *VM value* is `ptr`. Each then isolates one collector obligation, "the GC computes `ρ♯`": R-GC-is-ρ in R1-5 #2, R-GC-spec in R1-2 #5, G3 in R1-3 #5, and `reloc` in R1-6 #2.

The OCaml minor collector decides by bits: a word is rewritten iff it is a block (even) and `Is_young`. That obligation is **false** in any state where a scanned position holds a non-`ptr` VM value whose bit pattern is an even word inside the young range. The round-2 fact that the VM never treats `raw` as a pointer makes this possible, not impossible: nothing in `BcSem` stops a `raw w` with young-looking `w` from sitting in the accumulator or on the stack.

L3's 20,000 random heaps apply the *sort-driven* relocation to both sides. The check therefore validated the law the proofs use, not the law the collector delivers.

**Idea.** Split L3 into two proved laws joined by one named invariant:
- **L3_sort:** round 1's equivariance, any of the variants.
- **NoConfusion:** on scanned positions, sort and bit classification agree.
- **NC1:** under NoConfusion, `ρ♯_bits = ρ♯_sort`.

NoConfusion becomes a component of the loop-head relation. It is preserved by every VM step (a local check, by L4) and re-established trivially after a minor GC, because the young generation is then empty.

**Core rules:**
- **NC0 (definitions).**
  - `scanned m a`: the position is a root (register, stack slot) or a field of a block whose tag is below `No_scan_tag`.
  - `youngBits Y w := w % 2 = 0 ∧ Y.lo ≤ w < Y.hi`.
  - `structure NoConfusion (π) (Y) (s) (m) : Prop where coh : ∀ a v, scanned m a → holds π s a v → (youngBits Y (m a) ↔ ∃ ℓ k, v = .ptr ℓ k ∧ young ℓ)`. It is a named-field structure, following rule R6.
- **NC1 (the square; this is the bridge from L3_sort to what the GC does).** `NoConfusion π Y s m → ∀ a, scanned m a → relocBits r Y m a = relocSort r π s m a`. On no-scan positions both copy. Proved once, pointwise.
- **NC2 (the atom table, one fact per `Val` constructor).** Each is a single `decide` over `OCaml/Vm/Layout.lean` constants:
  - `int n`: `2n+1` is odd.
  - `code pc`: the text segment is disjoint from `[Y.lo, Y.hi)`.
  - `atom t`: the static atom table is outside the young range [check: static atoms in 4.14].
  - Closure info words (`Closinfo`) are odd-tagged in 4.14 [check].
  - The trap-frame link is stored as a tagged offset, not an address [check for 4.14].
  - `raw w`: the only non-trivial case. It becomes a named premise `RawDiscipline`: every `raw` either lives only in no-scan positions or has a non-young bit pattern. That premise has to be supplied by a census of the opcodes that produce `raw`.
- **NC3 (preservation is local).** By L4, a step writes only its footprint. So `NoConfusion` before the step, plus NC2 for the values written, gives `NoConfusion` after it. The proof is one per *written value sort*, not per opcode.
- **NC4 (reset by GC).** After a minor GC, `Y` is empty (the nursery is reset), so `youngBits Y' w` is false and `coh` reduces to "no scanned `ptr` targets a young ℓ", which is exactly promotion.

**Free, and what it costs.**
- *Free:* round 1's C3 machinery becomes *correct* for the actual collector, at the price of one square. Adding a new object kind costs one NC2 row.
- *Cost:* `RawDiscipline` is a genuine modelling obligation, and it may fail. If some arm puts an arbitrary `raw` word in a scanned slot, the project has found a real soundness gap in the Layer A statement, which rule 4 says to return as the machine-checked obstruction.
- *Recommended law recheck:* rerun L3's random-heap harness with `raw` words injected into scanned positions and relocation computed by bits. Expect counterexamples exactly when `raw` is young-looking, and 0 under `NoConfusion`.

**Distant theories:**
- Algebraic specification's "no junk, no confusion" (Burstall and Goguen [check]): the initial model identifies nothing extra. Here, no non-pointer is confused with a pointer.
- Conservative versus precise collection (Boehm and Weiser 1988 [check]). A precise collector is sound only when the mutator keeps the tag discipline, and NoConfusion is that discipline stated.
- Tagged hardware (CHERI capability tags, LISP-machine tag bits [check]): precision comes from a tag that the ALU cannot forge. Here the tag is the low bit plus the address range, and NC2 is the "cannot forge" table.
- Databases: typed foreign keys versus magic numbers. A column is a reference by schema, not by value, and the square is referential integrity checked by value.

**Clusters:** C3 (both the proof side and the use side), with NC3 feeding C4's invariants.

**Pilot.**
- **H5.** Two statements:
  - `theorem H5_sort_to_bits (h : NoConfusion π Y s m) (hs : scanned m a) (he : encodes π v (m a)) : encodes (r ∘ π) v (relocBits r Y m a) := (NC1 h hs) ▸ L3_sort.value he`
  - `theorem H5_bits_false : ¬ ∀ r Y m a v, encodes π v (m a) → encodes (r∘π) v (relocBits r Y m a) := ⟨_, _, toyMem, 0, .raw youngAddr, …⟩`. This is a `decide` counterexample on an 8-word toy memory.
- **H6.** For no-scan kinds (string, double, custom or channel), both relocations copy, so NoConfusion is vacuous and the lemma is 1 line. For scanned kinds (plain blocks, closures), use the NC2 rows for the header, the closure-info word and the code pointer, then NC1.
- **H7.** The stack holds return addresses (`code`), `extra_args` (ints), `env` pointers and trap frames. The proof is NC2 row by row, then NC1, then round 1's stack case.
- **H1–H4, H8, H9:** not targeted.
- **Three refactors:** not applicable, since all three are C1.

## 3. Effect-operation footprints: L4 proved per state *operation* (about 15), not per *opcode* (about 150), via two handlers of one free-monad step

**Round-1 target: an objection to the cost structure of all the C4 locality candidates, and a combination of two of them.**
- The locality candidates are R1-1 #3 Footprint Lenses, R1-2 #3 (R-Local "by a single `cases`"), R1-3 #3 P2 ("one large opcode-by-opcode proof"), R1-4 #3 ("should fall to `cases op <;> rfl` **[risk]**"), R1-5 #3 R-Stencil sweep, and R1-1 #5 N1 (refactor `step` to be polymorphic over a `ValueDomain`).
- Each pays roughly 150 opcode arms for L4. Each also hits *dynamic* footprints (GETFIELD reads a field chosen by the accumulator; APPTERM n; RETURN driven by `extra`), which it patches with "dependent lenses" (R1-1 #3) or a "two-phase stencil" (R1-5 #3).
- R1-6 #3's membrane avoids the sweep by kernel reduction, but it gets stuck on symbolic heaps: after `alloc`, `(E.heap ++ [b]).get? E.heap.length` does not reduce by `rfl`.
- The combination: R1-1 #5's naturality with R1-3 #3's algebraic-state view, but with *handlers* rather than patch normalisation.

**Idea.** Rewrite `stepI` (the `BcSem` step body) once, as a program in a free monad over a small signature of state operations:
- `getPc | setPc | getAccu | setAccu | peek i | push v | pop k`
- `getEnv | setEnv | getExtra | setExtra | getTrap | setTrap`
- `readField ℓ i | writeField ℓ i v | alloc blk | worldOp prim args`
- `fail (wrong | unsupported) | halt code`

`BcSem.step p s := Conc.run (stepProg p) s`. The footprint of a step is *the trace of operations it performed*: exact, and data-dependent by construction. Locality is then a theorem about the handler, proved by induction on the free-monad term with one case per operation. A second handler, `Sym`, runs the same `stepProg` on templates with free variables (`?σ` for the stack tail, `?E` for the rest). Its naturality square is also proved per operation, not per opcode.

```lean
inductive Op | getAccu | setAccu (v : Val) | peek (i : Nat) | push (v : Val) | pop (k : Nat)
             | readField (ℓ : Loc) (i : Nat) | alloc (b : Obj) | ...
def Resp : Op → Type | .getAccu => Val | .peek _ => Val | .readField _ _ => Val | .alloc _ => Loc | _ => Unit
inductive FreeM (α : Type) | ret (a : α) | op (o : Op) (k : Resp o → FreeM α)
def Conc.run : FreeM α → St → Next St R × Trace
```

**Core rules:**
- **E1 (L4 as a handler theorem).** `agree (trace (Conc.run e s)) s s' → outside (writes (trace …)) (Conc.run e s) (Conc.run e s') ∧ Conc.run e s ≈_{W} Conc.run e s'`. Proved by induction on `e`, about 15 operation cases. Opcode count is irrelevant.
- **E2 (naturality, R1-1 #5's N1 made cheap).** `Sym.run e t = .next t' → ∀ σ, Conc.run e ⟦t⟧σ = .next ⟦t'⟧σ`. It is also per operation. The `alloc` case returns the symbolic location `|?h| + k`, and `readField` on a fresh location resolves by an operation-level lemma, not by `rfl` on `List.get?` (this fixes the membrane's stuck case).
- **E3 (append-only heap).** It is an `alloc`-case lemma: `readField ℓ i` with `ℓ < |heap|` commutes with `alloc`.
- **E4 (checker soundness, C2).** `runbc`'s executor is `Conc.run` iterated, so it is sound by `rfl`.
- The `Fragment.lean` ledger and the difftest route are unchanged. Transcribing an `interp.c` arm now means writing a `do` block over `Op`.

**Free, and what it costs.**
- *Free:*
  - L4, for every present and future opcode, at no per-opcode cost.
  - Dynamic footprints, with no dependent lenses.
  - Symbolic "from ANY state" execution: `Sym` evaluates by `rfl`, and E2 lifts the result.
  - Frame reasoning: the complement of the trace.
- *Cost:*
  - Redefining `stepI` in `do`-notation over `Op`. It is behaviour-preserving, is revalidated by the existing `runbc` difftests, and needs no 150-arm equation if the free-monad form becomes *the* definition.
  - If instead the old `step` is kept, the bridge `step = Conc.run ∘ stepProg` is `cases op <;> rfl`. That carries R1-4's risk, now bounded because `Conc` is a plain state-passing interpreter.
  - Kernel reduction of `FreeM` binds on long runs needs `@[reducible]` care, and `Resp` must stay a closed `match`.
- *Lean without Mathlib:* the definitions above are core Lean; nothing is imported.

**Distant theories:**
- Algebraic effects and handlers (Plotkin and Power 2002; Plotkin and Pretnar 2009 [check]): one program, many interpretations.
- Optimistic concurrency control (Kung and Robinson 1981 [check]): a transaction's result is determined by its *read set*, and validation is checking that the read set is unchanged. E1 is that validation rule.
- Dynamic information-flow control and taint tracking (Austin and Flanagan [check]): the trace is a dynamic label, which is why data-dependent footprints come for free.

**Clusters:** C4 (straight-line code and framing), C2 (E4), and C3 (E1 tells the GC proof which fields a step can touch).

**Pilot.**
- **H8:**
  `theorem H8 (P) (hP : P.code = h8) (s : St) (h0 : s.pc = 0) : iter (BcSem.step P) 4 s = .next { s with pc := pcSTOP, accu := .int 42 }`
  - Proof: `E2.lift (t := tmpl0) (by rfl)`, where `tmpl0 := ⟨0, ?accu, ?σ, ?E⟩`.

- **H1–H7:** not targeted, except that E1 is what idea 5's G4 consumes.
- **Refactors:** the VM run-determinism block is unaffected, since `step` is still a function. The generic-model conversion is unaffected. Honestly, none of the three.

## 4. Application summaries: ZINC-aware, frame-polymorphic function specs (push/enter calls as a first-class rule)

**Round-1 target:**
- *Extends* R1-4 #4 Poincaré sections, R1-2 #4 ranked circularity and R1-6 #3 membrane.
- *Objects to* R1-4 #4's functoriality rule ("a call site is a nested section whose return is replaced by the callee's f").
- *Objects to* R1-1 #4 GKAT.

**Objections:**
- **GKAT (R1-1 #4).** Bytecode from a functional compiler moves control mostly by `APPLY`, `APPTERM`, `RETURN`, `RAISE` and `GRAB`/`RESTART`, which are computed transfers. GKAT's "escape hatch" would carry most of the 412k instructions. GKAT is also partial-correctness, and its decision procedure is a tool that can only check laws.
- **Poincaré return (R1-4 #4).** In ZINC, `RETURN n` pops `n` slots and then:
  - *if* `extra_args > 0`, it decrements the count and **re-applies the result** in the accumulator (`pc := Code_val(accu)`, `env := accu`);
  - otherwise it pops the return frame.
  `GRAB k` at entry builds a partial application (`RESTART`) when `extra_args < k` and returns at once [check exact 4.14 arms].

  So a callee's exit, and even its entry behaviour, depends on the *caller's* `extra_args`. A section that treats a call as "return to the next cut point" is unsound for over- and under-application. None of round 1's loop and modularity candidates (R1-4 #4, R1-2 #4, R1-6 #4) models this.

**Idea.** The unit of C4 specification at compiler scale is not a loop and not a block. It is an **application summary**: a closure `f` applied to exactly `k` arguments *in any caller frame* returns to the pushed return address with the frame restored and `Φ args r`. Over-application, under-application and tail calls are three generic theorems derived once from the push/enter semantics. Callers never step through callees. Callees never see their callers' frames, because the frame below the return frame is a free variable (R1-6 #3's membrane, justified by L4 or by idea 3's E1).

```lean
structure AppSpec (P : Prog) (f : Val) (k : Nat) (Φ : List Val → Heap → Val → Prop) : Prop where
  run : ∀ (args σ : List Val) (s : St) (ret : Nat) (env extra : Val),
    args.length = k → s.accu = f → s.extra = .int (k-1) →
    s.stack = args ++ [.code ret, env, extra] ++ σ → s.pc = entryPc f →
    ∃ n s', iter (BcSem.step P) n s = .next s' ∧
      s'.pc = ret ∧ s'.stack = σ ∧ s'.env = env ∧ s'.extra = extra ∧ Φ args s'.heap s'.accu
```

(The return-frame layout for `APPLY1..3` versus `PUSH_RETADDR; APPLY n` needs checking [check]. It is a named-field structure, following rule R6.)

**Core rules (each proved once, from `BcSem`'s push/enter arms and idea 1's U2):**
- **A1 (call, L4 as the frame rule).** `AppSpec f k Φ` implies that from *any* state executing `PUSH_RETADDR L; <k pushes>; APPLY k`, the run reaches `L` with the caller's stack, `env` and `extra` restored, plus `Φ`. Frame polymorphism in `σ` is exactly L4.
- **A2 (over-application).** From `AppSpec f k Φ` and `∀ r, Φ as h r → AppSpec r j Ψ_{as}` we get application of `f` to `k+j` arguments: `RETURN`'s `extra_args > 0` branch, once.
- **A3 (under-application).** For `j < k`, the application returns a partial-application closure `c` with `AppSpec c (k-j) Φ(as ++ ·)`: `GRAB`/`RESTART`, once.
- **A4 (tail call).** `APPTERM` composes summaries without pushing a frame.
- **A5 (recursion by ranked circularity, R1-2 #4).** While proving `AppSpec f k Φ` at arguments of rank `μ`, you may assume `AppSpec f k Φ` restricted to smaller rank at inner call sites. Soundness is well-founded induction plus idea 1's U2.
- **A6 (loops inside a body, R1-4 #4).** Back edges (`BRANCH`, `BRANCHIF`) are Poincaré sections semi-conjugate to a Lean function. A6 is local to the body and never crosses a `RETURN`.

**Free, and what it costs.**
- *Free:*
  - Every call site in the compiler is discharged by A1 with no frame reasoning.
  - Currying (over- and under-application) costs nothing per site.
  - The per-function summary is exactly the unit that Layer C's source-level statement needs (one OCaml function, one `AppSpec`).
- *Cost:*

  - Exceptions (`PUSHTRAP`/`RAISE`) need a second exit in `AppSpec` (normal return | raise to the trap frame below σ). This should be designed in now, as a field `raises : …`, not bolted on later.
  - `Φ` over heaps needs idea 5's closed domains once the callee allocates.

**Distant theories:**
- The eval/apply versus push/enter distinction (Marlow and Peyton Jones, "Making a fast curry", 2004 [check]). ZINC is push/enter, so the arity mismatch is the callee's business, and the summary must say so.
- Interprocedural summaries: Sharir and Pnueli's functional approach (1981 [check]) and RHS tabulation (Reps, Horwitz, Sagiv, POPL 1995 [check]). A summary is the callee's input-output relation, reused at every call site.
- Visibly pushdown languages and nested words (Alur and Madhusudan [check]): matched call/return brackets, with the frame below as the unmatched context.
- Linguistics: categorial grammar's type-raising and partial application. A functor applied to too few arguments yields a functor, which is A3.

**Clusters:** C4 (primary, at the 412k-instruction scale), feeding Layer C.

## 5. Garbage invisibility: representation over reachability-closed partial placements (L3 is not enough, and "GC computes ρ♯" is false as stated)

**Round-1 target: objections to the C3 domain of quantification and to the collector obligation.**
- **Heap domain.** R1-6 #2 Aureola (`Layout := Loc → Option …`, `conc` over all ℓ), R1-1 #2 ("bigStar over the live set"), R1-3 #2 (E5: "the loop-head relation is literally preserved") and R1-5 #5 (`follow` indexed by every loc).
- **Collector obligation.** R1-5 #2 R-GC-is-ρ, R1-2 #5 R-GC-spec, R1-3 #5 G3 and R1-6 #2's `reloc`.
- **Monotone worlds.** R1-6 #3's R-heap-append ("every pre-existing `ptr ℓ k` stays valid (monotone world)").

**Three objections.**
- **(a) The VM heap only appends; the machine frees.** After a minor GC, unreachable young blocks have no address. Once the next allocation reuses the nursery, their contents need not exist anywhere in memory. A representation that places *every* VM heap block is then unsatisfiable, even with placement existential.
  - "Live" in L3 must therefore mean *reachable from the VM roots*.
  - Reachability is a least fixed point over the heap graph. It is *not* expressible in the bounded-∀/∗/∃ grammars of R1-1 #2, R1-3 #2, R1-4 #2 or R1-5 #2, so their "every definable predicate is equivariant" theorem does not cover the set the relocation acts on.
- **(b) The minor GC rewrites only pointers it scans.** Those are the roots, the remembered set (`caml_ref_table`) and promoted copies [check 4.14 names]. An old-to-young pointer missing from the remembered set is not rewritten. So "GC = `ρ♯` (rewrite every pointer word)" holds only under a write-barrier invariant, which is a new C3 component that every field-writing arm (`caml_modify`) must maintain.
- **(c) Worlds shrink.** A pointer into garbage becomes dangling after a collection. Machine-side Kripke monotonicity holds only for *reachable* locations.

**Idea.** Represent the VM state by a **partial** injection `β : Loc ⇀ Addr` whose domain is any set *closed under pointer-following and containing the roots*. It is not required to be the whole VM heap. The GC's effect is then two proved operations: **restrict** to the reachable closure, then **relocate** the young part. L3 (relocation) gets a sibling law L5 (restriction):
- **L5 (garbage invisibility):** forgetting and overwriting unreachable blocks preserves the representation.
- **L4 links the two:** a VM step's footprint lies inside the reachable closure, so steps never notice what was forgotten.

```lean
structure ClosedPlacement (s : St) (m : Mem) : Type where
  β      : Loc → Option Addr
  roots  : ∀ ℓ, rootMentions s ℓ → (β ℓ).isSome
  closed : ∀ ℓ a i ℓ' k, β ℓ = some a → field s ℓ i = .ptr ℓ' k → (β ℓ').isSome
  disj   : PairwiseDisjointRanges β s
  layout : ∀ ℓ a, β ℓ = some a → blockAt m a (s.heap.get! ℓ)     -- per-kind layout, as in round 1
```

**Core rules:**
- **G1 (L3 on the closed domain).** Relocating `dom β` with disjoint targets preserves `ClosedPlacement`. Any round-1 C3 engine works here, since `closed` is stated per field and is itself equivariant.
- **G2 (L5, restriction).** If `D ⊆ dom β` is closed and contains the roots, then `β|D` is a `ClosedPlacement` for every `m'` that agrees with `m` on the ranges of `D`. Proved once, and the closure fields make it immediate.
- **G3 (the collector splits in two).**
  - *Correctness of the Cheney scan:* the promoted set is the least closed set containing the roots and the remembered set, a Datalog-style lfp fact about the scan loop.
  - *Relocation:* G1.
  - The invariant `RefTableComplete := ∀ old field holding a young ptr, its address ∈ ref_table` is the *named premise* that makes the scan's closed set contain every old-to-young edge. Its preservation is the `caml_modify` arm's obligation in Layer A.
- **G4 (steps respect garbage; L4 ∘ closure).** A step reads `field ℓ i` only if some `ptr ℓ _` is in its read footprint. The footprint starts at the roots, so every block read lies in `dom β` by `closed`. Stepping preserves `ClosedPlacement`, extending `β` at `alloc`. The proof is one case per *heap operation*, using idea 3's E1.
- **G5 (Kripke monotonicity, relativised).** Facts about reachable locations persist across GC. Facts about arbitrary `ptr ℓ k` do not, and the rule says so.

**Free, and what it costs.**
- *Free:*
  - The representation survives collections that actually free memory.
  - The write barrier appears as exactly one named invariant instead of hiding inside "GC = ρ♯".
  - C4 specs over heaps (idea 4's `Φ`) quantify only over reachable data, which is what callers can observe.
- *Cost:*
  - `closed` makes representation predicates non-local (a graph condition), so equivariance needs the one extra connective "closure under a relation" in whichever round-1 grammar is adopted. It is equivariant because relocation acts on locations bijectively.
  - The Cheney-scan lfp proof is real (Layer A).
  - Remembered-set maintenance is a new Layer A obligation for every mutation arm.
- *Recommended law check:* extend L3's harness with unreachable young blocks and nursery reuse. Predict counterexamples for total-placement statements, and 0 for `ClosedPlacement`.

**Distant theories:**
- Bisimulation and partial bijections in verified collectors: the CakeML generational GC (Ericsson, Myreen and Åman Pohjola, ITP 2017 [check]) and McCreight, Shao, Lin and Li, "A general framework for certifying garbage collectors" (PLDI 2007 [check]).
- Separation logic for space under GC, with ghost reasoning about unreachable locations (Moine, Charguéraud and Pottier, POPL 2023 [check]).
- Databases: the remembered set is a *materialised view* of `{old field ↦ young ptr}` that `caml_modify` maintains incrementally. `RefTableComplete` is view consistency, as in incremental view maintenance. Reachability is the recursive Datalog view over the heap graph.
- Cosmology: the observable universe. Regions outside the causal horizon of the roots can be dropped without any observable change, which is G2 plus G4.

**Clusters:** C3 (the domain of quantification and the collector obligation), with C4 via G4 and G5.

**Pilot.**
- **H5:** unchanged from any round-1 engine (G1 on one word), but stated with `β ℓ = some a` hypotheses.
- **H6.** Stated for `ℓ ∈ dom β`. Also a counterexample:
  `theorem total_placement_false : ∃ s m m', GCthenAlloc m = m' ∧ Repr_total s m ∧ ¬Repr_total s m'`
  This is `decide` on a toy two-block heap (block 0 unreachable and young, block 1 reachable), with a GC followed by one allocation that reuses the nursery.
- **H7:** the stack is a root region, so G1 applies with β fixed there. The `roots` field makes every stack `ptr` land in `dom β`.
- **H1–H4, H8, H9:** not targeted. H8 and H9 allocate nothing, and idea 4's heap-valued `Φ` would use G5.
- **Three refactors:** none. All three are C1.
