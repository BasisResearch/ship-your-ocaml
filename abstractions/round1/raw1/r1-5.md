## 1. Decay Chain: runs as the orbit of one total function

**Words that drove it:** *radiothorium* (a decay chain: a deterministic sequence that stops at a stable isotope), *resultless* (divergence), *irremovableness* (the orbit is fixed once the start is fixed), *Taygeta* (a single star's path).

**The idea.** Stop writing inductive n-step relations. For any deterministic `step : σ → Next σ | Stop r | Stuck e`, define once the **orbit** `orb s : ℕ → Phase σ ρ ε`, where `orb s 0 = live s` and `orb s (n+1) = bind (orb s n) step`. Stopped and stuck phases are absorbing. Every run notion becomes a statement about points of this one function:
- `s ⟶[n] t :≡ orb s n = live t`
- `halts s r :≡ ∃ n, orb s n = stop r`
- `diverges s :≡ ∀ n, (orb s n).isLive`

Every step relation in the project (machine, VM, generic machine model, OS spec) is packaged once as an instance of a class `Chain σ ρ ε` that has a `step` field. All C1 facts become theorems about `orb`, proved once, and the project stops restating them per relation.

**Core rules (proved once, generic in `Chain`):**
1. **R-Graph (L1):** `s ⟶[n] t ↔ iter step n s = live t`. Here L1 is the definition itself plus one `rfl`-level lemma relating the orbit to the fuel-bounded iterate.
2. **R-Shift:** `orb s (m+n) = (orb s m).bind (fun t => orb t n)`. This is the flow (semigroup) law and it gives prefix, append and snoc. It is proved by induction on `m`, once.
3. **R-Absorb:** `orb s n = stop r → ∀ k ≥ n, orb s k = stop r`, and the same for `stuck`.
4. **R-Unique:** `orb s n = stop r → orb s m = stop r' → r = r'`. This follows from Absorb plus the total order on ℕ (compare `m` and `n`).
5. **R-Trichotomy:** `halts s ∨ sticks s ∨ diverges s`, exclusively. It is proved by classical case analysis on `∃ n, ¬(orb s n).isLive` and `Nat.find`.
6. **R-Closure:** every closure-style relation (reflexive-transitive closure, `Relation.ReflTransGen`, the Iris-layer "reaches") is proved `↔ ∃ n, s ⟶[n] t` once, for `Chain`-induced relations.
7. **R-Transport:** a morphism of chains `f : σ → τ` with `step_τ (f s) = map f (step_σ s)` satisfies `orb (f s) = map f ∘ orb s`. This is used for the relation-to-relation conversions.

**What it makes free.** All of C1: 31 members at 8.6 lines each, roughly 270 lines, become instance declarations plus one-line `Chain.*` applications. New step relations get the whole run algebra for free. Divergence and halting are observations of one function, so there is no coinduction anywhere.

**What it costs.** Each step relation has to be restated as, or proved equal to, `orb` of a `Chain` instance. If the existing relations are inductive, each needs a bridging `↔` proof. With R-Graph this is about 10 lines per relation, only 4 times. `Phase` needs a `bind`/`map` API and roughly 15 simp lemmas.

**Theories from distant fields:**
- Symbolic dynamics and discrete dynamical systems: the orbit of a map, the shift/flow law `φ^{m+n} = φ^m ∘ φ^n`, absorbing fixed points.
- Radioactive decay chains and Markov chains with absorbing states: an absorbing state is unique along a deterministic chain, and absorption time is a stopping time (the `Nat.find` witness).
- Capretta's delay monad (2005). `orb` is its fuel-indexed observation, and R-Trichotomy is the classical collapse of the delay monad. *Check the citation.*

**Target:** C1 primarily; C2 through rule 6.

**Pilot:**
- **H1:** `Chain.stop_unique` applied to the machine-model instance, one line.
- **H2:** `Chain.reaches_iff_exists_n`, which is R-Closure, one line.
- **H3:** the hypothesis `never-wrong` says `∀ n, orb s n ≠ stuck`. R-Trichotomy then gives `diverges ↔ ¬halts`. About 3 lines.
- **H4:** the same proof, instantiated at the machine chain.
- **H5–H8:** not targeted.
- **H9:** only via R-Shift, which composes loop iterations as `orb s (k·c + r)`.
- **Refactor, VM run-determinism block:** delete it and replace it with `instance : Chain St …` plus the aliases `Chain.stop_unique`, `Chain.run_det` and `Chain.shift`.
- **Refactor, machine run-composition lemmas:** each becomes a rewrite by R-Shift.
- **Refactor, generic-model reachability ↔ VM n-step:** R-Closure on both sides, then R-Transport along the embedding of the VM chain into the machine-model presentation.

## 2. Pseudomorph Logic: representation formulas that cannot see addresses

**Words that drove it:** *natrojarosite* (a mineral that forms pseudomorphs, which replace a crystal and keep its external form; the pseudomorph idea is my association, so check the mineralogy), *placoidean* (placoid scales: rigid tiles that move as wholes), *sculptograph*, *nonpuncturable* (a block is never split), *irremovableness*.

**The idea.** Do not prove relocation invariance ~40 times for ~40 components. Write the representation in a small **deeply embedded assertion language** whose only address-touching atoms are relative to a block base. Then prove *one* equivariance theorem by induction on the syntax.

Formulas are written in `PForm`:
- `word (b : BlockVar) (k : ℕ) ≐ t`, where terms `t` are an encoded value, a literal, or `ptr b' k'` (meaning the word `base b' + 8k'`)
- `blockSpan b len`
- `disjoint b₁ b₂`
- `∧`, `∨`, `∀/∃` over values
- iterated `⋀ i < n` over fields and stack slots
- `≐` on non-pointer words

There is no raw-address atom. The denotation `⟦φ⟧ (base : BlockVar → Addr) (mem : Addr → Word)` is interpreted over a placement.

**Core rules:**
1. **R-Pseudomorph (L3, the master theorem):** let `ρ` be a block relocation, meaning each live block is moved as a whole range and the target ranges are pairwise disjoint (`ρ.disj`). Let `ρ♯ mem` rewrite pointer words through `ρ` and copy everything else. Then `⟦φ⟧ base mem ↔ ⟦φ⟧ (ρ ∘ base) (ρ♯ mem)`, for every `φ : PForm`. The proof is by structural induction. The only real cases are `word` atoms: they use `ρ.disj` to show the relocated word lands in the target range uniquely, and injectivity to invert pointer rewriting.
2. **R-Necessity (as a documentation lemma):** a counterexample to R-Pseudomorph without `ρ.disj`. This makes the brief's 12,358 counterexamples a proved fact and keeps the hypothesis from being "simplified away".
3. **R-Reflect:** `⟦quote P⟧ = P` for each shallow representation predicate `P`. Each component (value encoding, the 8 object kinds, the stack region, channels) is written *once* as a `PForm` and reflected back. After that, invariance for it is `R-Pseudomorph (quote P)`.
4. **R-Exists:** because placement is existential, the full loop-head relation `∃ base, ⟦Φ⟧ base mem` is invariant under `ρ♯`. Take the witness `ρ ∘ base`.
5. **R-GC-is-ρ:** the only fact to prove about the collector: its effect on memory is `ρ♯` for some `ρ` satisfying `ρ.disj` and mapping live young blocks. This is the single place where GC code meets the logic.

**What it makes free.** All of C3. About 40 invariance lemmas become one induction, about 150 lines, plus about 40 `quote` definitions, each a transliteration. The loop-head relation's 15 fields come for free if the relation is a `PForm` conjunction. It is also future-proof: a new object kind costs a `PForm` only, never an invariance proof.

**What it costs.**
- The shallow predicates have to be rewritten in (or reflected into) `PForm`. Any predicate that computes an address arithmetically outside `base b + 8k` breaks the language. That restriction is exactly the discipline you want, but migration can surface hidden raw-address uses.
- The `iterate` combinator (fields, stack slots) needs care in the equivariance proof.
- Decidability or `simp` normalisation of `⟦·⟧` has to be good enough for R-Reflect to be `rfl`/`simp`.

**Theories from distant fields:**
- Tarski's (1966/86) characterisation of logical notions as those invariant under all permutations of the domain, and the Erlangen program (Klein): a geometry is its invariants under a transformation group. Here the group is block relocations, and the language is designed so that every definable property is invariant. *Check the Tarski date.*
- Nominal sets (Pitts, Gabbay): equivariance holds by construction for anything built from equivariant pieces.
- CompCert memory injections (Leroy and Blazy): relocation as injection `b ↦ (b', δ)`. The `ρ.disj` condition is their no-overlap condition. *Check the attribution.*
- Crystallography and mineralogy: pseudomorphic replacement, where content is swapped and form is preserved.

**Target:** C3.

**Pilot:**
- **H5 (value encoding):** `quote encWord` is `word b k ≐ enc v`, where a pointer value `ptr loc off` becomes `ptr loc off`. Then apply R-Pseudomorph. Around 3 lines after the master theorem.
- **H6 (object layout):** `quote objLayout(kind)` is `blockSpan b (1+n) ∧ word b 0 ≐ hdr ∧ ⋀ i<n, word b (i+1) ≐ fieldTerm i`. Then apply R-Pseudomorph.
- **H7 (stack region):** the stack is a distinguished `BlockVar` (a pseudo-block that the collector's `ρ` fixes, or moves as a whole), and `⋀ i < len, word stk i ≐ enc (stack[i])`. Then apply R-Pseudomorph.
- **H1–H4, H8, H9:** out of scope.
- **Refactors:** none of the three refactor targets is C3, so none applies. Instead, note that the loop-head relation's 15 fields become one `PForm` conjunction.

## 3. Stencil Ceremony: VM instructions as light cones, specs by evaluation

**Words that drove it:** *ceremonialism* (a fixed ritual with a small cast), *ventroaxillary* (a precise body locus), *kinetoplast* (DNA held outside the nucleus: the untouched remainder of the state), *trippingly* (steps run lightly and mechanically), *cathro*.

**The idea.** Treat the VM state as an **addressable cell structure**: cells are `pc | accu | env | extra | trap | slot i` (the i-th stack slot from the top) `| field ℓ j | world | heapLen`. Treat each instruction as a **stencil**: a finite read set `R`, a finite write set `W`, and a function on those cells alone. L4 becomes a theorem: `step` factors through its stencil. Specifications are then written as **cell-level assertions** with a symbolic, universally quantified *rest* (the untouched stack tail and heap). Symbolic execution is `simp`/`decide` evaluation of the stencil on symbolic cells, not on per-instruction lemmas. The rest travels through unchanged, by the frame rule proved from locality.

**Core rules:**
1. **R-Stencil (L4):** for every instruction `ι`, `step p s = patch s (W ι) (f ι (read s (R ι s)))`. Here `R` may depend on the pc and the decoded instruction only, not on the rest. This is proved by one `cases ι` sweep over the instruction set. The sweep is generic and mechanical, *not* per-site, and is written once for the ISA.
2. **R-Frame:** if `s ≈_{R} s'` (they agree on the read set) then `step s` and `step s'` agree on `W` and each preserves its own complement. As a corollary, any property of cells outside `W` survives.
3. **R-StackFrame (specialisation):** writing `stack = top ++ rest`, where `|top| ≥ depth ι`, `step` acts on `top` and leaves `rest` untouched and *uninspected*. So a spec quantifies over `rest` and every other field of `St`.
4. **R-Compose:** stencils compose into a segment stencil with `R = R₁ ∪ (R₂ ∖ W₁)` and `W = W₁ ∪ W₂`. A straight-line segment gets its footprint by computation, and its effect is the composite function. Combined with R-Shift from candidate 1 (or any run algebra), a k-instruction straight segment is one evaluated function.
5. **R-Loop:** a loop is a stencil fixpoint. With an invariant `I` over the footprint cells and a measure over them, R-Frame lifts `I ∧ rest-unchanged` across iterations.

**What it makes free.** In C4, straight-line segments cost nothing: their spec is `by stencil_eval`, a tactic that unfolds R-Stencil and computes. Frame reasoning is never manual. For the 412k-instruction compiler, footprints of basic blocks can be computed and cached as data, so specs of large regions are compositions of cached stencils, and only loops and calls need invariants.

**What it costs.**
- The R-Stencil sweep over the whole ISA is a large one-time proof (every opcode). If the step function is written with helper functions that touch whole records, the factorisation has to be proved against them.
- Instructions whose read set depends on data (for example, reading the field of a pointer found in the accumulator) need *dynamic footprints*: `R` depends on the values read in phase 1. That is still fine, but the stencil becomes two-phase.

**Theories from distant fields:**
- Stencil computations and cellular automata: locality and the light cone. Garland-of-Eden and Hedlund's theorem characterise CA as exactly the continuous shift-commuting maps with finite neighbourhood. *Check the Hedlund attribution.*
- Separation logic's frame rule (Reynolds, O'Hearn), here derived semantically from a locality property rather than built into a logic.
- Special relativity's causal cones, and dataflow analysis (read/write sets as used in compiler dependence analysis, Bernstein's conditions for parallelism). *Recall; check.*

**Target:** C4. It also feeds C3: footprints say which blocks an instruction touches.

**Pilot:**
- **H8:** for an arbitrary `s` with `s.pc = 0` and `rest := s.stack`:
  - `stencil_eval` computes CONSTINT 40 (writes accu), PUSH (stack ← 40 :: rest), CONST2 (accu ← 2), ADDINT (accu ← 40+2, stack ← rest).
  - The final `accu = int 42` and `stack = rest` by `rfl` after `decide` on 63-bit arithmetic.
  - About 5 lines, with no per-instruction lemma.
- **H9:** use R-Loop.
  - Invariant: `top = int i ∧ i ≤ 10 ∧ rest unchanged`.
  - Measure: `10 − i`.
  - The body stencil is evaluated once, symbolically in `i`.
  - The exit branch is evaluated to STOP with accu 10.
  - About 20 lines, needing only arithmetic side goals.
- **H1–H4:** not targeted.
- **Refactor, VM run-determinism:** trivially from `step` being a function. Not this candidate's contribution.

## 4. Manifest: certificate-carrying runs, one validator

**Words that drove it:** *manifest* (a cargo list checked at the dock), *desulphur* (removing impurities from the trusted base), *subjectivistically* (the checker's view versus the relation's), *vinology* (the vintage and provenance record), *rattener*.

**The idea.** C2 grows because each executable runner or checker gets its own soundness proof. Instead, every checker is presented as a **fold over the orbit** that emits a *manifest*: a finite list of observations such as step count, phase, and optional watched cells. One generic, proved **validator** `validate : Chain σ → σ → Manifest → Bool` re-runs the fuel iterate and compares. Soundness and completeness of each checker then reduce to "the checker is a fold of `orb`", which is a structural fact, not a semantic one.

**Core rules:**
1. **R-FoldOrbit:** a checker `c : σ → ℕ → α` is *orbit-shaped* if `c s n = foldl g a₀ (list.map (orb s) (range n))` for some `g`. This is proved per checker by `rfl` or `funext`-level unfolding when the checker is written with a provided combinator `Chain.runFold`.
2. **R-Sound:** `validate s m = true → s ⟶[m.len] m.last`, and halting/stuck claims hold as stated. This is proved once from L1 (R-Graph).
3. **R-Complete:** `s ⟶[n] t → validate s (manifestOf s n) = true`. This is proved once.
4. **R-Monotone fuel:** `runFold` with more fuel extends the manifest. This follows from R-Absorb and gives "checker with fuel k succeeds ⇒ with fuel k' ≥ k succeeds".
5. **R-Simulation-check:** for a relation between two chains (for example VM and machine), a joint manifest of paired checkpoints is validated by checking each segment. Soundness is proved once via R-Transport.

**What it makes free.** C2: the 7 members at 4–20 lines each, and the future ones, become `runFold` instances plus `R-Sound`/`R-Complete` applications. It also gives C4 a cheap testing loop, because concrete runs produce manifests and `decide` on `validate` yields kernel-checked concrete facts (the H8 instance at a specific state).

**What it costs.**
- Existing checkers have to be rewritten through `runFold`. Checkers with clever early exits need `g` to carry a "done" flag.
- Kernel evaluation of `validate` on long runs is slow. It is fine for small programs; for the compiler it needs `native_decide`, which enlarges the trusted base, or chunked manifests.

**Theories from distant fields:**
- Proof-carrying code (Necula and Lee, 1996) and translation validation (Pnueli, Siegel, Singerman, 1998): the untrusted producer ships a certificate, and the trusted checker is small. *Check the years.*
- Logistics and customs: the manifest and bill of lading checked against cargo at the dock. This covers auditing by sampling versus a full re-run.
- Catamorphisms and the universal property of fold (Hutton, 1999): the universal property does the per-checker work. *Check.*

**Target:** C2; secondarily C1 (it relies on candidate 1) and C4 (concrete facts).

**Pilot:**
- **H2:** falls out of R-Sound/R-Complete composed with R-Closure.
- **H8:** a concrete instance only (a specific state) by `decide ∘ validate`. The universally quantified H8 needs candidate 3, which is an honest limit.
- **H9:** each `i ≤ 10` by `decide` over the 11 cases. Because `i` ranges over a finite set, `validate` for each start plus `Fin 11` case-split proves H9 outright. This works if the "any start" also quantifies the rest of the state; otherwise combine with R-StackFrame.
- **H1, H3, H4:** via candidate 1 underneath.
- **Refactor, generic model ↔ VM n-step:** the conversion becomes R-Simulation-check with the trivial one-step pairing.

## 5. Placement Quotient: the heap seen up to relocation, where GC is the identity

**Words that drove it:** *subjectivistically* (what exists depends on the observer), *Taygeta* (a star's apparent position moves while the star stays the same), *irremovableness*, *Ardea* (the heron standing still while the water moves), *hexapetaloid* (a six-fold symmetric form: an object up to symmetry).

**The idea.** Candidate 2 proves invariance. This one makes it *definitional*. Define `MemMod := Mem / ~`, where `m ~ m'` iff `m' = ρ♯ m` for some admissible block relocation `ρ` (disjoint targets, moved as a whole, pointer words rewritten). The representation relation is stated against `MemMod` with a Lean `Quotient.lift`. The machine's collector then *is* the identity on `MemMod` (`⟦gc m⟧ = ⟦m⟧`). Every representation predicate is a function on the quotient, so C3 invariance is the well-definedness obligation of `lift`, discharged **once per primitive observation**, not per component.

The primitive observations are:
- `follow : MemMod → BlockId → Option (List WordOrRef)`: the contents of a block, with pointer words replaced by abstract references (block id, offset).
- the root registers, likewise abstracted.

Everything else (value encoding, the 8 object kinds, the stack region, channels, the 15 loop-head fields) is defined from `follow` and the roots. So no component mentions a concrete address.

**Core rules:**
1. **R-Equiv:** `~` is an equivalence relation. Relocations compose, and composition preserves pairwise disjointness of targets; there is an identity and an inverse. This makes relocations a groupoid and is the one place where disjointness enters (L3's necessity).
2. **R-Follow-WD (L3, core):** `m ~ m' → follow m = follow m'` up to the block-id renaming carried by `ρ`. Block ids are abstract (the VM `loc`), and the placement maps loc to address, so `follow` indexed by `loc` is exactly invariant. This is proved once.
3. **R-Lift:** any predicate defined from `follow` and the roots is automatically a function on `MemMod`. Invariance under relocation is a `Quotient.sound` rewrite.
4. **R-GC:** `gc m ~ m` whenever the collector's effect is an admissible relocation. This is the single collector-facing obligation, as in candidate 2's R-GC-is-ρ.
5. **R-Existential-placement:** the existing "∃ placement" becomes the quotient's representative choice. `repr` of the loop-head relation is `∃ m ∈ class, concrete relation m`, and the quotient removes the ∃ from users' view.

**What it makes free.** C3 entirely, and without a deep embedding: shallow Lean definitions still work, provided they go through `follow`. It also clarifies the machine↔VM simulation, because the VM heap corresponds to `MemMod` (restricted to reachable blocks) and the correspondence is a bijection, not an existential relation.

**What it costs.**
- Working with Lean quotients (`Quotient.lift`, `Quotient.ind`) adds friction in every downstream proof. Computation on `MemMod` is not directly available, so it needs `Quotient.out`, which is noncomputable.
- Components written today with raw address arithmetic have to be re-expressed through `follow`.
- `follow` itself needs the block sizes (headers) to parse memory, so proving R-Follow-WD involves header preservation, which is the one real lemma.
- The design is weaker than candidate 2 if some component really does need addresses (for example the stack region, which the GC may not move and which sits at a fixed address). That case is handled by making the stack a root block with the identity relocation.

**Theories from distant fields:**
- General relativity's gauge invariance and diffeomorphism invariance: only coordinate-free observables are physical. `follow` is the gauge-invariant observable, and a relocation is a gauge transformation.
- Homotopy type theory and the univalence principle (the structure identity principle): isomorphic structures are equal, so every definable property transports. The quotient is a set-level shadow of this.
- Alpha-equivalence of terms with de Bruijn or locally nameless representation: pointers are to abstract references what bound names are to indices.
- Heap isomorphism in GC correctness proofs (for example, McCreight et al.'s GC verification framework, 2007/2010, and graph-isomorphism formulations of copying collectors). *Recalled; check the attribution.*

**Target:** C3; secondarily the machine↔VM relation used in C4.

**Pilot:**
- **H5:** `encWord v` is defined as `match v | ptr loc off => Ref loc off | int n => Lit (2n+1) …`, observed through `follow`. Relocation invariance is `Quotient.sound (R-Equiv…)` plus R-Lift, about 2 lines.
- **H6:** the object layout is `follow m loc = some (hdr :: fields)` with a kind predicate on that list. Invariance comes from R-Follow-WD, 1 line.
- **H7:** the stack is a root block. Relocation fixes it or moves it whole, and `follow m stackRoot` is invariant, 1 line. The one-time cost, R-Follow-WD (with header preservation), is roughly 120 lines.
- **Others:** out of scope.

### Cross-candidate note
Candidates 1+4 (C1/C2) and 3 (C4) compose directly. Candidates 2 and 5 are rival solutions for C3: 2 is a syntactic guarantee via a deep embedding, and 5 is a semantic guarantee via a quotient. A pilot bake-off on H5–H7 should pick one. My prior favours 5 when the existing predicates are already loc-indexed with placement existential, and 2 when they perform raw address arithmetic.
