## 1. Runs as delay computations (a coalgebraic outcome semantics)

**Seed driver:** the repeat with a gap, `FvQ … FvQ`. A run is a stream that eventually becomes periodic; the most extreme case repeats "not yet" forever, which is divergence.

**The idea.** Stop writing facts about n-step relations. Any deterministic step function is packaged once as a `Machine`: a carrier `C`, outcome type `O` and `step : C → Next C O`, where `Next` is `next c | done o`. The VM's `Halt code world`, `Unsupported` and `Wrong` become three `done` outcomes, and the RISC-V `Error` becomes one more. Every machine gets one denotation:

`⟦c⟧ : Delay O`, defined by `Delay O := {f : ℕ → Option O // ∀ n a, f n = some a → f (n+1) = some a}`

This is Mathlib's `Computation` **[check: `Mathlib.Data.Seq.Computation`, which defines `Computation α` as a monotone `Stream' (Option α)` with `mem_unique`, `Terminates`, `think`, `pure`, `corec`, `bind`]**. Every C1 fact becomes a `Computation` lemma plus one bridge law. Configuration-to-configuration reachability is `Machine.iter n c : Option C`, the Kleisli iterate. It is used only through the rules below.

**Core rules (all proved once, for every `Machine`):**
- **R0 (L1, the bridge).** `⟦c⟧.val n = (iterFuel step n c).outcome`, and `c ⇝ⁿ c' ↔ iter n c = some c'`. This is L1 stated as the definition of `Delay` together with the unfolding below.
- **R1 (unfold).** `⟦c⟧ = match step c with | next c' => think ⟦c'⟧ | done o => pure o`.
- **R2 (unique outcome).** `o ∈ ⟦c⟧ → o' ∈ ⟦c⟧ → o = o'`. This is `Computation.mem_unique`.
- **R3 (trichotomy).** `⟦c⟧ = empty ∨ ∃ o, o ∈ ⟦c⟧`, classically. Halts, is stuck and diverges become predicates on `o`: `o ∈ Halt`, `o ∈ Stuck`, or `⟦c⟧ = empty`.
- **R4 (prefix and append).** `iter n c = some c' → ⟦c⟧ = think^[n] ⟦c'⟧`, and `iter (n+m) = iter n >=> iter m`.
- **R5 (closure conversion).** `ReflTransGen (graph step) c c' ↔ ∃ n, iter n c = some c'`, proved once for any functional relation.
- **R6 (transport along a machine morphism).** Suppose `h : C → C'` commutes with `step` (with an outcome map `g`). Then `⟦h c⟧ = g <$> ⟦c⟧`. This one rule replaces every conversion between step relations.

**What it makes free, and what it costs.**
- All 31 C1 members become one-line instantiations, and every new step relation (OS spec, future ones) costs one `Machine` structure, about 5 lines.
- **Cost 1:** Lean 4 has no native coinduction, so we rely on the fuel-sequence quotient, which Mathlib has already built.
- **Cost 2:** the Iris adequacy theorem has to be restated once as "wp Φ c → ∀ o ∈ ⟦c⟧, Φ o". That is a one-time bridge, but adequacy proofs usually talk about n-step runs, so expect around 60 lines.
- **Cost 3:** step-indexed reasoning still needs `iter n`. R4 keeps that honest.

**Theories it draws on.**
- The Capretta delay monad from type theory ("General recursion via coinductive types", LMCS 2005 **[check]**).
- Universal coalgebra and final coalgebras from category theory (Rutten 2000 **[check]**). R6 is the finality of behaviour maps.
- Kleene fixed-point iteration from domain theory. R0 is the ω-chain approximation.
- Coinductive big-step semantics from compilers (Leroy–Grall 2009 **[check]**).

**Target cluster:** C1, plus the outcome half of C2. A checker that returns `f n` is sound because `f n = some o → o ∈ ⟦c⟧`.

**Pilot.**
- **H1:** `Computation.mem_unique` composed with R1. About 2 lines.
- **H2:** R5. About 1 line per machine; the generic proof is about 15 lines, once.
- **H3:** Never-wrong means `∀ o ∈ ⟦c⟧, o ∉ {Wrong, Unsupported}`. By R3, `⟦c⟧ = empty ↔ ¬∃ o ∈ Halt, o ∈ ⟦c⟧`. About 4 lines.
- **H4:** the same proof with Stuck = Error. Written generically, H3 and H4 are the same lemma.
- **H5–H9:** out of scope, deliberately. For H8 this gives only `⟦c⟧ = think^[4] ⟦c'⟧` once the configuration after four steps is known.
- **Refactor, VM run determinism:** delete the block. It becomes `vmMachine : Machine St Outcome` plus R2/R4. Expect about 90 percent deletion.
- **Refactor, machine run composition:** becomes R4 (`iter_add`).
- **Refactor, generic model reachability ↔ VM n-step conversion:** if the generic machine model wraps the VM `step`, then `h = id` and R6 closes it at `rfl` level. Otherwise R6 costs one commuting square (`step' ∘ h = map h ∘ step`), which is proved by `cases` on `step`.

## 2. Placement parametricity (an "Erlangen program" for heap representations)

**Seed driver:** the doubled characters `EE`, `pp`, `77`. Each is a copy of itself. A copying collector produces the same shape at a new place, and in the Erlangen program's terms a property is admissible exactly when copying does not change it.

**The idea.** Representation predicates stop being arbitrary `Prop`s over memory. They are written in a placement-generic language, and only its atoms touch addresses:
- `word m a = w`
- `ptrWord (loc, off) = w`, meaning `w = pl loc + 8·off`
- `intWord n = w`, meaning `w = 2n+1`
- header and field atoms
- connectives: `∧`, `∨`, `∃` over values and locations, bounded `∀ i < len`, and separating disjointness of block ranges

The relocation group (more precisely, the groupoid of block-affine partial injections) acts on pairs `(placement, memory)`. The fundamental theorem says every formula in the language is invariant under that action. L3 becomes a meta-theorem, and its disjointness side condition becomes the definition of what counts as an admissible relocation.

It can be done two ways:
- **Shallow:** `class RelocInvariant (P : Placement → Mem → Prop)`, with instances for each connective and atom, discharged by a `fun_prop`-style tactic **[check: `fun_prop` in Mathlib is extensible to user-defined function properties]**.
- **Deep:** a reified `RFormula` with a denotation plus a fundamental lemma, proved by induction on the formula.

**Core rules.**
- **Admissible relocation `ρ` (the laws' hypotheses become the definition).**
  - `ρ` is block-affine: `ρ(pl l + 8k) = ρ(pl l) + 8k` for `k ≤ size l`.
  - Target ranges are pairwise disjoint (the counterexamples show this condition is necessary).
  - `ρ` is the identity outside live young blocks.
  - `m'` is the memory relocated by `ρ`: pointer words are mapped through `ρ` and every other word is copied.
- **Atom laws (the only hand proofs).**
  - `ptrWord` is covariant: `ptrWord_{ρ∘pl}(l,off) = ρ(ptrWord_pl(l,off))`.
  - `intWord`, `codeWord`, `atomWord` and headers are fixed, because they are non-pointer words and are copied.
  - `word` reads commute: `m'(ρ a) = relocWord ρ (m a)`.
- **Fundamental theorem (L3).** `⟦φ⟧ pl m → ⟦φ⟧ (ρ ∘ pl) (reloc ρ m)`, by induction on φ. The separating-disjointness connective needs the disjointness of targets.
- **Composition.** Relocations compose and invariance is closed under composition, so repeated minor collections cost nothing.
- **The bad case, made visible.** Any predicate that tests raw address order or compares a pointer against a constant is not in the language. That is where a proof should fail, and it will fail at elaboration time rather than halfway through a proof.

**What it makes free, and what it costs.**
- Of the roughly 40 upcoming C3 cases, all but the atom laws become `by relocInvariant`: 8 object kinds, the stack region, channels, and the 15 fields of the loop-head relation. That leaves about 5 atom lemmas of about 10 lines each, plus one fundamental theorem.
- **Cost 1:** the existing representation predicates have to be re-expressed, or proved equal to terms of the language. That is a one-time rewrite of the loop-head relation, about 15 small equalities.
- **Cost 2:** doubles live outside the heap-pointer language, and they must stay non-pointer words.
- **Cost 3:** the GC's scan must be shown to produce `reloc ρ m` for an admissible `ρ`. That is the collector's own correctness and stays a separate obligation, but it is now stated once.

**Theories it draws on.**
- The Reynolds abstraction theorem and Wadler's free theorems (PL semantics). The fundamental lemma is exactly the logical-relations argument.
- The Tarski–Sher invariance criterion for logical notions (philosophical logic): a notion is logical iff it is invariant under permutations of the domain (Tarski 1966 lecture, published 1986 **[check]**).
- Klein's Erlangen program (geometry): properties are the invariants of a transformation group.
- Nominal sets and the equivariance principle (Gabbay–Pitts **[check]**). Locations play the role of atoms, and `ρ` is a renaming, generalised to partial injections as in nominal renaming sets **[check: Gabbay–Hofmann]**.

**Target cluster:** C3. It also covers relocation-invariance of the pieces of C4 specifications that mention heap shapes.

**Pilot.**
- **H5:** the atom law for value encoding. `cases v`: four constructors are copied words, and the `ptr` case uses block-affinity. About 12 lines.
- **H6:** object layout is `header ∧ ∀ i < n, word (pl l + 8(i+1)) = enc(field i)`, which lies in the language, so `by relocInvariant`. About 1 line, plus the reification equality (about 3 lines).
- **H7:** the stack region is `∀ i < len, word (sp + 8i) = enc(stk[i])`. Here `sp` is not a block pointer. The stack is an old-generation root region, so `ρ` fixes it and only its contents are rewritten. That falls to the same fundamental theorem. About 1–3 lines.
- **H1–H4, H8, H9:** out of scope.
- **Three refactors:** none, beyond noting that the representation relation used in the reachability conversion becomes `RelocInvariant`.

## 3. Instruction patches: a lens algebra of footprints

**Seed driver:** the recurring short pairs `Bw`, `cn` and `dMr`/`dXMr`. Small fragments recur throughout the long string, just as each instruction touches only a few fields of a large state.

**The idea.** Each bytecode instruction denotes a patch: a footprint lens `fp : St ⟶ View`, a pure kernel `k : View → Δ`, and a writer `apply : Δ → St → St` that updates only the view's fields. Here `View` covers pc, accu, the top-k stack slots and the touched fields, and `Δ` is a record of optional updates to pc, accu, a pop count, pushes and one allocation.

The VM `step` is proved once to equal `patchOf (code[pc])` interpreted, by `funext` and `cases` on the opcode. This is one theorem with a `cases` arm per opcode. It is not a family of per-instruction decode lemmas, because nobody ever cites the arms by name.

Segment proofs are then written by composing patches. `Patch.comp` normalizes symbolically: an update followed by a read of the same field is resolved, and a push followed by a pop cancels. The final `Δ` is read off directly. Straight-line code becomes a computation in a monoid of patches, and `simp` works over one fixed lemma set of about 12 lemmas (the lens laws plus the array-theory select/store laws).

**Core rules.**
- **Lens laws.** `get (put v s) = v`, `put (get s) s = s`, `put v' (put v s) = put v' s`, plus independence: disjoint lenses commute.
- **Locality (L4 as a proved rule).** `fp s₁ = fp s₂ → step s₁ = patch-apply (k (fp s₁)) s₁` and `rest(step s) = rest(s)`, where `rest` is the complement lens. This is Bancilhon–Spyratos' constant complement, and it is proved generically from `step = interp ∘ patchOf`.
- **Frame by complement.** For any predicate `Q` over `rest`, `Q (rest s) → Q (rest (step s))`. "Stack unchanged below depth k" is an instance.
- **Composition.** `interp (p ; q) = interp q ∘ interp p`, and `Patch.comp` normalizes the pairs `push;pop`, `set accu;read accu`, and `pc := pc+1` chains.
- **Allocation.** Allocation appends, so the heap view is `heap.length` plus the fields read. Allocation writes only fresh indices, which gives heap framing for free.

**What it makes free, and what it costs.**
- Straight-line C4 code, including "from ANY state" specifications, becomes symbolic evaluation with a fixed simp set. The frame is automatic, since there is no separation-logic predicate to maintain.
- **Cost 1:** the equality `step = interp ∘ patchOf` is about 150 opcode arms, once. It should fall to `cases op <;> rfl` if `patchOf` mirrors `step` closely **[risk]**.
- **Cost 2:** branches in the view (`BRANCHIF`) give conditional patches, and sequences of them fan out; the loop candidate below takes over from there.
- **Cost 3:** the machine side is not covered.

**Theories it draws on.**
- Bidirectional lenses from programming languages (Foster, Greenwald, Moore, Pierce, Schmitt, TOPLAS 2007 **[check]**).
- The database view-update problem with constant complement (Bancilhon–Spyratos, TODS 1981 **[check]**).
- McCarthy's select/store theory of arrays (automated reasoning), used here as simp laws rather than an SMT call.
- Goguen–Meseguer noninterference from security (1982 **[check]**). Locality is "the output does not depend on high inputs", with high meaning outside the footprint.

**Target cluster:** C4, and it supplies the L4 rule used by candidate 4.

**Pilot.**
- **H8.** Patches: CONSTINT 40 is `{accu := 40, pc+1}`, PUSH is `{push accu, pc+1}`, CONST2 is `{accu := 2, pc+1}`, ADDINT is `{accu := accu + top, pop 1, pc+1}`.
  - `Patch.comp` of the four normalizes to `{accu := 42, pc := 4}`, with the push/pop cancelled.
  - "Stack unchanged" comes from the complement frame.
  - Proof: `simp [patch_simps]` after `rw [step_eq_patch]` four times. That is roughly `iter 4 s = some {s with pc := 4, accu := int 42}`, about 5 lines.
  - Integer overflow: `40 + 2` is inside 63 bits, and `decide` discharges it.
- **H9:** the loop body is one patch, `{top := top+1 …}` plus a conditional branch patch. The iteration is handed to candidate 4.
- **H1–H7:** out of scope.
- **Three refactors:** none directly. If candidate 1 is adopted, the VM run-determinism refactor is unaffected, because patches are a presentation of `step` and not a new relation.

## 4. Poincaré sections: loops as return maps, semi-conjugate to Lean functions

**Seed driver:** the digit/letter alternation in `3On7t27sN35C` and the numeric clusters `32`, `208`, `29`. They read as a signal that keeps coming back to one place (a section) with a changed numeric state.

**The idea.** A bytecode loop, and eventually any function of the 412k-instruction compiler, is specified by three things:
1. A section `Σ`: a set of cut-point pcs, namely loop heads plus function entries and returns. This is Floyd's method, but posed as dynamics.
2. The first-return map `R : Σ ⇀ Σ ⊎ Exit`, computed by candidate 3's straight-line symbolic evaluation of the body between cut points.
3. An abstraction `α : St → A` and a pure Lean function `f : A → A ⊕ B`, with the semi-conjugacy `α (R s) = f (α s)` on an invariant set `I ⊆ Σ`.

Once the square commutes, the VM's behaviour from the section is `f`'s behaviour, transported. Termination and final values come from Lean's own reasoning about `f`, whether by `decide`, `omega` or induction on a measure of `A`.

This fits the compiler because each OCaml source function already is the `f`. The VM's code for it is proved semi-conjugate to it, and semi-conjugacies compose along calls (nested sections).

**Core rules.**
- **Return-map rule.** If the body from `s ∈ Σ` hits `Σ ∪ Exit` after `k` steps with no intermediate cut point, then `R s` is defined and `⟦s⟧ = think^[k] ⟦R s⟧`. This uses candidate 1's R4, or any C1 algebra.
- **Transport.** From `α ∘ R = f ∘ α` on `I` and `R(I) ⊆ I ∪ Exit`, conclude `α (R^n s) = f^n (α s)` and `exits (R, s) ↔ exits (f, α s)`, with the exit value mapped by the exit-side α.
- **Termination lift.** If `f` terminates (`WellFounded` on `A` via a measure, or `f` is total recursion), then so does the VM from `I`. Divergence of `f` likewise transports to divergence of the VM, which gives H3-style facts about specific programs.
- **Functoriality.** Semi-conjugacies compose: `(α₂, f₂) ∘ (α₁, f₁)`. A call site inside the body is a nested section whose return is replaced by the callee's `f`. This is the modularity rule for C4 at scale.
- **Frame.** α reads only the view. By candidate 3's locality (L4), the rest of the state is carried unchanged through `R`, so the specification quantifies over "ANY state" for free.

**What it makes free, and what it costs.**
- Every loop specification becomes: one body evaluation (symbolic, candidate 3), one commuting-square proof, and ordinary Lean reasoning about `f`. No per-iteration step counting.
- **Cost 1:** choosing α and cut points for 412k instructions. Back-edges of the bytecode CFG give Σ mechanically; α per function has to come from the source (the compiler's own OCaml).
- **Cost 2:** heap-allocating loops need α to read heap graphs, where candidate 2's placement-generic view helps.
- **Cost 3:** the invariant `I` still has to be found by hand for tricky loops, though it is often just `pc = head ∧ stack shape`.

**Theories it draws on.**
- Dynamical systems: Poincaré first-return maps and topological semi-conjugacy.
- Symbolic dynamics: α as a coding map, as with Markov partitions **[check the analogy's precise fit]**.
- Floyd's inductive assertions with cut points (1967 **[check]**).
- Cousot–Cousot abstraction functions (abstract interpretation), using the exact, not the approximate, case.

**Target cluster:** C4, with C1 used only through the transport rules.

**Pilot.**
- **H9.**
  - Σ = {loop head}. α s = the integer at `stack[0]`. `f i = if i < 10 then inl (i+1) else inr 10`, where the exit value is the accumulator.
  - The square is one symbolic body pass, about 6 lines via candidate 3, with a `BRANCHIF` split.
  - Termination: `f` terminates by the measure `10 - i`, and the exit value 10 comes from `decide` or `omega` over `i ≤ 10`. This part is about 5 lines.
  - About 15 lines in total, independent of the iteration count.
- **H8:** the degenerate case with no loop: Σ = {0, 4}, `R` = one straight-line pass, `α = (accu, stack)`, `f _ = inr (42, stack)`.
- **H1–H7:** out of scope.
- **Three refactors:** none. Its value shows on C4, not on existing code.

## 5. Point-free relation algebra: determinism, checkers and conversions as inclusions

**Seed driver:** the near-palindrome `WdW`, a string that reads the same reversed. In relation algebra reversal is the converse `R°`, and determinism is the one-line inequation `R°;R ⊆ id`.

**The idea.** Write C1 and C2 without points, in a Kleene algebra with tests over relations on configurations. Mathlib has `KleeneAlgebra`, and `Set (α × α)` or `SetRel` may carry a composition structure **[check both]**.

Everything becomes an arrow:
- the step relation `S`
- the halting test `H` (outcome arrows)
- the fuel iterate `fuel n` from L1
- the executable checker's graph `G_chk`
- the maps between machines `α`

C1 facts become short calculations from four axioms. C2 soundness is an inclusion, `G_chk ⊆ S*;H`. Completeness is the reverse inclusion restricted to the domain. Both are proved by fixed-point fusion rather than by hand-rolled induction.

**Core rules.**
- **Simplicity.** `simple R := R°;R ⊆ id`. Proved rule: `simple S ∧ dom S ∩ dom H = ∅ ∧ simple H ⇒ simple (S*;H)`. This single lemma is halting-is-unique for every relation.
- **L1 as the star identity.** `S* = ⋃ₙ graph(fuel n)`, with `fuel n` the Kleisli iterate of the functional `S`. The C1 prefix and append rules follow from `Sⁿ;Sᵐ = Sⁿ⁺ᵐ` and star unfolding (Kozen's axioms).
- **Divergence as the dual.** `Div := νX. S;X` (the greatest fixed point). Rule: `simple S ⇒ Div ∩ dom(S*;H) = ∅`, and `dom(S*;(H ∪ Stuck)) ∪ Div = ⊤` (classically). Never-stuck and never-wrong mean `S*;Stuck = ∅`.
- **Star fusion.** `α;S₁ ⊆ S₂;α ⇒ α;S₁* ⊆ S₂*;α`, and the same with equality. Every conversion between step relations is one fusion.
- **Checker soundness by fixed-point fusion.** Knaster–Tarski: if `chk` is a fuel-bounded fold and the specification is the least fixed point `μX. H ∪ S;X`, then soundness reduces to showing that one unfolding of `chk` is included in one unfolding of the specification. This is the pattern all seven C2 cases follow **[claim: they are all shaped this way; verify against C2]**.
- **(Optional) C3 in the same algebra.** L3 reads `Rep;ρ ⊆ Rep` for admissible ρ. That makes the obligation statable, but candidate 2 is what proves it.

**What it makes free, and what it costs.**
- C1 and C2 lemmas become inequational calculations shared across all four step relations, and C2's growing list gets one proof template.
- **Cost 1:** point-free proofs are unfamiliar and awkward in Lean. Expect a custom `rel_calc` tactic or heavy `Set.ext` unfolding.
- **Cost 2:** the greatest fixed point for divergence needs `OrderHom.gfp` **[check the Mathlib name]**.
- **Cost 3:** this overlaps candidate 1 on C1. Candidate 1 is the easier sell there; this candidate earns its place on C2 and on conversions.

**Theories it draws on.**
- Tarski's relation algebra (logic).
- Allegories (category theory, Freyd–Scedrov 1990 **[check]**): simplicity, domains, tabulations.
- Kleene algebra with tests (Kozen 1997 **[check]**), which covers Hoare logic in KAT.
- The Algebra of Programming (functional programming, Bird–de Moor 1997 **[check]**): fusion laws and hylomorphisms, used for the checker case.

**Target cluster:** C1 and C2.

**Pilot.**
- **H1:** the simplicity lemma applied to `stepOnce`'s graph. `simple (graph f)` is immediate, and `dom S ∩ dom H = ∅` holds because `Next` is a sum type. About 3 lines.
- **H2:** the L1 star identity. About 1 line.
- **H3/H4:** the divergence rule plus "never stuck", with Stuck instantiated as `Wrong ∪ Unsupported` or `Error`. About 4 lines each, one generic lemma.
- **H5–H9:** out of scope, except that H5–H7 can be stated as `Rep;ρ ⊆ Rep`.
- **Refactor, VM run determinism:** becomes `simple (graph vmStep)` plus the simplicity lemma.
- **Refactor, machine run composition:** becomes `Sⁿ;Sᵐ = Sⁿ⁺ᵐ` and star unfolding.
- **Refactor, generic model reachability ↔ VM n-step conversion:** one application of star fusion with `α` = the presentation map. The commuting square `α;S_vm = S_gen;α` is proved by `cases` on `step`. About 6 lines instead of an induction.
