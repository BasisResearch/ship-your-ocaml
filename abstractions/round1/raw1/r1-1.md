## 1. Orbit Calculus (runs as delay-monad values)
**Seed driver:** `diZiZ`, the period-2 repeat, read as an orbit returning to itself.

**Idea.** Write no run relations at all. For any deterministic `f : C → Next C` (`Next = step c | halt r | err e`), define one canonical object: `orbit f c : Delay (Outcome)`, the Capretta delay monad (coinductive `now r | later d`), or equivalently a partial stream of configurations. Every C1 statement becomes an equation between orbits or about their finiteness. "c reaches c′ in n steps" is not a primitive: it is `iter f n c = some c′`, and L1 is the definition itself, not a theorem.

**Core rules (proved once, generic in f):**
- R1 (L1 as definition): `reach f n c c' :↔ iterate f n c = .step c'`. Here `iterate` is a total, fuel-bounded function, and the relational form is a derived `@[simp]` view.
- R2 (the shift law): `iterate f (m+n) c = (iterate f m c).bind (iterate f n)`. This one law gives prefix, append, snoc and composition.
- R3 (a function has one output): `orbit f c` is a single value, so a unique halt follows from `now r = now r' → r = r'`.
- R4 (trichotomy): `orbit f c` either converges to `halt r`, converges to `err e`, or is `never` (constructive in the classical fragment only). Divergence is defined as `orbit f c = never`.
- R5 (closure bridge): `ReflTransGen (stepRel f) = ∃ n, reach f n` is proved once from R1 and R2, and relation conversions are rewrites along it.

**What becomes free:** all 31 C1 members, and every future step relation (OS spec, new machine) via one instance `DetSystem f`. The Iris-machine layer's adequacy can consume `orbit` directly.

**What it costs:** coinduction in Lean 4 is awkward. Use a fuel-indexed (`Nat → Option`) encoding of Delay (the "stream of approximations"), not a coinductive type. Strong bisimilarity of delays needs a quotient if you ever want `=`, so avoid it and keep everything as `iterate` equations.

**Distant theories:**
- Symbolic dynamics and topological dynamics: orbits, the shift map, periodic points.
- The Capretta delay monad and partiality (Capretta 2005; Chapman, Uustalu and Veltri, "Quotienting the delay monad", recalled from memory, check).
- Elgot iteration theories (Bloom and Ésik, recalled, check), for the iteration laws.

**Target cluster:** C1 (and it feeds C2).

**Pilot:**
- H1: `instance : DetSystem machineStep`, then `halt_unique := orbit_now_unique`. That is one line.
- H2: this is R5 instantiated.
- H3: "never wrong" means `∀ n, iterate step n s ≠ .wrong`. R4 minus the `err` branch gives diverges ↔ ¬halts.
- H4: the same with "never stuck".
- H8/H9: out of scope (see 3 and 4).
- Refactor, VM run-determinism block: delete it and replace it with `DetSystem BcSem.step` plus R3.
- Refactor, machine run composition: each lemma becomes `by simp [iterate_add]` (R2).
- Refactor, generic reachability to VM n-step conversion: the two relations are both `reach`, instantiated through the presentation map, so the conversion is R5 composed with a proved `iterate_map` (a simulation that is a strict commuting square).

## 2. Relocation Equivariance (a nominal / Erlangen treatment of placement)
**Seed driver:** the mirror `B9alb9`. An object and its image under a transformation have the same properties.

**Idea.** Treat the set of admissible relocations (live block ↦ new disjoint range) as a groupoid `Reloc` acting on memories. Represent placement as a support, in the nominal-sets sense. Write every representation predicate in a small combinator grammar (word-is-encoding-of, block-at, region, separating conjunction, ∃-placement, big-star over the live set). Prove once that every grammar term is equivariant: `P (ρ·mem) (ρ∘place) ↔ P mem place`. The GC proof then reduces to "the collector's effect is ρ·mem for some ρ ∈ Reloc". C3 stops being about 40 components and becomes a single theorem about the grammar.

**Core rules:**
- E1 (L3 as the action law): `ρ · (m : Mem)` rewrites each pointer word through ρ and copies all other words. `Reloc` requires pairwise-disjoint target ranges, which are part of the type (the 12,358 counterexamples show this must be a type invariant, not a side condition).
- E2 (equivariance is closed under the connectives): `Equiv P → Equiv Q → Equiv (P ∗ Q)`, `Equiv (∃ pl, P pl)`, `Equiv (bigStar live P)`, and `Equiv (fun m pl => m[pl l + 8k] = enc v)` when `enc` maps `ptr l k ↦ pl l + 8k`. The last one is the only atom that inspects ρ.
- E3 (support): a predicate that mentions only addresses inside `pl(live)` and uses them only through `pl` is automatically equivariant. This is Pitts' finite-support principle transposed to heaps.
- E4 (GC is an action): `minorGC m = ρ_gc · m` restricted to the live set, proved once against the collector's code.

**What becomes free:** H5–H7 and every one of the ~40 C3 obligations, including all 8 object kinds, channels and the 15 loop-head fields, as instances of the `Equiv` typeclass synthesized structurally. Adding an object kind costs zero new GC lemmas if it is written in the grammar.

**What it costs:**
- A disciplined deep or shallow embedding of the representation grammar, so predicates are syntactically in-grammar and `Equiv` instances resolve by type-class search.
- One real proof (E4), which is hard and irreducible.
- Raw words must be proved not to be mistaken for pointers: the int tag bit makes the encoding injective, and this must be an explicit lemma.

**Distant theories:**
- Nominal sets and equivariance (Gabbay and Pitts; Pitts' book *Nominal Sets*, recalled, check).
- Klein's Erlangen program: a geometry is the invariants of a group action.
- Reynolds' parametricity and representation independence. Existentially quantified placement is an abstract type, so any client is parametric in it.

**Target cluster:** C3.

**Pilot:**
- H5: `Equiv (valueEncodes v)` from the E2 atom plus tag injectivity.
- H6: `Equiv (objLayout o)` by instance search (header word, then `bigStar` over fields).
- H7: `Equiv (stackRegion sp vs)`. The stack region lives outside the young generation, so ρ is the identity on its addresses and only the words inside change: E1 plus E2.
- H1–H4, H8, H9: not applicable.
- The three refactors: not applicable.
- Success metric for C3: the number of GC-specific lemmas equals the number of grammar connectives (about 6), not the number of components (about 40).

## 3. Footprint Lenses (local actions with a proved frame rule over VM states)
**Seed driver:** the `a0f … a0f` bookend. The ends are held fixed while the middle is rewritten, which is a frame.

**Idea.** Give each bytecode instruction a declared footprint as a lens `ℓ_i : St ⟶ F_i` (e.g. `F = pc × accu × stack.take 2`, plus a named heap field) and a small function `δ_i : F_i → Next F_i`. The theorem `step p s = ℓ_i.put s <$> δ_i (ℓ_i.get s)` is L4 made into a definition-level fact, proved once per instruction by `rfl`/`simp` from the step function, not hand-written per arm. Specifications are written over footprints and composed with a frame rule derived from the lens laws. The stack is a list lens `top k ⊗ rest`, so "stack unchanged" means "rest is outside the footprint", for free.

**Core rules:**
- F1 (lens laws): get-put, put-get and put-put for each footprint lens, and independence `ℓ ⊥ ℓ'` (the puts commute and neither changes the other's get).
- F2 (frame rule): `ℓ ⊥ m` and `{P} δ {Q}` on `ℓ` imply `{P ∧ m s = x} step {Q ∧ m s = x}`. This is L4 as a rule.
- F3 (sequencing): footprint transformers compose, and the composite footprint is the join of the lenses.
- F4 (heap monotonicity): allocation appends, so the old heap prefix is outside every footprint. This is a frame for "old objects unchanged".

**What becomes free:** "the rest is unchanged" clauses in every C4 spec, and reusing a segment spec at any stack depth or in any environment.

**What it costs:**
- Footprints depend on runtime values (field index read from the stack). They are dependent lenses, so use "lens indexed by the prefix read".
- Heap-field footprints need a per-location lens.
- One lemma per opcode (about 150) to certify the factoring. It is mechanical, but must be proved from the actual step function, and these are opcode-level, not site-level.

**Distant theories:**
- Bidirectional transformations and lenses (Foster, Greenwald, Moore, Pierce and Schmitt, TOPLAS 2007, recalled, check).
- The database view-update problem (Bancilhon and Spyratos, constant complement, recalled). The complement is exactly the framed part.
- The separation-logic frame rule (O'Hearn, Reynolds and Yang).

**Target clusters:** C4 (primary), plus C3, since relocation is also a put that commutes with the value footprint.

**Pilot:**
- H8: footprints of `CONSTINT`, `PUSH`, `CONST2`, `ADDINT` compose to the footprint `pc × accu × top1`. Evaluating `δ` symbolically gives `accu = 42`, the net stack effect is push-then-pop, so `rest` is outside the composite footprint and F2 gives "stack unchanged" for any state.
- H9: the loop body's footprint is `pc × accu × top1`. The invariant `top = i ∧ i ≤ 10` is stated on the footprint and framed.
- Refactor, VM determinism: not applicable.
- The other two refactors: not applicable (this candidate is C4-only by design).

## 4. Deterministic Guarded Kleene Algebra for bytecode control flow (GKAT + footprint actions)
**Seed driver:** the doubled runs `rr`, `dd`, `zz`, `33`, `44`, read as idempotent iteration. The cluster `23340` suggests counters.

**Idea.** Lift the code of a program (up to 412k instructions) to a GKAT term. Primitive actions are basic blocks with footprint semantics from candidate 3. Tests are guards on the footprint (e.g. `top < 10`). Because the VM is deterministic, GKAT (guarded, deterministic `if`/`while`), not full KAT, is the right algebra. Specs become Hoare inequalities `b · e ≤ e · c`, i.e. `b·e·¬c = 0`. Loops are proved by the star/while induction axiom instead of step-counting, and whole-procedure equivalences (e.g. "optimized loop equals reference") are decided by GKAT's near-linear equivalence procedure. That is a tool used only to check the algebraic law. The adequacy theorem is proved once: the GKAT denotation of the lifted CFG equals `orbit` (candidate 1) of the VM restricted to that code.

**Core rules:**
- G1 (adequacy): `⟦lift(code)⟧ s = orbit step s` on the region of code covered by the lift, proved once by the fuel iterate.
- G2 (Hoare-as-equation): `{b} e {c} ⟺ b·e·¬c = 0`, with the sequencing, conditional and while rules derived as theorems of the algebra.
- G3 (while induction): `b·c·e ≤ e·c ⟹ c·(while b do e) ≤ (while b do e)·(c ∧ ¬b)`.
- G4 (termination): a ranking function on the footprint strictly decreasing on `b·e` proves `while b do e` is productive. This is needed because GKAT itself is partial-correctness.
- L4 enters as the fact that atomic actions are footprint transformers, so guards and actions on disjoint footprints commute (`b·p = p·b` when `fp(b) ⊥ fp(p)`). These commutation hypotheses are exactly NetKAT/KAT "commuting tests".

**What becomes free:**
- Control-flow plumbing for all C4 loops and branches.
- Spec composition across segments.
- Mechanical decidability of CFG-shape equivalences, which is useful for 412k-instruction chunks where most blocks are straight-line.

**What it costs:**
- Building the CFG lift and proving G1 once.
- Irreducible control flow (computed jumps, closures, exceptions via `trap`) needs an escape hatch: those edges become opaque actions with hand specs.
- GKAT completeness requires the "early termination" axiom subtleties. Only soundness is needed, so rely on that.

**Distant theories:**
- Kleene algebra with tests (Kozen 1997, recalled).
- GKAT (Smolka, Foster, Hsu, Kappé, Kozen and Silva, POPL 2020, recalled, check the author list).
- Automata theory: coalgebraic bisimulation and the determinization of guarded automata.
- Program-schema theory (Ianov schemes, recalled): uninterpreted-action equivalence.

**Target clusters:** C4, and C1 via G1.

**Pilot:**
- H9: the loop is `while (top<10) do (top++)`, then `STOP`. G3 with invariant `top ≤ 10`, plus G4 with rank `10 − top`, gives `top = 10` on exit. After the exit block `accu = 10`.
- H8: a straight-line term `a₁·a₂·a₃·a₄`. Algebra adds nothing here, so it is just footprint evaluation from candidate 3.
- H3: follows from G1 plus candidate 1's R4.
- Refactors: the generic reachability to VM n-step conversion is an instance of G1's adequacy square, in the special case of the trivial one-block lift.

## 5. Natural Symbolic Stepping (step as a natural transformation over state templates)
**Seed driver:** the palindrome `sYs`, read as a round trip: concretize, step, abstract back.

**Idea.** Define a template state `Tm` whose fields are terms over variables (stack = `t₁ :: … :: tₖ ++ ?rest`, heap = `?h ++ new`, and so on), with an instantiation `σ : Var → value` and `⟦·⟧σ : Tm → St`. Prove once a symbolic step `sstep : Tm → Next Tm ∪ {stuck-on-unknown}` and its naturality square: `sstep t = some t' → ∀σ, step (⟦t⟧σ) = ⟦t'⟧σ`. This is L4 generalized: an instruction that does not inspect a variable commutes with every instantiation of it. H8's "from ANY state" is then one run of `sstep` by `decide`/kernel reduction on a template with fresh `?rest, ?env, ?heap`. C2 checker soundness also becomes an instance, because every checker is a symbolic stepper plus a decision on the resulting template, and soundness is the naturality square composed n times.

**Core rules:**
- N1 (naturality): `step ∘ ⟦·⟧σ = ⟦·⟧σ ∘ sstep` where `sstep` is defined. This is proved once by structural induction on the opcode, reusing the step function's own code (write `step` generically over a `ValueDomain` typeclass and instantiate it at concrete values and at terms: a Futamura-style reuse).
- N2 (iteration): N1 lifts to `iterate`, giving `iterate sstep n t = some t' → iterate step n ⟦t⟧σ = ⟦t'⟧σ`. This is L1 composed with N1.
- N3 (checker soundness schema): any `check : Tm → Bool` with `check t = true → ∀σ, Post ⟦t⟧σ` is sound for `Post` after the run. The C2 members become instances.
- N4 (generalization): a template variable never inspected in a run is universally quantified. This is the "free theorem" that gives "stack unchanged".

**What becomes free:**
- H8-style straight-line specs at zero manual cost (by `decide`/`rfl`).
- Most of C2.
- Basic-block summaries for the 412k-instruction compiler, generated rather than proved.

**What it costs:**
- Refactoring `step` to be polymorphic over the value domain. This is a real engineering change, and kernel reduction on 63-bit arithmetic needs care (use `BitVec` normal forms).
- Branches on unknowns stop the symbolic stepper, so loops still need candidate 3/4 reasoning.
- Allocation with symbolic heap length needs `loc = |?h| + k` terms.

**Distant theories:**
- Partial evaluation and the Futamura projections: the concrete and symbolic steppers are specializations of one generic stepper.
- Category theory: naturality and Wadler's "Theorems for free!" (recalled).
- Term rewriting and narrowing: symbolic execution as narrowing with instantiation.
- Abstract interpretation's soundness square (Cousot and Cousot), with a γ-only (concretization) presentation.

**Target clusters:** C4 (straight-line), C2, and C1 via N2.

**Pilot:**
- H8: the template is `pc=0, stack=?rest, env=?e, …`. `sstep⁴` computes to `accu=42, stack=?rest`, and N2 gives the result for any state. Expected about 3 lines.
- H9: the stepper computes the loop body summary `top ↦ top+1`, and the induction is manual (or via candidate 4).
- H1/H2: not applicable.
- Refactors:
  - The machine's run-composition lemmas are N2's compositionality specialized to the identity template.
  - The reachability conversion is N1 with `⟦·⟧` taken as the presentation map from the VM into the generic machine model: the same square, instantiated.
