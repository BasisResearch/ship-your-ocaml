## 1. Behaviour extraction: every step relation is the graph of one `Computation`

**Seed driver:** `Emu` (in `J2EmuUb`). The emulator *is* the semantics: running the total step function is the definition, and relations are derived from it. The doubled `RR`/`NN` suggest one object seen twice, the relation and its graph.

**The idea.** Stop treating n-step runs as inductive relations that each need their own algebra. Every step relation in the project (machine, `BcSem`, the generic machine model, the OS spec) is presented once as a total function `σ : C → Next C R`, where `Next C R = go C | stop R`. Two derived objects then carry every C1 fact:
- the **fuel iterate** `it : ℕ → C → Next C R`, with `it 0 c = go c` and `it (n+1) c = (it n c).bind σ`;
- the **behaviour** `beh σ c : Computation R`, built from Mathlib's `Computation` (a Capretta-style delay monad encoded as an eventually-constant `ℕ → Option R` stream, *check the current Mathlib API names*).

Proofs are written about `it` and `beh` and are generic in `σ`. Each concrete semantics contributes one adapter: a function to `Next`, plus a map from its halt/error variants into `R`.

**Core rules (proved once, generic in σ):**
- **R-Graph (L1):** `Rel σ n c c' ↔ it n c = go c'`. This is the only place a relational n-step form is allowed to appear, and it is a definition-level `Iff`.
- **R-Act:** `it (m+n) c = (it m c).bind (it n)`. This is a monoid action of (ℕ,+) on `Next C R`. Prefix, append and snoc are the instances `n=1` and `m=1`.
- **R-Stop:** `it n c = stop r → ∀ k ≥ n, it k c = stop r`. Stopping is absorbing.
- **R-Beh:** `r ∈ beh σ c ↔ ∃ n, it n c = stop r`, and `beh σ c = Computation.empty ↔ ∀ n, ∃ c', it n c = go c'`.
- **R-Unique:** `r ∈ beh σ c → r' ∈ beh σ c → r = r'`. This is `Computation.mem_unique` transported by R-Beh.
- **R-Tri:** `beh σ c` terminates, or `beh σ c = empty`. This is classical and holds for any `Computation`. "Sticks" and "halts" are just different values of `R`: `R := Halt code out | Err`, or `Halt | Unsupported | Wrong`.
- **R-Clos:** `ReflTransGen (fun a b => σ a = go b) c c' ↔ ∃ n, it n c = go c'`. This converts between closure relations.

**What it makes free, and what it costs.**
- *Free:* all 31 C1 members become one- or two-line corollaries, or stop existing because they were the generic rule restated. The rules are proved once, at roughly 150 lines.
- *Free:* C2 checker soundness where the runner is fuel-bounded execution. Such a runner *is* `it`, up to an adapter equation, so "sound" reduces to R-Graph plus `rfl`.
- *Cost:* one adapter per semantics, a function to `Next` and a result embedding. The adapter must be definitional, meaning `σ_VM p = BcSem.step p` holds by `rfl` with the constructor map, or R-Graph will not fire by `simp`.
- *Cost:* uses of existing relational `n`-step forms have to be rewritten through R-Graph once.
- *Cost:* coinduction is avoided entirely because `Computation` is a subtype of streams. The price is that proofs about infinite behaviour go through `∀ n`. That is fine here because everything is deterministic.

**Theories drawn on (all recalled from memory, check them):**
- Universal coalgebra: behaviour is the unique map into the final coalgebra of `X ↦ R + X` (Rutten, TCS 2000).
- Capretta's delay monad (LMCS 2005) and Mathlib's `Computation`.
- Semiflows and discrete dynamical systems: the iterate as an action of ℕ, with absorbing (fixed) points.
- Kleene iteration and least fixed points (domain theory): `beh` is the lub of the fuel approximations.

**Targets:** C1 (fully) and C2 (the runner/fuel part).

**Pilot:**
- **H1:** `beh` for the generic model's σ, then R-Unique. About 2 lines.
- **H2:** R-Clos directly. Where "reaches in n steps" is stated relationally, add R-Graph under `∃ n`. About 2 lines.
- **H3:** "Never-wrong" is `∀ n, it n s ≠ stop Wrong`. Diverges ↔ `beh = empty` (R-Beh) ↔ ¬∃ r, r ∈ beh (R-Tri) ↔ ¬halts, after excluding `Wrong` and `Unsupported` from `r`. If "never-wrong" also excludes Unsupported, both are ruled out; otherwise the statement must say "does not stop". About 4 lines.
- **H4:** Same proof with the machine adapter; "never-stuck" excludes `Err`.
- **H5–H9:** not targeted.
- **Refactor, VM run-determinism block:** it disappears. Determinism is `it n c = go a → it n c = go b → a = b`, which is `Next.go.inj`. The halting variants are R-Unique.
- **Refactor, machine run-composition lemmas:** each becomes an instance of R-Act (append, and snoc with `n=1`) followed by R-Graph rewriting.
- **Refactor, generic-model reachability ↔ VM n-step conversion:** both sides are graphs of `it` of the *same* σ once the adapter equation `σ_generic(VM) = σ_VM` is `rfl`. The conversion is R-Clos on one side and R-Graph on the other, about 3 lines.

## 2. A relocation-equivariant layout language (a deep-embedded DSL whose theorems are free)

**Seed driver:** `lLT … lLT`. The same fragment appears at two different places, which is relocation. The near-copy `PlT` right after it is the pointer word that is rewritten rather than copied.

**The idea.** Write every representation component (value words, the 8 object kinds, the stack region, disjointness, channels, the 15 loop-head fields) as a *term* of a small inductive language `Lay`, not as a hand-written Lean predicate. The concrete predicates become `⟦φ⟧ π m`, with placement π. Addresses in `Lay` are symbolic: `base ℓ + 8·k` for block ℓ, or `fixed a` for non-moving regions (stack, registers, statics). A raw integer can never denote a block address.

Words are **sorted**: `vword v` renders a VM `Val`, and the *VM value's constructor* (not the bit pattern) decides whether the word is a pointer. The payoff is one induction over `Lay`: every definable predicate is equivariant under relocations, which is a free theorem in Reynolds's sense.

Constructors, about 10:
- `vword (addr) (v : Val)`
- `hdr (addr) tag size`
- `bytes (addr) (bs)`
- `block ℓ (body : Lay)`, which binds `base ℓ` for the body
- `region (fixed a) (vs : List Val)`
- `sep φ ψ`
- `conj`
- `pure P`
- `exV` (existential over VM-level data)
- `reg r v`

**Core rules:**
- **Relocation:** ρ is a finite map from block ids to new bases, **injective on footprints**. The footprint ranges `[ρ ℓ, ρ ℓ + 8·(size ℓ + 1))` are pairwise disjoint and disjoint from `fixed` regions. `ρ·m` copies each block as a whole, rewrites pointer-sorted words through ρ, and copies all other words.
- **R-Equiv (L3):** `⟦φ⟧ π m → Disj ρ π φ → ⟦φ⟧ (ρ ∘ π) (ρ · m)`, for every `φ : Lay`. This is one structural induction, with the cases `vword`, `hdr`, `block`, `region` and `sep` doing the work.
- **R-Translate:** within a block, `ρ(π ℓ + 8k) = ρ(π ℓ) + 8k` for `k ≤ size`. This is the "as a whole" condition of L3, and the `block` case needs it.
- **R-SepDisj:** `sep` requires disjoint footprints, and `Disj` requires ρ to preserve that. This is exactly where the 12,358 overlapping-target counterexamples live. The hypothesis is necessary, and in the DSL it is visible in exactly one constructor.
- **R-Adequate:** for each existing concrete component `P`, `P π m ↔ ⟦lay_P⟧ π m`. The goal is `rfl`, or `Iff.rfl` after `simp [denote]`.

**What it makes free, and what it costs.**
- *Free:* all ~40 upcoming C3 obligations become the instance `R-Equiv lay_P` plus R-Adequate. New object kinds or loop-head fields are equivariant as soon as they are written in `Lay`.
- *Free:* heap disjointness comes from `sep`, with nothing extra.
- *Cost:* the DSL and its denotation, about 200–300 lines, plus re-expressing the existing components as terms (mostly mechanical).
- *Cost:* expressiveness discipline. Anything outside `Lay` (for example arithmetic on addresses computed from data) loses the free theorem. That is a feature, because it flags exactly the predicates that are *not* relocation-safe.
- **Risk to check:** the `raw word` VM value. The real GC classifies words by bit pattern (even and in the young range), not by VM sort. A `raw` word that happens to look like a young pointer would be rewritten by the machine GC but not by ρ·m. Either `Lay` must show that raw words can never alias the young range, or the relocation law must be stated over the machine's own classification. This is the obligation to push back to the laws stage.

**Theories drawn on (recalled, check them):**
- Nominal sets and the equivariance principle: every predicate definable from equivariant primitives is equivariant (Gabbay–Pitts 2002; Pitts, *Nominal Sets*, CUP 2013).
- Relational parametricity and free theorems (Reynolds 1983; Wadler, "Theorems for free!", 1989).
- Linker relocation records (Levine, *Linkers and Loaders*): code is written against symbolic bases so that relocation is mechanical.
- Partial-bijection GC relations in CakeML's verified GC (Ericsson, Myreen, Åman Pohjola, *verify the exact paper and year*).

**Targets:** C3.

**Pilot:**
- **H1–H4:** not targeted.
- **H5 (value encoding):** the `vword a v` case of R-Equiv.
  - `v = int n`: the word `2n+1` is not pointer-sorted, so it is copied unchanged, and the address `a` moves by ρ if it lies inside a block (R-Translate) or stays put if it is `fixed`.
  - `v = ptr ℓ k`: the word `π ℓ + 8k` becomes `ρ(π ℓ) + 8k = (ρ∘π) ℓ + 8k` by R-Translate.
  - `code`/`atom`: unchanged.
  - `raw`: this is the side condition from the risk above.
- **H6 (object layout):** the `block ℓ (hdr … ⊛ fields …)` case. It follows from the induction hypothesis on the body under the translated base.
- **H7 (stack region):** the `region (fixed a) vs` case. The addresses are unchanged and each word goes through the `vword` case.
- **H8–H9:** not targeted.
- **Refactors:** none of the three is in C3. Stated honestly: this candidate does not help them.

## 3. Footprint lenses: L4 as the lens laws, and a "Curtis–Hedlund–Lyndon" frame theorem

**Seed driver:** the palindrome `HBH`, read as get–put–get round trip (the lens laws). `TeX`, read as boxes composed by juxtaposition, plays the part of disjoint views composing.

**The idea.** Treat a VM state as a *view plus a residue*. For each finite footprint `F` there is a very-well-behaved lens `L_F : Lens St (View F)`. `F` names:
- `pc`, `accu`, `env`, `extra`, `trap`;
- `stk≤k`, which is total because it uses `take k`/`drop k` and does not index;
- `fld (ℓ,i)`, an affine lens, partial on missing fields;
- `heapLen` and `world`.

L4 becomes one proved theorem about `BcSem.step`: the step at `pc` **factors through** the footprint of the instruction at `pc`. Proofs of straight-line bytecode then run on a small concrete `View`, never on `St`. There are no per-instruction lemmas. There is one locality theorem, proved by a single `cases` on the instruction with `simp`, plus a generic factorisation.

**Core rules:**
- **GetPut / PutGet / PutPut** for each `L_F` (standard lens laws). Lenses on disjoint footprints commute: `put_F a (put_G b s) = put_G b (put_F a s)` when `F ⊥ G`.
- **R-Split:** `s = put_F (get_F s) s`. Any "arbitrary state" is rewritten into view-plus-residue form.
- **R-Local (L4):** for every `p, s` there is a footprint `F = fp p s.pc`, a write set `W ⊆ F ∪ {heapLen}`, and a function `δ : View F → Next (View F) R`, such that `step p s = (δ (get_F s)).map (put_F · s)`. This is the Curtis–Hedlund–Lyndon form: a global map that is "continuous" (bounded dependence) is given by a finite local rule. It is proved once, by a single `cases` on the decoded instruction.
- **R-Seq:** for a straight-line segment whose instructions have footprints `F₁ … F_n`, `it n s = (δ_n ∘ … ∘ δ_1)(get_{⋃F} s)` mapped by `put_{⋃F} · s`. This is proved once from R-Local, R-Act (candidate 1) and lens composition.
- **R-Frame:** anything read by a lens disjoint from `⋃F` is unchanged by the segment. "Stack unchanged below the top k" is an instance.
- **Allocation:** `heapLen` is in `W`, and `alloc` is `put` on the pseudo-slot `heapTail`. Because allocation appends, the lens for an old field `fld(ℓ,i)` with `ℓ < heapLen` is disjoint from `heapTail`, so old fields are framed automatically.

**What it makes free, and what it costs.**
- *Free:* straight-line C4 segments are symbolic execution over a finite view, closed by `rfl`/`decide`, from any state.
- *Free:* stack and heap framing come without hand proofs.
- *Free:* the same L4 theorem drives candidate 4's Step rule.
- *Cost:* the lens library over `St` (about 150 lines), R-Local (one big but uniform case split), and an `affine` variant for `fld`.
- *Risk:* instructions whose footprint depends on data (for example `APPTERM n` or a closure with variable arity) need `F` to be a function of the view. That is allowed, since `fp` takes `s.pc` and code, and may need `View` to carry `n`.

**Theories drawn on (recalled, check them):**
- Bidirectional transformations and lenses (Foster, Greenwald, Moore, Pierce, Schmitt, TOPLAS 2007).
- The Curtis–Hedlund–Lyndon theorem from symbolic dynamics and cellular automata (Hedlund 1969): continuous, shift-commuting maps on shift spaces are exactly sliding block codes with a finite local rule.
- Separation logic's frame rule (Reynolds, LICS 2002; O'Hearn–Reynolds–Yang 2001) and dynamic frames (Kassios, FM 2006).

**Targets:** C4 (straight-line segments, framing), and it feeds candidate 4's loops.

**Pilot:**
- **H1–H7:** not targeted.
- **H8:** let `s` be arbitrary with `s.pc = 0` and the code equal to the five-instruction block. The footprint union is `{pc, accu, stk≤1}`, so the view is `(0, a, take 1 s.stack)` and the residue is everything else.
  - `CONSTINT 40` sets `accu := 40`.
  - `PUSH` makes the stack `40 :: s.stack`.
  - `CONST2` sets `accu := 2`.
  - `ADDINT` pops, giving `accu := 42` and stack `s.stack`.
  - Proof: `rw [R-Split]; rw [R-Seq]; rfl`. The view computation is closed and concrete except for `take 1 s.stack` passing through untouched. R-Frame gives "stack unchanged". About 5 lines, with no case split on `s.stack`: `take`/`drop` handles the empty stack because PUSH makes it non-empty before the only pop.
- **H9:** the loop body is one R-Seq segment. The loop itself needs candidate 4.
- **Refactors:** none directly. In the VM run-determinism block, R-Local does make the determinism proof of a *segment* a view equation.

## 4. Language-parametric reachability with ranked circularity (reachability logic for any σ)

**Seed driver:** the echo `JIm … ZIm`, read as a back-link: a proof that cites itself, which is circularity. The digit clusters (`451`, `25`, `75`) stand for loop bounds and ranks.

**The idea.** Write C4 specifications as **reachability claims between state patterns**, `φ ⇒ ψ` with `φ, ψ : St → Prop`, with no step counts. The meaning is total, via candidate 1's iterate: `∀ s, φ s → ∃ n, ∃ s', it n s = go s' ∧ ψ s'`, or a `stop` variant for claims that end in halting. Claims come with a proof system proved sound **once for every deterministic σ**. Loops are handled by *ranked circularity*: a claim may be used as a hypothesis after at least one real step, provided a rank strictly decreases.

This is the setup the K framework uses to verify programs against arbitrary language semantics. It scales from small programs to per-function specs of the 412k-instruction compiler because a function's spec is a claim that can be reused at every call site.

**Core rules (all proved sound once, generic in σ):**
- **Step:** if for all `s` with `φ s`, `σ s = go s'` and `ψ s'`, then `φ ⇒ ψ`. For the VM, the premise is discharged by candidate 3's R-Local on a view, not by per-site lemmas.
- **Trans:** `φ ⇒ χ` and `χ ⇒ ψ` give `φ ⇒ ψ`. This is R-Act from candidate 1.
- **Conseq / Case / Exists:** standard.
- **Frame:** if `φ ⇒ ψ` is stated on a view `F`, then `(φ ∧ R ∘ get_G) ⇒ (ψ ∧ R ∘ get_G)` for any `G ⊥ W`. This comes from candidate 3.
- **Circ-rank:** given a measure `μ : St → ℕ` (or any well-founded order), if assuming `∀ t, φ t ∧ μ t < μ s → (φ ⇒ ψ) at t` lets you prove `φ ⇒⁺ ψ` at `s`, where `⇒⁺` means at least one step, then `φ ⇒ ψ`. It is proved by well-founded induction on `μ` plus R-Act.
- **Adequacy bridges:**
  - `φ ⇒ (halted with r)` implies `r ∈ beh σ s` (candidate 1).
  - For the machine side, `φ ⇒ ψ` implies the Iris WP for the generic-machine layer by that layer's adequacy, so C4 claims can later be *lifted* into the representation argument without re-proof.

**What it makes free, and what it costs.**
- *Free:* loop and recursion specs (circularities replace hand-built counting inductions), function specs reusable at call sites, and step-count-free statements. Uniformity in σ means the same logic serves the machine, the VM, and the OS spec.
- *Cost:* soundness, about 200 lines once. Every loop needs an invariant pattern and a rank, which is inherent.
- *Cost:* a symbolic-execution tactic that repeatedly applies Step with R-Local and simplifies the view.
- *Cost:* partial-correctness variants would need a separate coinductive soundness proof. I propose total claims only, since H9 is total.

**Theories drawn on (recalled, check them):**
- One-path and all-path reachability logic and matching logic (Roşu, Ştefănescu, Ciobâcă, Moore, LICS 2013; Ştefănescu et al., RTA 2014 for all-path).
- Cyclic proof systems (Brotherston, TABLEAUX 2005; Brotherston–Simpson, LICS 2007).
- Floyd's inductive assertions with ranking functions (Floyd 1967).
- Lyapunov functions from control theory: a strictly decreasing "energy" certifies convergence. The rank in Circ-rank is a discrete Lyapunov function.

**Targets:** C4 (primary), and C1 as a consumer of candidate 1.

**Pilot:**
- **H1–H4:** consumes candidate 1 and proves nothing new.
- **H5–H7:** not targeted.
- **H8:** `(pc=0 ∧ code=P) ⇒ (pc=4 ∧ accu=42 ∧ stack=stack₀)`, from four Step applications with Trans, each premise closed on the view.
- **H9 (the concrete counting loop; exact opcodes to be matched to the real program):** the invariant is `Inv(i) := pc = L ∧ code = P ∧ stack = int i :: rest ∧ i ≤ 10`, with rank `μ = 10 − i`.
  - *Body claim:* `Inv(i) ∧ i < 10 ⇒⁺ Inv(i+1)`. This is a straight-line segment (compare, branch-not-taken, increment, store to slot 0, branch back), handled by Step×k on the view.
  - *Exit claim:* `Inv(10) ⇒ pc = STOP ∧ accu = 10`, by Step×j.
  - *Main claim:* `Inv(i) ⇒ (at STOP ∧ accu=10)`, by Circ-rank using Case on `i < 10`. The body claim decreases μ, and the exit claim closes.
  - An arbitrary start `i ≤ 10` enters through a Step prefix into `Inv(i)`. About 20 lines, with no induction written by hand.
- **Refactor, generic-model reachability ↔ VM n-step:** the semantic clause of `⇒` is stated in terms of `∃ n, it n`, so the conversion is the definitional unfolding plus candidate 1's R-Clos.
- **The other two refactors:** delegated to candidate 1.

## 5. Rendering naturality: representation as `m ⊇ render π s`, with relocation as a commuting square

**Seed driver:** the recurring fragments `E2 … E2`, `Ej … Ej` and `Wj ×3`: the same object at several positions, identical up to where it sits. That is transport, or equivariance of rendering. `Snc` (sync) reads as keeping two views in step.

**The idea.** A semantic companion to candidate 2, with no DSL. Define one **executable** function, `render : Placement → St → PMem`, from VM states to *partial* memory images (address → word, finite). Define the representation as `∃ π, WF π s ∧ render π s ⊆ m ∧ regs m = regsOf π s`. Every one of the ~40 C3 components is then a **projection** of `render` (a restriction to an address set), not an independent predicate.

Model a relocation as an affine-like pair `ρ = (move : Addr ⇀ Addr, fix : Word → Word)`, where `fix` rewrites pointer-sorted words by `move`. L3 becomes **one naturality square** about `render`, proved by unfolding a fold over the heap. Invariance of every projection then follows by pure order reasoning.

**Core rules:**
- **R-Nat (L3):** `Disj ρ π s → render (move ∘ π) s = ρ♯ (render π s)`. Here `ρ♯` is the pushforward of a partial map: move the addresses, fix the words. It is well-defined only when `move` is injective on `dom(render π s)`, which is exactly the disjointness hypothesis. Overlapping targets make `ρ♯` a non-function, which is the 12,358 counterexamples.
- **R-Mono:** `P ⊆ m → ρ♯ P ⊆ ρ♯ m`, and `ρ♯` commutes with restriction: `(ρ♯ P)|_{move A} = ρ♯ (P|_A)`.
- **R-GC-spec:** the machine GC's effect on memory is `ρ♯` on the young region and the identity elsewhere, for some `ρ` with `Disj`. This is the *only* fact the GC implementation proof has to deliver. It separates C3 cleanly into "GC computes a pushforward" (machine-level, once) and "representation survives pushforwards" (R-Nat, once).
- **R-Proj:** each component `C_k π s m :≡ (render π s)|_{A_k π s} ⊆ m`. This is a definitional redefinition of the existing components, or an `Iff` proved once each.
- **Bonus for C2:** `render` is executable, so the checker "memory `m` represents `s` under the witness `π`" is `decide (render π s ⊆ m)`. Its soundness is `decide_eq_true_iff` and costs nothing.

**What it makes free, and what it costs.**
- *Free:* all C3 components at once, with future components free as long as they are stated as projections.
- *Free:* the placement existential is discharged by the explicit witness `move ∘ π`.
- *Free:* a runnable representation checker (C2), usable to *test* the relocation law on real GC traces before any proof.
- *Cost:* writing `render` (about 150 lines: a fold over heap objects by kind, the stack region, statics).
- *Cost:* proving that the existing components are projections.
- *Cost:* R-Nat needs the same within-block translation property as candidate 2. The same `raw`-word aliasing risk applies (see candidate 2) and should be settled at the laws stage.
- *Contrast with candidate 2:* this one is cheaper to adopt, since there is no DSL. It is weaker at *preventing* new non-equivariant predicates, because a component that is not a projection of `render` silently loses the guarantee.

**Theories drawn on (recalled, check them):**
- Category theory: `render` as a natural transformation between two actions of the relocation groupoid, on placements and on memory images. L3 is its naturality square.
- Computer graphics: rendering commutes with rigid transforms of the scene graph (`render(T·scene) = T·render(scene)`), the reason retained-mode renderers move objects without re-rasterising.
- Klein's Erlangen programme (1872): the representation components are invariants of a transformation group, here the groupoid of disjoint relocations.
- Abstract interpretation (Cousot–Cousot 1977): `render` as a concretisation map, with representation as ⊑ against it.

**Targets:** C3 (primary) and C2 (the representation checker).

**Pilot:**
- **H1–H4:** not targeted.
- **H5:** `render` restricted to one value slot at address `a` gives `{a ↦ word π v}`. Then `ρ♯{a ↦ word π v} = {move a ↦ fix (word π v)}`, and `fix (word π (ptr ℓ k)) = move(π ℓ) + 8k = word (move∘π) (ptr ℓ k)` by within-block translation. For ints, codes and atoms, `fix` is the identity. About 6 lines.
- **H6:** the object at ℓ is `render|_{[π ℓ, π ℓ + 8(size+1))}`. Apply R-Nat, then R-Mono with restriction commuting, and the target range is `[move(π ℓ), …]`. About 4 lines.
- **H7:** the stack region `A = [sp, top)` is fixed, with `move = id` on `A`. R-Nat plus restriction gives each stack word replaced by `fix(word)`, which is `render (move∘π)` of the same VM stack. About 4 lines.
- **H8–H9:** not targeted.
- **Refactors:** none is in C3. Stated honestly: this candidate does not help them.

### How the five fit together
- Candidate 1 is the substrate for candidates 3 and 4: Trans and Circ-rank rest on R-Act and R-Beh.
- Candidate 3 discharges candidate 4's Step premise without per-site lemmas.
- Candidates 2 and 5 are the syntactic and semantic answers to C3. A bake-off between them on H5–H7 is informative. Both must first settle the `raw`-word aliasing question, which I flag as a possible gap in L3 as stated: L3 rewrites words by VM sort, while a real copying GC rewrites them by bit pattern.
