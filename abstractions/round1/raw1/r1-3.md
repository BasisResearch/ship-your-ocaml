## 1. Absorbing ℕ-orbits: every step relation is the graph of an orbit

**Seed driver:** `Nf77` (the same step taken twice, i.e. the action law `iterate (m+n) = iterate m ∘ iterate n`). `LbL`/`ojo` (a run reads the same from either end, which is how uniqueness works). `LCS` (two runs from one state share their longest common prefix, which is the whole shorter run: determinism).

**Idea.** Stop treating "n steps" as an inductive relation. Present every deterministic system (machine, `BcSem`, the generic machine model, the deterministic part of the OS spec) as a one-field typeclass. `DetSys α ω` has `step : α → Next α ω` with outcomes `next a | stop ω`, where `stop` covers Halt, Error, Wrong and Unsupported as data in `ω`. The single object of study is the *orbit*, `orbit : ℕ → α → Outcome α ω`: fuel-bounded iteration in which a stop value, once reached, is absorbing. Every C1 fact is an equation about orbits, proved once for the class. A new step relation pays exactly one bridge lemma, `rel_n a n b ↔ orbit n a = next b`. It pays nothing if its n-step relation is *defined* as that equation.

**Core rules (all proved once in the class)**
- **O1 (action):** `orbit (m+n) a = (orbit m a).bind (orbit n)`, with `bind` absorbing on `stop`.
- **O2 (absorption):** `orbit m a = stop r → m ≤ n → orbit n a = stop r`.
- **O3 (graph law, L1 as a rule):** the n-step relation of `step` equals `fun a b => orbit n a = next b`. The reflexive-transitive closure is `∃ n, orbit n a = next b`.
- **O4 (first hitting time):** if some `n` stops, `τ a := Nat.find` is the least such `n`, and the stop value is `orbit (τ a) a`. Unique halting is O2 applied at `max m n`.
- **O5 (trichotomy):** for every `a`, exactly one of three holds: stops at τ with a value; runs forever (`∀ n, ∃ b, orbit n a = next b`); or neither. "Neither" is impossible, so there are only two cases, and "sticks" is simply a stop value in a designated subset of `ω`.
- **O6 (closure calculus):** every closure conversion (refl-trans, trans, n-indexed, the snoc and prepend inductive forms) is a corollary of O1 and O3. There is one lemma per closure shape, not one per relation.

**Makes free:** all 31 C1 members and every future step relation. Determinism of runs becomes definitional, because `orbit` is a function.

**Costs:**
- One bridge lemma per existing inductive n-step relation (induction on n, about 10 lines each), or re-definition.
- Error channels must be folded into `ω`.
- A genuinely nondeterministic OS spec does not fit and needs a separate treatment (see #5 or a powerset lifting).

**Theories:**
- Monoid actions / discrete dynamical systems (orbits of an ℕ-action).
- Kleisli composition for the `Except`/`Option` monad.
- Domain theory: the orbit is a Kleene chain, and halting is its stabilization.
- Stopping times in probability (τ is a hitting time; strong-Markov-style restart is O1 at τ).

**Cluster:** C1, and C2 via #4.

**Pilot:**
- **H1:** `orbit m a = stop r`, `orbit n a = stop r'`; by O2 both hold at `max m n`, so `r = r'`. About 3 lines, generic.
- **H2:** O3 plus O6 (`ReflTransGen (graph step) ↔ ∃ n, …`). One generic lemma, proved by induction once.
- **H3/H4:** "diverges" := `∀ n, ∃ b, orbit n a = next b`; "halts" := `∃ n r, orbit n a = stop (halt r)`. The hypotheses "never Wrong" and "never stuck" say every stop value is a halt. O5 then gives diverges ↔ ¬halts. H3 and H4 are the same generic theorem instantiated twice. Caveat to check: H3 must also exclude `Unsupported`, or "never-wrong" must mean "every stop is Halt".
- **Refactors:**
  - The VM run-determinism block becomes `DetSys.orbit_det` instantiated.
  - The machine's run-composition lemmas become O1 (plus snoc as O1 with `n = 1`).
  - The reach ↔ n-step conversion becomes O3 on both sides, and the two orbits coincide because the generic model *is* the VM's `step` behind a wrapper (one `rfl`-level bridge).

## 2. Equivariant representation predicates: a fundamental lemma for relocation

**Seed driver:** the palindromes `jTj`, `vnv`, `SMS` and the conjugation-like `DcdM`. All are invariance under a symmetry: predicates stay fixed while addresses are acted on.

**Idea.** Machine-side representation predicates are built from a small set of combinators, and each combinator is proved *equivariant* under a relocation ρ. The key observation is that the abstract heap uses `loc`, which never changes, so a relocation acts only on the placement and on machine memory. A relocation is ρ : Addr ⇀ Addr, affine on each live block's range, with pairwise-disjoint targets. It acts:
- on placements, by post-composition;
- on words, by `ρ̂ w` (pointer-into-live-range ↦ shifted, otherwise unchanged);
- on memories, by block copy.

The encoding of a VM value is *typed* (driven by `Val`, not by inspecting the word), so no raw word is ever mis-rewritten. The 40 upcoming C3 cases become instance resolution of a typeclass `Equivariant P` whose statement is `P plc m → P (ρ ∘ plc) (ρ · m)`, followed by the fundamental lemma.

**Core rules**
- **E1 (value primitive):** `enc (ρ ∘ plc) v = ρ̂ (enc plc v)`. Ints are fixed (ρ̂ fixes odd words); `ptr loc k` maps to `ρ(plc loc) + 8k`. This is the only arithmetic lemma.
- **E2 (points-to):** for `a` in a live range, `(a ↦ w) m → (ρ a ↦ ρ̂ w) (ρ · m)`; outside live ranges it is the identity.
- **E3 (connectives):** equivariance is closed under ∧, ∨, ∃, ∀ (over non-address sorts), ∗, and iterated ∗ over lists.
- **E4 (disjointness):** pairwise-disjoint targets imply ρ is injective on live addresses, which implies ∗ is preserved. This is the only place the 12,358 overlapping-target counterexamples bite, and it is proved once.
- **E5 (absorption, L3 as a rule):** if `R := ∃ plc, P plc m` and P is equivariant, then `R m → R (ρ · m)`, because `ρ ∘ plc` is again a placement. So the loop-head relation is *literally* preserved, with the VM state untouched.

**Makes free:** all of C3 (8 object kinds, stack region, channels, the 15 fields). Each needs only "written in the combinators", discharged by instance search.

**Costs:**
- Predicates must be restated in the combinator vocabulary (a shallow embedding plus the typeclass).
- Fields that store raw machine words (doubles, byte strings) need `ρ̂ = id` side conditions: typed as non-pointer.
- The GC's action on *non-live* memory must be specified as "don't care", or the frame must be excluded from the predicate.

**Theories:**
- Nominal sets (Gabbay–Pitts; equivariance and support). Check: Gabbay & Pitts, LICS 1999 / FAC 2002.
- Reynolds relational parametricity ("free theorems"; the fundamental lemma of logical relations). Check: Reynolds 1983.
- Tarski's "What are logical notions?": invariance under permutations of the domain. Check: 1966 lecture, published 1986.
- Klein's Erlangen program: properties are invariants of a transformation group.

**Cluster:** C3.

**Pilot:**
- **H5:** E1, by cases on `Val`, about 6 lines.
- **H6:** an object's layout is `hdr ↦ w₀ ∗ ⊛ᵢ (base+8i ↦ enc fᵢ)`; equivariant by E2, E3 and E4 via instance search, about 1 line.
- **H7:** the stack region is `⊛ᵢ (sp+8i ↦ enc sᵢ)` with `sp` outside the young heap, so ρ fixes it; E2 and E3.
- **Refactors:** none of the three C1 blocks is touched. The machine run-composition lemmas combine with E5 to give "GC run segment preserves the relation" in one line.

## 3. Step patches: a lens algebra for instruction footprints

**Seed driver:** the diff fragments `dx`, `dff`, `Ddoee` (a step as a *patch* or delta). The run of sevens: footprints are small, fixed-width windows (at most about 7 lenses per instruction).

**Idea.** Not triples. Write C4 specifications as *equations between state transformers*. Each instruction denotes a guarded patch `δ = (R, g, W)`:
- a finite set of read lenses R (pc, accu, `stack[i]` for small i, field lenses `heap[loc].f[j]`);
- a guard `g` on the values read (otherwise `Wrong`/`Unsupported`);
- a write map W, from written lenses to expressions over the read values, plus a stack-depth delta and an optional append-allocation.

A segment's specification is its *composed* patch, normalized by substitution. L4 becomes a structural theorem, `step p s = apply (δ_{p,pc} (read R s)) s`, proved once by case analysis on the opcode. The lens laws then give framing.

**Core rules**
- **P1 (lens laws):** GetPut, PutGet, PutPut for every state lens. Disjoint lenses commute: `put ℓ₁ ∘ put ℓ₂ = put ℓ₂ ∘ put ℓ₁`, and `get ℓ₁ ∘ put ℓ₂ = get ℓ₁`.
- **P2 (locality, L4 as a rule):** the equation above. Reads outside R and writes outside W are the identity. Stack lenses are indexed *relative to the top*, so push and pop are lens re-indexings (a shift) rather than writes to the whole stack.
- **P3 (composition):** `apply δ₂ ∘ apply δ₁ = apply (δ₂ ⊙ δ₁)`, where ⊙ is substitution of δ₁'s writes into δ₂'s reads with the guards conjoined. The operation is computable, and `decide`/`simp` normalizes it.
- **P4 (monotone heap):** append-allocation commutes with every field lens on an existing `loc` (`loc < heap.length`).
- **P5 (loop summary):** for a back-edge patch δ with measure μ over R, `δ^k` has a closed form by induction on k. The loop summary is the patch `δ^{μ(s)} ⊙ exit`.

**Makes free:**
- Straight-line specifications of any length by normalization.
- The frame property for everything untouched.
- The "stack unchanged" and "rest of state unchanged" conclusions, which are the P1 identity.

**Costs:**
- One large opcode-by-opcode proof of P2. This is exactly L4 made into a proof, done once.
- A normalizer (C2-style soundness of ⊙, proved once).
- Data-dependent stack depth breaks fixed lens indices; the guard must pin the depth.

**Theories:**
- Bidirectional transformations / lenses. Check: Foster, Greenwald, Moore, Pierce, Schmitt, POPL 2005 / TOPLAS 2007.
- Plotkin–Power algebraic theory of global state (lookup/update equations). Check: FoSSaCS 2002.
- Hoare et al., "Laws of Programming" (CACM 1987): equational, not assertional, reasoning.
- Version-control patch theory (Darcs: commuting disjoint patches). Check the Darcs patch-theory attribution.

**Cluster:** C4, plus C2 for the normalizer.

**Pilot:**
- **H8:** compose the four patches. The result is `{accu := 42, pc := 4}` with the stack-depth delta 0. It still has to be checked whether `ADDINT` pops the pushed 40, which would restore the stack. Normalization gives `run 4 s = s.{accu := 42, pc := 4}` for *all* s (guard `True`), so the stack is unchanged by P1.
- **H9:** body patch on (`stack[0]`, accu) with measure `10 − i`. P5 gives a closed form and exit at STOP with `accu = 10`, for all `i ≤ 10`.
- **Refactor:** not aimed at the three C1 blocks. The runs of H8/H9 connect to #1 because `orbit n` is P3 iterated.

## 4. Fuel-indexed reflection: checkers as monotone approximant chains

**Seed driver:** the literal `fue` in `Q5fueFOAQ` (fuel). `0Q5`/`U0`/`v0` (a zero-based index into an approximant chain). The doubled `77`: an approximant n+1 refines approximant n.

**Idea.** Every executable runner or checker in C2 is a family `chk : ℕ → α → Option Bool` that is *monotone in fuel*. It relates to its relation through a single `Reflect` judgment, stated over the orbit of #1. Soundness and completeness become two instances of one Galois-connection shape.

The pilots also use a second move: **decide on the footprint, lift by locality.** Evaluate the checker on the *projection* of a state to its footprint (finite for H9's `i ≤ 10`), and transport the result to arbitrary states via #3's P2. "For all states" becomes a finite `decide` plus one lift lemma.

**Core rules**
- **F1 (reflect):** `chk n a = some b ↔ (b = true ↔ Rₙ a)`, where `Rₙ` is the n-bounded relation from orbit O3.
- **F2 (fuel monotonicity):** `chk n a = some b → chk (n+k) a = some b`. It is derived from absorption O2 when `chk` is defined as `observe ∘ orbit n`.
- **F3 (sup):** `R a ↔ ∃ n, chk n a = some true` (H2 generalized). Completeness is F3 from right to left.
- **F4 (projection lift):** if `chk` reads only the footprint R (P2), then `chk n s = chk n (π_R s ⊕ junk)`. So `decide` over `π_R`'s finite image proves `∀ s`.
- **F5 (composition):** sequential and conjoined checkers reflect composed relations. There is one lemma per combinator, not one per checker.

**Makes free:** the soundness and completeness of every runner defined as an observation of an orbit (all 7 C2 members, most likely), plus finite-footprint C4 lemmas.

**Costs:**
- Checkers not defined through `orbit` need a one-time bridge.
- `decide` cost grows with the footprint image. H9 has 11 cases, which is fine; this does not scale to data-dependent loops.
- Kernel reduction of `BcSem.step` must actually be efficient (a well-founded recursion or `Nat` binary-representation trap is possible).

**Theories:**
- Abstract interpretation (Galois connections; Cousot & Cousot, POPL 1977).
- Kleene's fixpoint theorem (the sup of an ω-chain).
- SSReflect `reflect` views (Gonthier et al.): small-scale reflection.
- Model theory: finite-support / locality theorems (Gaifman locality: a formula's truth depends on a bounded neighbourhood). Check the aptness of this analogy.

**Cluster:** C2, with C4 small programs and C1 H2.

**Pilot:**
- **H2:** F3 instantiated.
- **H9:** the footprint is (pc, `stack[0]`, accu, the code). Project, `decide` for `i ∈ {0..10}` with a fuel bound, and lift by F4.
- **H8:** the footprint is (pc, accu, code, stack depth at most 1). `decide` is impossible on an unbounded accu, but the accu is *written before it is read*, so the projected footprint is a singleton. `decide` works, then lift.
- **H1/H3/H4:** unaffected (#1 covers them).
- **Refactor:** the "generic model reach ↔ VM n-step" conversion becomes F1 on both sides with a shared `observe`.

## 5. Gauge-fixed simulation: GC as a gauge transformation, runs modulo relocation

**Seed driver:** `Bst`/`BT` repeated three times (block shift transform, the same shift at different offsets). `DcdM` (conjugation: ρ ∘ plc ∘ ρ⁻¹). `LbL` (a GC run, looked at through the quotient, reads as a stutter).

**Idea.** Complement to #2, which says *how* to prove invariance. This one says *how to use it* so that C3 never leaks into C1 or C4.
- **Setup:** placement is a *gauge* (a choice of coordinates for the abstract heap), and relocations with disjoint targets form a groupoid 𝒢. The representation relation is a functor `𝒢 → Prop`, via transport by #2's E5.
- **The quotient system:** define it by `Config/≈`, where `c ≈ c'` iff they differ by some ρ ∈ 𝒢 on the live heap and agree elsewhere. On the quotient, the machine's GC is the identity, a *stutter step*.
- **What proofs quantify over:** only *gauge-invariant observables* (output, halt code, int-valued accumulator, VM state). Simulation diagrams are stated to commute up to ≈.
- **Payoff:** C4 specifications never mention placement or GC, and C1 lemmas lift through the quotient.

**Core rules**
- **G1 (groupoid):**
  - `id ∈ 𝒢`;
  - composition preserves disjointness of targets;
  - a disjoint-target ρ is injective on the live set, hence invertible on its image.
- **G2 (transport = L3):** `Repr plc m s → Repr (ρ ∘ plc) (ρ·m) s`. This is #2's E5, imported.
- **G3 (stutter):** a machine GC segment from c ends in some c' with `c ≈ c'`. This is a spec obligation on the collector, proved once.
- **G4 (orbit lifting):** if `step` respects ≈ (≈-related configs step to ≈-related configs, and stop with the *same* observable), then #1's orbit descends to the quotient, and determinism, unique halting and trichotomy hold there *up to ≈*.
- **G5 (observable invariance):** halt code, output and the interpretation of ints are constant on ≈-classes.

**Makes free:**
- No proof about a bytecode segment or run-composition ever re-proves "survives GC".
- End-to-end correctness is stated on observables.
- Runs that include GC compose as if the GC were not there.

**Costs:**
- G4's "step respects ≈" is a real obligation on the *machine* step. It fails for code that reads raw addresses (pointer comparison, hashing on addresses), so those instructions need an explicit exception list.
- Quotients in Lean (`Quot`) complicate computation, so prefer a setoid with lifted lemmas.
- Stuttering breaks naive step-count equalities (use #1's ∃n forms).

**Theories:**
- Gauge theory: physics is gauge-invariant, and fixing a gauge is a proof convenience. Weyl.
- α-equivalence / nominal abstraction: addresses as bound names, and GC as α-renaming.
- Stuttering bisimulation (Browne, Clarke, Grumberg 1988; check) and Lamport's stuttering invariance in TLA.
- Groupoids / setoids in homotopy type theory (transport along an equivalence).

**Cluster:** C3 (use side), C1 (lifting), C4 (keeps specifications placement-free).

**Pilot:**
- **H5–H7:** instances of G2 (via #2).
- **H1/H4 for the machine with GC:** G4 plus #1 give unique halting up to ≈, and G5 collapses it to plain equality of halt code and output.
- **H8/H9:** stated only on VM state, so the GC is invisible by construction.
- **Refactor:** the conversion "generic machine model reach ↔ VM n-step" is restated as a commuting square of quotiented orbits. The machine's run-composition lemmas are #1's O1 applied through G4.
