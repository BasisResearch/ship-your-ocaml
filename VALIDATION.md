# Validation (Phase 1)

Everything below was measured on aws-dev on 2026-09-29 with the committed
sources. Sail runs use the Lean emulator of ship-your-interpreter's
`riscv-lean/lean_emulator` (the binary `~/vsa-b3-work/bin/lean_riscv_emulator`,
sha256-identical to a rebuild from this tree's `riscv-lean/` per
ship-your-interpreter's REVIEW2.md §4), driven by `c/tests/sail_run.py`,
which traces the entry PCs of a few runtime functions (`--trace-pcs`) and
the HTIF exit store. A "step" is one retired instruction of the Sail model.
The emulator runs at about 49,000 steps/s.

## 1. Release and toolchain

* **OCaml 4.14.2** (PLAN.md §1 for why not 5.x: domains need pthreads and
  atomics, the proof ELF is rv64i). Vendored in `vendor/ocaml-4.14.2`
  (tarball sha256 in ATTRIBUTION.md). A host 4.14.2 built from the same
  tarball (`~/toolchains/ocaml-4.14.2`) compiles the test programs, so the
  bytecode matches the runtime version.
* **Cross toolchain**: the xPack `riscv-none-elf-gcc` 15.2.0-1 (GCC 15.2.0,
  newlib 4.5.0.20241231) in `~/toolchains/`, the same release, flags and
  newlib/dlmalloc as ship-your-interpreter's proof ELF and ship-your-lua's
  ELF: `-march=rv64i -mabi=lp64 -mcmodel=medany -O2` (the Sail Lean model
  has no M/A/F/D: multiplication, division and doubles are libgcc soft
  routines), plus the runtime's own `-fno-strict-aliasing -fwrapv
  -fno-common -fno-tree-vrp`.
* **Build** (`c/Makefile`, `make`): the 50 bytecode-runtime C files of
  `runtime/Makefile`'s `BYTECODE_C_SOURCES` other than `main.c`, compiled
  unmodified with a hand-written `m.h`/`s.h` (`c/src/config/`: 64-bit,
  little-endian, `OCAML_OS_TYPE "Unix"`, no signals, sockets, dynlink,
  clocks), threaded code OFF (`-DSHRINKED_GNUC`: one switch dispatch, code
  words stay opcodes), `prims.c` generated by the runtime's own recipe.
  Four link-time holes needed stubs (`geteuid`/`getuid`/`getegid`/`getgid`,
  `getppid`, `chdir`/`mkdir`/`rmdir`, and `caml_debugger_saved_instruction`,
  which `interp.c` references even when `debugger.c` compiles to nothing
  without sockets) plus empty `sys/ioctl.h` and a `sys/dir.h`.
* **OS layer** (`c/src/htif.c`): HTIF console and exit as in
  ship-your-interpreter, plus an in-memory file system: files linked into
  the image by `c/src/gen_embed.sh` (read-only, copy-on-write), files the
  program creates (heap-backed), directories as path prefixes (needed:
  4.14's `Load_path` indexes include directories with `Sys.readdir`).
  `caml_main` then opens the embedded executable `/prog` through its
  ordinary `ocamlrun prog args` path; the runtime is not patched.
  `c/src/main.c` bakes in `argv = { "ocamlrun", "/prog", ARGS… }` and
  `OCAMLRUNPARAM`.
* **The proof ELF**: `c/ocamlrun-riscv-htif.elf` (521,128 bytes, sha256
  `c8afd9dc1c4e7b886577a0ecd5bdebdb9991d52affc4183e58832cd0cca5e8c5`,
  `c/ELF.sha256`) with `c/tests/while.ml` embedded: `c/while.byte`, the
  21,993-byte bytecode executable from the host `ocamlc` (sha256 in
  `c/ELF.sha256`).

## 2. On Sail

### 2.1 Programs

| program | output | exit | steps | cut point (2nd `caml_interprete` call) | after the cut |
|---|---|---|---|---|---|
| `while.ml` (proof ELF) | `55\n2500\n36\n` | 0 | 4,568,481 | 4,496,260 | 72,221 |
| `while_min.ml` (no Stdlib) | `55\n2500\n36\n` | 0 | 4,310,573 | 4,266,883 | 43,690 |
| `boot/ocamlc -version` | `4.14.2\n` | 0 | 53,831,034 | 48,242,926 | 5,588,108 |
| `boot/ocamlc -nostdlib -I /lib/ocaml -dinstr -c /src/hello.ml` | PENDING_HELLO_OUT | PENDING | PENDING | PENDING | PENDING |

`while.ml` is the OCaml port of ship-your-interpreter's `c/tests/while.wl`
(while loops, `break` as an exception, nesting). `hello.ml` is
`let () = print_int (6 * 7)`; the compile run embeds `stdlib.cmi` from the
host 4.14.2 at `/lib/ocaml/stdlib.cmi`, and `-dinstr` makes the compiler
print the bytecode it generates on the HTIF console.

**Where the steps go before the cut point** (`while.ml`; `ocamlc`):

| phase | `while.ml` | `boot/ocamlc -version` |
|---|---|---|
| crt0 (`.bss` clear), `caml_init_gc` | 0 → 123k | 0 → 122k |
| `caml_load_code`: read CODE through the in-memory file system, MD5 of the code | 123k → 388k | 122k → 37.03M |
| `caml_build_primitive_table`: linear `strcmp` over the 403 builtin names per required primitive | 388k → 4.46M | 37.03M → 41.10M |
| `caml_input_val` (unmarshal DATA), promotion (one minor collection), `caml_sys_init` | 4.46M → 4.50M | 41.10M → 48.24M |

All of it is before the cut point: it costs emulator time and boot-witness
length, not proof (PLAN.md §6).

### 2.3 GC

* Every program has exactly one minor collection before the cut point:
  `caml_main` promotes the unmarshalled global data (`caml_oldify_one` +
  `caml_oldify_mopup`, `startup_byt.c`) at step 4,482,776 for `while.ml`,
  13,484 steps before the cut.
* **After the cut point, with the default 256k-word minor heap, eight of
  the nine difftests run no minor collection and no major slice** (table
  above): they stay in PLAN.md's G1 regime. `f6_alloc` (allocation
  pressure by design) runs its first minor collection at step 33,328,567,
  26.9M steps after the cut, and 3 minor collections and 2 major slices in
  all. `boot/ocamlc -version`: none after the cut.
* PENDING_GC

## 3. `BcSem` against the binary

* **Executable `BcSem`** (`runbc FILE`, `RunBc.lean`: the step function of
  `OCaml/Bytecode/Semantics.lean` on the `Prog` built by
  `OCaml/Bytecode/Load.lean`'s transcription of `caml_main`'s loading,
  including the DATA unmarshaller):

  | program | `BcSem` | ZINC steps |
  |---|---|---|
  | `f1_while` | `55\n2500\n36\n`, exit 0 — identical to host and Sail | 2,602 |
  | `f2_closures` | identical to host and Sail (5 lines) | 118,119 |
  | `while_min` | identical | 2,161 |
  | f1_arith / f3 / f4–f7 / f8 | stops `.unsupported` at the first primitive outside F1 (`caml_greaterequal`, `caml_make_vect`, `caml_create_bytes`, `caml_obj_block`) | 1,105–2,139 |

  No test ever reaches `.wrong`. Two transcription bugs were found by these
  runs and fixed, both in offsets: `SWITCH` and `CLOSUREREC` offsets are
  relative to the table start, not to each slot; `GRAB`'s partial
  application points at the `RESTART` one word before it (C's `pc - 3` is
  taken after the operand read).
* **Kernel-checked**: `whileMin_bcSem : BcHalts whileMin "55\n2500\n36\n" 0`
  (`OCaml/Programs/Validation.lean`) by `decide +kernel` on `runTo`
  (2,161 steps, 26 s, 6.5 GB); axioms `propext`, `Classical.choice`,
  `Quot.sound`. The Stdlib-linked `while.ml` exhausts 30 GB in the kernel
  within ~100 steps (no sharing between steps over a Stdlib-sized heap);
  chunking is PHASES.md A1.
* **Machine steps per ZINC step** after the cut: 27.8 (`while.ml`), 20.2
  (`while_min`), 14.7 (`f2_closures`), C primitives included.

## 4. Census

### 4.1 The ELF (`scripts/census.py`, `results/census.json`)

| | functions | instructions |
|---|---|---|
| image | 1,321 | 83,826 |
| reachable from `_start` (direct edges ∪ address-taken) | 1,123 | 77,206 |
| reachable from `caml_interprete` + the 403 C primitives | 1,003 | 68,880 |

* 484 address-taken functions (the primitive table, custom-operation
  tables, hooks); 234 indirect jump sites.
* **`caml_interprete`**: 1,966 instructions; the dispatch is one
  `lw; add; jr` through a 149-entry table (`OCaml/Vm/Layout.lean`:
  `jumpTable`), 147 distinct arm entries. Arm sizes (control-flow walk from
  the arm to the loop head): median 7 instructions; largest `CLOSUREREC`
  152, `CLOSURE` 94, `MAKEBLOCK` 86, `MAKEFLOATBLOCK` 74, `RAISE`/`RERAISE`
  74, `GRAB` 72, `RAISE_NOTRACE` 63, `APPTERM` 58, `APPLY3` 51; 1,899
  instructions reachable from some arm, 111 shared by several (GC entry,
  raise, signal and callback paths). Loop-head registers: pc `s0`, sp
  `s1`, accu `s5`, env `s9`, extra_args `s2`.
* **Site classes** (ship-your-interpreter's `disasm_to_sites.py`
  classifier): 64,205 of 77,206 reachable instructions (83.2%) fall in a
  class its generators handle. The rest by mnemonic: `auipc` 3,285,
  `slli` 2,241, `andi` 1,053, `srli` 997, `addw` 846, `lui` 663, `slliw`
  635, `or` 580, `srai` 467, `and` 357 — the tagged-integer idiom
  (`slli`/`srai`/`ori 1`) is the main new family.
* **New C constructs** beyond the WHILE interpreter: the switch jump table;
  calls through the primitive table (`jalr`); `setjmp`/`longjmp` for
  exceptions raised in C; soft-float on the GC pacing path even for integer
  programs (`caml_adjust_gc_speed` from `caml_alloc_custom_mem`: 19
  soft-float functions, 3,253 instructions); the collector (140 functions,
  13,398 instructions: `caml_empty_minor_heap` 205, `caml_oldify_one` 145,
  `caml_oldify_mopup` 149, `caml_major_collection_slice` 509, best-fit
  allocator); `intern_rec` (730) before the cut.
* **Shared with the WHILE proof ELF**: 131 of the 213 same-named functions
  (9,869 instructions; 99 reachable, 8,644 instructions) are identical up
  to PC-relative immediates: `memcpy`, `memmove`, `memset`, `strlen`,
  `strcmp`, `strcpy`, `__muldi3`, `__divdi3`, `__moddi3`, `__umoddi3`,
  `__ssprint_r`, `__ssputs_r`, `_realloc_r`, `setjmp`, `longjmp`, 12
  soft-float routines, … `_malloc_r` and `_free_r` are the same newlib
  objects but differ: linker relaxation shortened different branch/call
  sequences in the larger image. Site proofs transfer by address retarget
  (A0); these two are regenerated.

## 5. Fixpoint

The host build (`make world` of the vendored tarball) compiles the
compiler's sources with `boot/ocamlc`. Section by section, the resulting
`ocamlc` against `boot/ocamlc`:

| section | `boot/ocamlc` | rebuilt `ocamlc` | equal |
|---|---|---|---|
| CODE | 2,622,940 | 2,622,940 | yes |
| PRIM | 7,858 | 7,858 | yes |
| SYMB | 3,338 | 3,338 | yes |
| CRCS | 5,827 | 5,827 | yes |
| DATA | 358,533 | 358,597 | no: only `Config`'s install paths (`/usr/local/bin`, `/usr/local/lib/ocaml` vs the build prefix) |
| DBUG | 0 | 17,631,284 | the host build uses `-g` |

So `boot/ocamlc` is the 4.14.2 compiler compiled by itself, up to
`configure`'s strings: the premise of the bootstrap-fixpoint step
(`boot_ocamlc_fixpoint_Statement`, PLAN.md §5) holds for this release.

## 6. Host mirror

`c/tests/hostmirror.sh` builds the same runtime sources, configuration,
`main.c` and in-memory file system natively (the file-system calls routed
to `htif.c` by macros, `c/tests/hostmirror.h`), so an embedded-program run
that takes Sail an hour can be reproduced in milliseconds when debugging
the OS layer. It reproduces `while.ml` and the `boot/ocamlc` compile run
(same `-dinstr` listing, exit 0). It is a debugging aid, not evidence:
every number above is from Sail.

## 7. What did not work, and limits

* No `native_decide` anywhere. The kernel cannot evaluate `BcSem` over a Stdlib-initialised heap for
  more than ~100 steps within 30 GB (§3).
* Startup is expensive on Sail (§2.1); boot witnesses beyond small
  programs are impractical (PLAN.md §6).
* The difftest ELFs are separate builds of the same sources with other
  embedded programs; the proof ELF is `c/ocamlrun-riscv-htif.elf` only.
